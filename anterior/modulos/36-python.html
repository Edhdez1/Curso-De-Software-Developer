Cómo se aprende un segundo lenguaje

Cuando alguien que ya programa en un lenguaje empieza con otro, suele cometer uno de dos errores. El primero es empezar desde cero, con un curso para principiantes que explica durante horas qué es una variable. El segundo es no estudiar nada y escribir el lenguaje nuevo «como si fuera» el viejo, hasta que algo falla de una forma que no entiende. El camino bueno está en medio: comparar. Tomas cada idea que ya dominas y buscas cómo se dice en el lenguaje nuevo, prestando atención especial a lo que se parece pero no es igual.

Para entenderlo

Si hablas español, aprender portugués o italiano es mucho más rápido que aprender japonés: la gramática se parece y muchas palabras son casi iguales. Pero cuidado con los falsos amigos, las palabras que se parecen y significan otra cosa: en italiano, burro es «mantequilla». Entre lenguajes de programación pasa lo mismo. En Python, for x in lista recorre los valores, mientras que el for...in de JavaScript recorre los índices o las claves. Donde la analogía falla: algunos lenguajes tienen ideas sin equivalente en el otro, como las comprensiones de Python o el bucle de eventos de JavaScript. Esas no se traducen; se aprenden.

El método: diez preguntas antes de escribir nada serio

Cuando empieces con cualquier lenguaje nuevo (Python hoy; quizá C#, Kotlin, Go o GDScript mañana), responde estas preguntas en orden. Es la misma lista que sigue esta estación:

  1. ¿Cómo lo instalo y cómo ejecuto un archivo? ¿Tiene un modo interactivo para probar líneas sueltas?

  2. ¿Cómo imprimo algo? Es tu herramienta de depuración número uno desde la Estación 12.

  3. Variables y tipos. ¿Cómo se declaran? ¿Qué tipos básicos hay? ¿Qué pasa si mezclo un texto con un número?

  4. Bloques y decisiones. ¿Los bloques se marcan con llaves, con sangría o con palabras como end?

  5. Bucles. ¿Cómo recorro una lista? ¿Cómo repito algo N veces?

  6. Funciones. ¿Cómo se definen, cómo devuelven valores, cómo reciben parámetros opcionales?

  7. Colecciones. ¿Cuál es su «array»? ¿Y su «objeto» o su Map?

  8. Errores. ¿Cómo se ve un mensaje de error? ¿Cómo se capturan y se lanzan?

  9. Módulos y paquetes. ¿Cómo importo código de otro archivo? ¿Cuál es su npm?

  10. Costumbres. ¿Hay una guía de estilo oficial? ¿Qué formateador y qué herramienta de pruebas usa la comunidad?

Con esas diez respuestas, escribe en el lenguaje nuevo un programa que ya sepas hacer en el viejo: la ficha de personaje de la Estación 7, un juego de adivinar un número, un contador de palabras. Como ya conoces la solución, toda tu atención va a la forma. Es la manera más rápida de aprender la columna del medio.

¿Por qué Python?

Python es un lenguaje de programación de propósito general creado por el neerlandés Guido van Rossum y publicado por primera vez en 1991. El nombre no viene de la serpiente, sino del programa de humor británico Monty Python's Flying Circus. Se diseñó para que el código se leyera casi como un texto en inglés, y esa decisión explica muchas de las diferencias que vas a ver.

Según el índice TIOBE, que mide la popularidad de los lenguajes a partir de búsquedas, cursos y ofertas, Python era el lenguaje número uno en septiembre de 2026. En GitHub, el informe Octoverse de 2025 lo situó segundo en número de personas que contribuyen, justo detrás de TypeScript, y como el lenguaje dominante en los proyectos de inteligencia artificial. Estos rankings cambian cada año y miden cosas distintas; lo que no cambia es que Python aparece en casi todos los campos:

El mismo programa en dos lenguajes

Este programa de JavaScript ya lo sabes leer:

const jugadores = ["Ana", "Leonor", "Mía"];
for (const nombre of jugadores) {
  if (nombre.length > 3) {
    console.log(`${nombre} tiene un nombre largo`);
  } else {
    console.log(`${nombre} tiene un nombre corto`);
  }
}
console.log(`Total: ${jugadores.length}`);

Aquí está en Python. Antes de ejecutarlo, predice qué imprime y busca al menos cinco diferencias con la versión de JavaScript:

La salida es idéntica. Las diferencias que deberías haber encontrado:

  • No hay const ni let: una variable se crea al asignarle un valor.
  • No hay llaves ni punto y coma. Las líneas que abren un bloque terminan en dos puntos (:) y lo que va dentro se marca con sangría, los espacios al principio de la línea.
  • La condición del if no lleva paréntesis.
  • for nombre in jugadores recorre los valores, como el for...of de JavaScript.
  • La longitud se pide con la función len(...), no con la propiedad .length.
  • Los textos con valores dentro se escriben con f"..." y llaves, no con comillas invertidas y ${}.
  • Se imprime con print, no con console.log.

Todo lo demás (el orden de ejecución, la decisión, el bucle) es exactamente lo que ya sabías. Esa es la promesa de esta estación.

Instalar Python y usar el intérprete

JavaScript viene dentro de cada navegador. Python no: hay que instalarlo, igual que instalaste Node.js en la Estación 5. El programa que instalas se llama CPython: es el intérprete oficial de Python, escrito en C, y es el que usa casi todo el mundo cuando dice «Python».

Qué versión usar

A finales de septiembre de 2026, la serie estable más reciente es Python 3.14 (la versión 3.14.7 salió en agosto de 2026), y la 3.15 está prevista para el 1 de octubre de 2026. Cada serie recibe correcciones durante unos cinco años. Instala la más reciente que ofrezca python.org y comprueba qué tienes con:

El intérprete interactivo

Si escribes python sin nada más, se abre el intérprete interactivo, también llamado REPL (de Read-Eval-Print Loop, «bucle de leer, evaluar e imprimir»): escribes una línea, Python la ejecuta y te muestra el resultado. Es como la consola del navegador de la Estación 6, pero para Python:

$ python
Python 3.14.7 (main, ...) [...] on linux
Type "help", "copyright", "credits" or "license" for more information.
>>> 2 + 3
5
>>> nombre = "Ana"
>>> nombre
'Ana'
>>> print(nombre)
Ana
>>> 10 / 4
2.5
>>> exit()

Los tres signos >>> son el indicador: Python espera tu línea. Si escribes una línea que abre un bloque (un if, un for), el indicador cambia a ... hasta que dejas una línea en blanco. La fecha y los detalles de la primera línea cambian según tu instalación. Para salir, escribe exit() (desde Python 3.13 basta con exit), o pulsa Ctrl + D en macOS y Linux, o Ctrl + Z y Enter en Windows.

Fíjate en la diferencia entre nombre y print(nombre). Cuando escribes solo una expresión, el intérprete te muestra su representación, pensada para programadores: por eso aparecen las comillas en 'Ana'. print muestra el texto tal cual, pensado para personas. Desde Python 3.14, el intérprete además colorea la sintaxis y completa nombres de módulos al pulsar Tab.

Consejo de oficio

El intérprete es tu calculadora y tu laboratorio. ¿No recuerdas qué hace un método? Escribe help(str.split). ¿Qué métodos tiene un texto? dir("hola"). ¿De qué tipo es algo? type(x). Mucha gente programa con el editor en una mitad de la pantalla y el intérprete en la otra, probando cada idea antes de escribirla en el archivo.

Sangría, variables y tipos

Lo primero que notas al abrir un archivo de Python es cómo se ve: casi no hay símbolos. Ni llaves, ni punto y coma, ni let. Esa limpieza tiene un precio: los espacios al principio de cada línea pasan a ser parte del lenguaje. Empecemos por ahí, porque es la fuente de los primeros errores de todo el mundo.

La sangría es la sintaxis

Sigue esta animación: el mismo if escrito en los dos lenguajes.

Las reglas prácticas son pocas:

  • Usa 4 espacios por nivel. En VS Code, al pulsar Tab en un archivo .py se insertan 4 espacios.
  • No mezcles tabuladores y espacios en un mismo archivo: Python lo rechaza con un TabError.
  • Un bloque no puede estar vacío. Si todavía no sabes qué poner, escribe pass, la instrucción que no hace nada.
  • Los comentarios empiezan con #. No existe /* ... */: para varias líneas, pon # en cada una.
  • No se usa punto y coma. Python lo acepta al final de una línea, pero nadie lo escribe.
  • Una instrucción larga puede partirse en varias líneas si está dentro de paréntesis, corchetes o llaves.

Error común

Olvidar la sangría después de los dos puntos es el error número uno de la primera semana. Python 3.14 te dice exactamente qué pasó: IndentationError: expected an indented block after 'if' statement on line 2, «se esperaba un bloque con sangría después del if de la línea 2». Y si copias código de una web o de un chat, revisa la sangría: a veces se pierde o se mezcla con tabuladores al pegar.

Variables sin let ni const

En Python no se declara nada: una variable nace la primera vez que le asignas un valor.

vidas = 3                  # nace vidas
vidas = vidas - 1          # cambia (no hay let ni const)
vidas -= 1                 # atajo; no existe vidas-- ni vidas++
nombre_de_usuario = "Kai"  # snake_case: palabras en minúscula unidas con _
GRAVEDAD = 9.8             # MAYÚSCULAS: «por favor, no cambies esto»
x, y = 0, 10               # dos variables en una línea
x, y = y, x                # intercambiar valores sin variable auxiliar

La comunidad de Python escribe los nombres en snake_case (palabras en minúscula separadas por guion bajo, precio_total), no en camelCase. Lo dice PEP 8, la guía de estilo oficial. Un PEP (Python Enhancement Proposal, «propuesta de mejora de Python») es un documento público que describe un cambio o una norma del lenguaje; la 8 es la de estilo, y la vas a ver citada en todas partes.

No hay constantes de verdad

Python no tiene const. Escribir un nombre en MAYÚSCULAS es un acuerdo entre personas («esto no debería cambiar»), pero nada impide escribir GRAVEDAD = 10 más abajo. En JavaScript el motor te frenaba; en Python te frena la disciplina del equipo y, si quieres, herramientas de revisión como las de la Estación 25.

Decisiones y bucles

La lógica de las decisiones y los bucles la dominas desde las Estaciones 8 y 9. Aquí cambian tres cosas: las palabras, la sangría y una idea que Python lleva muy lejos: recorrer colecciones directamente, sin contadores.

if, elif y else

temperatura = 31
lloviendo = False

if temperatura >= 30 and not lloviendo:
    print("Día de playa")
elif 15 <= temperatura < 30:          # comparación encadenada
    print("Clima agradable")
else:
    print("Mejor quedarse en casa")

estado = "calor" if temperatura > 25 else "fresco"   # el «ternario» de Python
  • else if se escribe elif.
  • Los operadores lógicos son palabras: and, or y not en lugar de &&, || y !.
  • Las comparaciones se pueden encadenar como en matemáticas: 15 <= temperatura < 30 significa «entre 15 (incluido) y 30 (sin incluir)».
  • El operador ternario condicion ? a : b se escribe a if condicion else b, en el orden en que lo dirías en voz alta.

Sin ámbito de bloque

En JavaScript, una variable creada con let dentro de un bloque desaparece al salir de él (Estación 10). En Python los bloques de if y for no crean ámbito: después del bucle, ronda y p siguen valiendo lo último que tomaron. Solo las funciones crean un ámbito nuevo.

Tuplas

Una tupla es como una lista que no se puede cambiar después de crearla: es inmutable. Parece una limitación, pero comunica una intención («estos datos van juntos y no cambian») y permite usarla como clave de un diccionario. Lo más útil de las tuplas es el desempaquetado, repartir sus valores en varias variables de una vez, como la desestructuración de la Estación 11:

def minimo_y_maximo(numeros):
    return min(numeros), max(numeros)    # devuelve una tupla

menor, mayor = minimo_y_maximo([4, 9, 1])   # 1 y 9

Diccionarios

Un diccionario guarda parejas de clave y valor. Se parece a un objeto de JavaScript, con tres diferencias que vas a notar el primer día:

heroe = {"nombre": "Lyra", "nivel": 7}    # las claves van entre comillas
print(heroe["nombre"])                     # siempre con corchetes: heroe.nombre NO funciona
heroe["vida"] = 240                        # añadir o cambiar
print(heroe.get("mana", 0))                # si no existe, devuelve 0 en vez de fallar
del heroe["nivel"]                         # borrar una clave
print("vida" in heroe)                     # ¿existe la clave?

for clave, valor in heroe.items():         # recorrer parejas
    print(clave, "→", valor)
  • Las claves de texto van siempre entre comillas: {nombre: "Lyra"} buscaría una variable llamada nombre.
  • Se accede con corchetes, nunca con punto. El punto es para atributos y métodos de objetos, como heroe.get.
  • Leer una clave que no existe con corchetes lanza KeyError. En JavaScript obtenías undefined y el fallo aparecía mucho más tarde. Si la clave puede faltar, usa .get(clave, valor_por_defecto).

Los diccionarios conservan el orden en que añadiste las claves y encuentran cualquier clave en un tiempo casi constante, porque por dentro son tablas hash (Estación 19). El patrón más común con ellos es contar. Síguelo paso a paso:

votos = ["pizza", "tacos", "pizza", "sushi"]
conteo = {}
for comida in votos:
    conteo[comida] = conteo.get(comida, 0) + 1
print(conteo)
ganadora = max(conteo, key=conteo.get)
print("Gana:", ganadora)

Conjuntos

Un conjunto guarda elementos sin repetir y sin orden. Responde muy rápido a «¿está este elemento?» y permite las operaciones de conjuntos de la Estación 18:

print(amigos_ana | amigos_leo)    # unión
print(amigos_ana - amigos_leo)    # diferencia

Comprensiones: map y filter en una línea

En la Estación 11 transformaste arrays con map y los filtraste con filter. Python tiene esas funciones, pero la comunidad casi siempre prefiere una sintaxis propia, la comprensión de listas (en inglés, list comprehension): una lista nueva descrita entre corchetes con un for dentro.

precios = [12.5, 3.0, 45.0, 8.75]

# JavaScript: precios.map(p => p * 1.16)
con_iva = [round(p * 1.16, 2) for p in precios]      # [14.5, 3.48, 52.2, 10.15]

# JavaScript: precios.filter(p => p < 10)
baratos = [p for p in precios if p < 10]             # [3.0, 8.75]

# Las dos cosas a la vez: transformar solo los que cumplen
nombres = ["ana", "leo", "mía", "gabriela"]
cortos = [n.title() for n in nombres if len(n) == 3]   # ['Ana', 'Leo', 'Mía']

Se lee casi en voz alta: «p redondeado, para cada p en precios, si p es menor que 10». La forma general es [expresión for elemento in iterable if condición], y la parte del if es opcional. La misma idea sirve para diccionarios y conjuntos, y sin corchetes dentro de una función como sum:

cuadrados = {n: n ** 2 for n in range(1, 5)}   # {1: 1, 2: 4, 3: 9, 4: 16}
iniciales = {n[0] for n in nombres}              # conjunto de primeras letras
total_caros = sum(p for p in precios if p > 10)  # 57.5, sin crear una lista intermedia

Consejo de oficio

Una comprensión debe caber de un vistazo. Si necesitas dos for, tres condiciones o una línea que no entra en la pantalla, vuelve al bucle normal: se lee mejor. Una comprensión no debe usarse solo por sus efectos (por ejemplo, para llamar a print muchas veces); para eso está el for.

Funciones y módulos

Las funciones de la Estación 10 se traducen casi palabra por palabra. Lo nuevo está en los parámetros, que en Python son más flexibles, y en cómo se reparte un programa en varios archivos.

def y return

def calcular_danio(ataque, defensa, critico=False):
    """Devuelve el daño de un golpe. Nunca menos de 1."""
    danio = max(1, ataque - defensa)

    return danio

Funciones como valores y lambda

Las funciones son valores, como en JavaScript: puedes guardarlas en variables y pasarlas a otras funciones (lo viste como callbacks en la Estación 10). Para funciones cortas de usar y tirar, Python tiene lambda, el equivalente de una función flecha, con una limitación: su cuerpo es una sola expresión, sin return y sin varias líneas.

jugadores = [
    {"nombre": "Ana", "puntos": 1200},
    {"nombre": "Leo", "puntos": 950},
    {"nombre": "Mía", "puntos": 1480},
]
# JavaScript: [...jugadores].sort((a, b) => b.puntos - a.puntos)
ranking = sorted(jugadores, key=lambda j: j["puntos"], reverse=True)
for posicion, j in enumerate(ranking, start=1):
    print(f"{posicion}. {j['nombre']:<5}{j['puntos']:>6}")

mejor = max(jugadores, key=lambda j: j["puntos"])
print("Mejor:", mejor["nombre"])      # Mejor: Mía

Fíjate en la diferencia de enfoque. En JavaScript, sort recibe una función que compara dos elementos. En Python, sorted, max y min reciben una función key que dice por qué valor ordenar cada elemento. Es más corto y más difícil de equivocarse.

Anotaciones de tipo

Verás funciones escritas así: def area(base: float, altura: float) -> float:. Son anotaciones de tipo: dicen qué tipos se esperan, como en TypeScript (Estación 23). La gran diferencia es que Python las ignora al ejecutar: no impiden pasar un texto. Las comprueban el editor y herramientas aparte, como mypy. Son opcionales, y en proyectos de equipo cada vez más habituales.

Sobre el ámbito, basta una regla: las variables que creas dentro de una función son locales, y una función puede leer las variables de fuera, pero si intenta asignar una variable global, Python crea en su lugar una local con el mismo nombre. Existe la palabra global para forzarlo, pero en código limpio no se usa: pasa los datos como parámetros y devuelve resultados.

Módulos: cada archivo es un módulo

En la Estación 22 viste los módulos de JavaScript, con export e import. En Python, cada archivo .py es un módulo, y todo lo que defines en él se puede importar desde otro: no existe export. Si una función es solo de uso interno, la costumbre es empezar su nombre con guion bajo (_calcular_interno) para avisar «no uses esto desde fuera».

Imagina un proyecto con dos archivos en la misma carpeta:

# utilidades.py

def precio_con_iva(precio):
    return round(precio * (1 + TASA_IVA), 2)
# main.py

Hay tres formas de importar y las verás todas:

def main():
    print("Arranca el juego")

Así, main() solo arranca si ejecutas el archivo, y no cuando alguien lo importa para reutilizar sus funciones. Excepciones y archivos

Python se queja más que JavaScript. Donde JavaScript devuelve undefined, NaN o Infinity y sigue adelante, Python se detiene con un error que te dice qué pasó y dónde. Una traza (en inglés, traceback) se lee así:

  1. Empieza por la última línea. KeyError: 'pocion' es el tipo de error y su detalle: se buscó la clave 'pocion' y no existe.

  2. Sube una entrada. La última entrada File ... es donde ocurrió: línea 4, dentro de usar. Los signos ~~~^^^ subrayan la parte exacta de la línea que falló.

  3. Sigue subiendo para ver quién llamó a quién. most recent call last significa «la llamada más reciente, al final»: el programa principal (<module>) llamó a turno, que llamó a usar. Es la pila de la Estación 12, con el orden invertido.

  4. Busca el primer archivo que es tuyo. Si el error sale dentro de una librería, las entradas de arriba y de abajo te dicen desde qué línea de tu código la llamaste. Casi siempre el fallo está ahí, no en la librería.

try, except, else y finally

Capturar errores funciona como el try...catch de la Estación 12, con palabras nuevas: catch se escribe except y throw se escribe raise. La gran diferencia es que en Python se captura por tipo: escribes qué clase de error esperas, y los demás siguen su camino.

texto = "12a"
try:
    edad = int(texto)
except ValueError:
    print("Eso no es un número")
else:
    print("Edad válida:", edad)       # solo si NO hubo error
finally:
    print("Esto se ejecuta siempre")  # haya error o no

El bloque else es un invento de Python que no existe en JavaScript: su código se ejecuta solo si el try terminó sin errores. Así el try contiene únicamente la línea que puede fallar, y queda claro qué error estás esperando.     """Error propio: hereda de Exception y no necesita nada más."""

def comprar(precio, saldo):
    if precio <= 0:
        raise ValueError("El precio debe ser positivo")
    if precio > saldo:
        raise SaldoInsuficiente(f"Te faltan {precio - saldo} monedas")
    return saldo - precio

try:
    saldo = comprar(120, 100)
except SaldoInsuficiente as error:
    print("No se pudo comprar:", error)    # No se pudo comprar: Te faltan 20 monedas

Pedir perdón en vez de permiso

En Python es costumbre intentar la operación y capturar el error si falla, en lugar de comprobar todo antes. La comunidad lo resume con la sigla EAFP, easier to ask for forgiveness than permission, «es más fácil pedir perdón que permiso». Por ejemplo, para convertir un texto a número se escribe try: int(texto) en vez de revisar primero si todos sus caracteres son dígitos. Dos reglas: captura siempre un tipo concreto, y nunca escribas un except: vacío que se trague todos los errores, porque esconderá también los que no esperabas.

Leer y escribir archivos

Los programas de Python trabajan con archivos todo el tiempo: registros, configuraciones, datos exportados de una hoja de cálculo. En tu computadora, un archivo se abre con open, casi siempre dentro de un bloque with:

# Escribir: "w" crea el archivo (o lo vacía si ya existía)
with open("notas.txt", "w", encoding="utf-8") as archivo:
    archivo.write("Primera nota\n")
    archivo.write("Segunda nota\n")

# Añadir al final: "a"
with open("notas.txt", "a", encoding="utf-8") as archivo:
    archivo.write("Tercera nota\n")

# Leer línea por línea: "r" (el modo por defecto)
with open("notas.txt", encoding="utf-8") as archivo:
    for numero, linea in enumerate(archivo, start=1):
        print(numero, linea.strip())    # strip quita el salto de línea final

El bloque with cierra el archivo al terminar, aunque haya un error en medio. Sin él tendrías que acordarte de llamar a archivo.close(), y si el programa falla antes, el archivo quedaría abierto. Los modos principales son "r" (leer), "w" (escribir desde cero; ¡borra lo que había!) y "a" (añadir al final).

Escribe siempre encoding="utf-8"

Hasta Python 3.14, si no indicas la codificación, open usa la del sistema, que en Windows puede no ser UTF-8: las tildes y las eñes salen mal, o el programa falla en otra computadora. Python 3.15 cambia el valor por defecto a UTF-8 (lo decidió la PEP 686), pero escribir encoding="utf-8" sigue siendo la costumbre segura y funciona en todas las versiones.

Para formatos con estructura, la biblioteca estándar trae json y csv. El CSV (comma-separated values, valores separados por comas) es el formato de texto más sencillo para tablas: una fila por línea, columnas separadas por comas, y la primera línea con los nombres de las columnas. Cualquier hoja de cálculo lo exporta.

import csv
import json
from pathlib import Path

# CSV: cada fila llega como un diccionario de TEXTOS
with open("ventas.csv", encoding="utf-8", newline="") as archivo:
    for fila in csv.DictReader(archivo):
        print(fila["producto"], float(fila["precio"]))

# JSON: como JSON.stringify y JSON.parse, pero con archivos
partida = {"jugador": "Mira", "nivel": 3, "inventario": ["espada"]}
with open("partida.json", "w", encoding="utf-8") as archivo:

class Personaje:
    def __init__(self, nombre, vida_maxima=100):
        self.nombre = nombre
        self.vida_maxima = vida_maxima
        self.vida = vida_maxima

    def recibir_danio(self, cantidad):
        self.vida = max(0, self.vida - cantidad)

    def curar(self, cantidad):
        self.vida = min(self.vida_maxima, self.vida + cantidad)

    def esta_vivo(self):
        return self.vida > 0

    def __str__(self):
        return f"{self.nombre} ({self.vida}/{self.vida_maxima} PV)"


lyra = Personaje("Lyra", 120)
brom = Personaje("Brom")
lyra.recibir_danio(50)
print(lyra)
print(brom, brom.esta_vivo())
lyra.curar(30)
print(lyra)
lyra.curar(100)
print(lyra)

min pone el techo igual que max(0, ...) pone el suelo en recibir_danio. Si olvidas self en la definición, Python protesta al llamar: TypeError: Personaje.curar() takes 1 positional argument but 2 were given, porque el objeto siempre llega como primer argumento.

Dataclasses: clases para guardar datos

Muchas clases solo existen para agrupar datos: un producto, un punto, una fila de un informe. Escribir su __init__, su __str__ y su __eq__ a mano es repetitivo. El módulo dataclasses los genera por ti. La línea @dataclass es un decorador: una función que recibe la clase (o la función) de debajo y le añade comportamiento.

from dataclasses import dataclass

@dataclass
class Producto:
    nombre: str
    precio: float
    stock: int = 0          # valor por defecto

taza = Producto("Taza", 7.25, stock=4)
print(taza)                                  # Producto(nombre='Taza', precio=7.25, stock=4)
print(taza == Producto("Taza", 7.25, 4))     # True: compara los campos, no la identidad
taza.stock -= 1

Las anotaciones (nombre: str) le dicen a dataclass qué campos tiene la clase, en qué orden van en el constructor y de qué tipo se esperan. Recuerda que Python no comprueba esos tipos al ejecutar; tu editor sí te avisará.

Entornos, paquetes y librerías

Llegamos a la columna derecha del diagrama del principio: el ecosistema. La biblioteca estándar es grande, pero la fuerza de Python está en los cientos de miles de paquetes que publica la comunidad en PyPI (Python Package Index, pypi.org), el equivalente del registro de npm que usaste en la Estación 29. Para instalarlos sin romper nada necesitas una pieza que en Node.js no hacía falta pedir: el entorno virtual.

Por qué un entorno virtual

En Node.js, npm install guarda los paquetes en la carpeta node_modules de cada proyecto. Python, por defecto, los instalaría en una carpeta compartida por toda la computadora. Mira qué problema causa y cómo se resuelve:

venv y pip, paso a paso

pip es el instalador de paquetes oficial: viene con Python y descarga paquetes de PyPI. venv es el módulo de la biblioteca estándar que crea entornos virtuales. Este es el ciclo completo, con la salida real en Linux y Python 3.14 (tus números de versión pueden ser otros):

  1. Crea la carpeta del proyecto y, dentro, el entorno virtual. Se llama .venv por costumbre; el punto la oculta en macOS y Linux:

    $ mkdir clima
$ cd clima
$ python -m venv .venv

  2. Actívalo. El comando depende del sistema:

    $ source .venv/bin/activate          # macOS y Linux
PS> .venv\Scripts\Activate.ps1        # Windows, PowerShell
> .venv\Scripts\activate.bat          # Windows, cmd

    Desde ese momento, el indicador empieza con (.venv), y python y pip son los del entorno, en cualquier sistema. Si PowerShell se niega a ejecutar el script de activación, la documentación oficial indica ejecutar una vez Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser.

  3. Instala lo que necesites:

Idea clave

Escribe python -m pip en lugar de pip a secas. La -m ejecuta el módulo pip del mismo Python que estás usando, así que el paquete se instala donde tú crees. Con varios Pythons en la computadora, pip a secas puede pertenecer a otro, y entonces instalas en un sitio y ejecutas en otro: «lo instalé, pero me dice ModuleNotFoundError». Es el problema de instalación más común de Python.

error: externally-managed-environment

Si intentas pip install fuera de un entorno virtual en Ubuntu, Debian, Fedora o macOS con Homebrew, verás esto:

error: externally-managed-environment

× This environment is externally managed
╰─> To install Python packages system-wide, try apt install
    python3-xyz, where xyz is the package you are trying to
    install.

No es un fallo: el sistema operativo usa ese Python para sus propias herramientas y lo protege para que no lo rompas (la norma se llama PEP 668). La solución es la que acabas de aprender: crea un entorno virtual y activa. Verás en internet la opción --break-system-packages; su nombre avisa de lo que hace («romper los paquetes del sistema»), así que no la uses.

Hay dos archivos que tampoco deben subirse a Git. Uno es la carpeta .venv. El otro es __pycache__, que Python crea junto a tus módulos al importarlos para guardar su bytecode ya traducido (el paso intermedio que viste en la Estación 22) y arrancar más rápido la próxima vez. Desde Python 3.13, venv mete dentro de .venv un pequeño .gitignore que la oculta a Git, pero la costumbre es escribir las dos carpetas en el .gitignore del proyecto, como hiciste con node_modules en la Estación 24. Practícalo:

  1. Entra en el proyecto con cd clima. Compara ls con ls -a: la carpeta .venv está oculta. Mira también qué hay en __pycache__.
  2. Crea el .gitignore con dos líneas: echo ".venv/" > .gitignore y echo "__pycache__/" >> .gitignore. Compruébalo con cat .gitignore.
  3. Crea el repositorio con git init, prepara todo con git add . y revisa con git status que no aparecen ni .venv ni __pycache__.
  4. Guarda la primera versión: git commit -m "feat: primera versión del clima".

class Inventario:
    def __init__(self):
        self.objetos = {}   # nombre -> cantidad

    def agregar(self, nombre, cantidad=1):
        self.objetos[nombre] = self.objetos.get(nombre, 0) + cantidad

    def quitar(self, nombre, cantidad=1):
        if self.objetos.get(nombre, 0) < cantidad:
            raise ValueError(f"No tienes {nombre}")
        self.objetos[nombre] -= cantidad
        if self.objetos[nombre] == 0:
            del self.objetos[nombre]

    def total(self):
        return sum(self.objetos.values())

    def __str__(self):
        return ", ".join(f"{nombre} x{cantidad}" for nombre, cantidad in sorted(self.objetos.items()))

try:
    mochila.quitar("escudo")
except ValueError as error:

Mensajes secretos: el cifrado César

Reto

El cifrado César desplaza cada letra un número fijo de posiciones en el alfabeto: con desplazamiento 3, la «a» pasa a «d» y la «z» da la vuelta hasta la «c». Completa cifrar para las letras minúsculas de la «a» a la «z» (sin la «ñ»); el resto de caracteres queda igual. Con un desplazamiento negativo, descifra. Debe imprimir dwdtxh do dpdqhfhu, ataque al amanecer y apssp yza.

Pista 1

ord("a") da 97, el código de la letra, y chr(98) da "b". La posición de una letra en el alfabeto es ord(letra) - ord("a"), de 0 a 25.

Pista 2

La nueva posición es (posicion + desplazamiento) % 26. En Python, (0 - 3) % 26 da 23, la «x»: el resto de Python ya da la vuelta bien con negativos. En JavaScript daría -3 y tendrías que sumar 26.

Ver una solución 
def cifrar(texto, desplazamiento):
    resultado = ""
    for letra in texto:
        if "a" <= letra <= "z":
            posicion = ord(letra) - ord("a")
            nueva = (posicion + desplazamiento) % 26
            resultado += chr(ord("a") + nueva)
        else:
            resultado += letra
    return resultado

secreto = cifrar("ataque al amanecer", 3)
print(secreto)
print(cifrar(secreto, -3))
print(cifrar("zorro xyz", 1))

"a" <= letra <= "z" es una comparación encadenada con textos: compara por orden alfabético (por código). Otra forma: alfabeto = "abcdefghijklmnopqrstuvwxyz" y alfabeto.index(letra). Y otra más pythónica: construir una lista de letras y unirlas al final con "".join(...).

import csv
import io

DATOS = """fecha,jugador,juego,minutos,puntos
2026-09-01,Ana,Tetris,25,1800
2026-09-01,Leo,Snake,40,950
2026-09-02,Mía,Tetris,30,2100
2026-09-02,Ana,Snake,15,700
2026-09-03,Leo,Tetris,20,abc
2026-09-03,Mía,Snake,35,1200
2026-09-04,Ana,Tetris,30,2400
2026-09-04,Leo,Snake,,600
2026-09-05,Mía,Pong,10,300
"""
PUNTOS_POR_ALMOHADILLA = 500


def leer_partidas(archivo):
    """Devuelve la lista de partidas válidas y cuántas filas se descartaron."""
    validas = []
    descartadas = 0
    for fila in csv.DictReader(archivo):
        try:
            fila["minutos"] = int(fila["minutos"])
            fila["puntos"] = int(fila["puntos"])
        except ValueError:
            descartadas += 1
            continue
        validas.append(fila)
    return validas, descartadas


def resumen_por_jugador(partidas):
    """Suma puntos, partidas y minutos de cada jugador."""
    resumen = {}
    for p in partidas:
        datos = resumen.setdefault(p["jugador"], {"puntos": 0, "partidas": 0, "minutos": 0})
        datos["puntos"] += p["puntos"]
        datos["partidas"] += 1
        datos["minutos"] += p["minutos"]
    return resumen


def promedio_por_juego(partidas):
    """Devuelve un diccionario juego -> promedio de puntos."""
    por_juego = {}
    for p in partidas:
        por_juego.setdefault(p["juego"], []).append(p["puntos"])
    return {juego: sum(puntos) / len(puntos) for juego, puntos in por_juego.items()}


def main():
    partidas, descartadas = leer_partidas(io.StringIO(DATOS))
    jugadores = resumen_por_jugador(partidas)
    ranking = sorted(jugadores.items(), key=lambda par: par[1]["puntos"], reverse=True)

    print("=== INFORME DE PARTIDAS ===")
    print(f"Filas válidas: {len(partidas)} · descartadas: {descartadas}")
    print()
    print("Ranking por puntos")
    for posicion, (nombre, d) in enumerate(ranking, start=1):
        palabra = "partida" if d["partidas"] == 1 else "partidas"
        print(f"{posicion}. {nombre:<5}{d['puntos']:>6}  ({d['partidas']} {palabra}, {d['minutos']} min)")
    print()
    print("Promedio por juego")
    promedios = promedio_por_juego(partidas)
    for juego, promedio in sorted(promedios.items(), key=lambda par: par[1], reverse=True):
        print(f"{juego:<8}{promedio:>8.1f}")
    print()
    print(f"Gráfico (cada # = {PUNTOS_POR_ALMOHADILLA} puntos)")
    for nombre, d in ranking:
        print(f"{nombre:<5}{'#' * (d['puntos'] // PUNTOS_POR_ALMOHADILLA)}")


if __name__ == "__main__":
    main()

Después de numeros = [3, 1, 2] y ordenada = numeros.sort(), ¿cuánto vale ordenada?

  1. [1, 2, 3]

    La lista numeros sí queda así, pero sort no la devuelve.

  2. [3, 1, 2]

    sort no hace una copia: ordena la lista original.

  3. Da un error

    La línea es válida; el problema es más sutil.

  4. None

    Correcto. sort() ordena en su sitio y devuelve None. Para obtener una lista nueva, usa sorted(numeros).

¿Qué produce [n * 2 for n in [1, 2, 3, 4] if n > 2]?

  1. [2, 4, 6, 8]

    Esa sería la lista sin el if: el filtro deja pasar solo los mayores que 2.

  2. [6, 8]

    Correcto. Primero se filtran el 3 y el 4, y después se multiplican por 2.

  3. [3, 4]

    Filtra bien, pero olvida la expresión n * 2 del principio.

  4. [False, False, True, True]

    La condición decide qué elementos entran; no se guarda en la lista.

En un método como def curar(self, cantidad):, ¿qué es self?

  1. Una palabra obligatoria para crear objetos, como new

    En Python los objetos se crean sin new, llamando a la clase: Personaje("Lyra").

  2. Una marca para que los atributos sean privados

    La privacidad en Python es solo una convención con guion bajo (_vida).

  3. El objeto sobre el que se llama el método, que Python pasa como primer argumento

    Correcto. Es el this de JavaScript, pero explícito: lyra.curar(30) equivale a Personaje.curar(lyra, 30).

  4. Una variable global que comparten todos los objetos

    Cada llamada recibe su propio objeto como self.

¿Para qué sirve crear un entorno virtual en cada proyecto?

  1. Para que cada proyecto tenga sus paquetes y versiones sin afectar a los demás ni al Python del sistema

    Correcto. Es la misma idea que node_modules en cada proyecto de Node.

  2. Para que Python se ejecute más rápido

    La velocidad es la misma; lo que cambia es dónde se instalan los paquetes.

  3. Porque sin él no se pueden ejecutar archivos .py

    Puedes ejecutar archivos sin entorno; lo necesitas para instalar paquetes de forma ordenada.

  4. Para subir los paquetes instalados a GitHub junto con el proyecto

    Al revés: .venv no se sube. Se sube requirements.txt o uv.lock, y cada persona recrea su entorno.

En Ubuntu, pip install requests responde error: externally-managed-environment. ¿Qué haces?

  1. Repetir el comando con --break-system-packages

    Su nombre lo dice: puede romper herramientas del sistema que dependen de ese Python.

  2. Crear y activar un entorno virtual, e instalar ahí con python -m pip install requests

    Correcto. El sistema protege su Python y te pide que instales en un entorno propio.

  3. Usar sudo pip install requests

    Es peor: modificas como administrador el Python del que depende el sistema operativo.

  4. Desinstalar Python y volver a instalarlo

    No hace falta: el mensaje no es un fallo de la instalación, es una protección.

Una traza de Python es larga y termina con KeyError: 'pocion'. ¿Cómo la lees?

  1. Desde la primera línea hacia abajo, porque ahí está el error

    Esa es la forma de leer las pilas de JavaScript. Python pone la llamada más reciente al final.

  2. Solo la primera entrada File ..., que es donde falló

    La primera entrada es el programa principal, el punto de partida, no el lugar del fallo.

  3. No hace falta leerla: basta con envolver todo el programa en un try

    Esconder el error no lo arregla, y un try que lo captura todo oculta también otros fallos.

  4. Desde abajo: la última línea da el tipo de error y la entrada anterior dice en qué línea ocurrió; subiendo ves quién llamó a quién

    Correcto. most recent call last: lo más reciente, al final.

Glosario

Python
Lenguaje de programación de propósito general, creado por Guido van Rossum en 1991, muy usado en inteligencia artificial, datos, automatización y backend.
CPython
El intérprete oficial de Python, escrito en C. Es el que se instala desde python.org.
Intérprete interactivo (REPL)
Modo en el que escribes una línea de Python y ves el resultado al momento. Se abre escribiendo python en la terminal; su indicador es >>>.
Sangría
Espacios al principio de una línea. En Python marca qué líneas forman un bloque; la convención es 4 espacios por nivel.
snake_case
Forma de escribir nombres en minúsculas con las palabras unidas por guion bajo, como precio_total. Es la norma en Python.
PEP 8
La guía de estilo oficial de Python. Un PEP (Python Enhancement Proposal) es un documento público que propone o describe un cambio o una norma del lenguaje.
f-string
Texto con una f delante en el que se insertan valores entre llaves y se les da formato: f"Total: {total:.2f}".
None
El valor que representa «nada» en Python. Ocupa el lugar de null y undefined de JavaScript.
Lista
Colección ordenada y modificable de elementos, escrita entre corchetes: [1, 2, 3]. Equivale al array.
Tupla
Colección ordenada que no se puede modificar, escrita entre paréntesis: (3, 5). Útil para grupos fijos de valores.
Diccionario
Colección de parejas clave y valor, como {"nombre": "Ana"}. Equivale a un objeto literal o a un Map.
Conjunto (set)
Colección sin orden y sin elementos repetidos, muy rápida para preguntar si algo está dentro.
Iterable
Cualquier cosa que se puede recorrer con for: listas, textos, diccionarios, archivos, range…
Comprensión de listas
Forma compacta de crear una lista a partir de otra: [x * 2 for x in datos if x > 0]. Sustituye a map y filter.
Desempaquetado
Repartir los valores de una tupla o una lista en varias variables a la vez: x, y = posicion.
Argumento con nombre
Argumento que se pasa indicando el nombre del parámetro, en cualquier orden: sorted(lista, reverse=True). En inglés, keyword argument.
Módulo
Un archivo .py cuyo contenido se puede usar desde otro archivo con import.
Biblioteca estándar
El conjunto de módulos que viene con Python sin instalar nada: math, json, csv, datetime, random…
Traza (traceback)
El informe que muestra Python cuando un error detiene el programa. Se lee de abajo arriba: la última línea dice el tipo de error.
self
Primer parámetro de los métodos de una clase: el objeto sobre el que se llama el método. Equivale a this, pero se escribe explícitamente.
Método especial (dunder)
Método con dos guiones bajos a cada lado, como __init__ o __str__, que Python llama por su cuenta en momentos concretos.
Decorador
Función que se escribe con @ encima de otra función o clase y le añade comportamiento, como @dataclass o @app.get(...).
Entorno virtual
Carpeta (normalmente .venv) con un Python y unos paquetes propios de un proyecto, aislados del resto. Se crea con python -m venv .venv.
pip y PyPI
pip es el instalador oficial de paquetes de Python; PyPI (pypi.org) es el registro público de donde los descarga, como npm y su registro.
uv
Herramienta que instala Python, crea entornos virtuales y gestiona los paquetes de un proyecto en un solo programa, con pyproject.toml y uv.lock.
