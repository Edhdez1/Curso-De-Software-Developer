Lo que vas a lograr

En la estación anterior construiste páginas con HTML: títulos, párrafos, listas, imágenes y formularios. Funcionan, pero se ven como un documento de 1995: letra negra, enlaces azules y todo apilado de arriba abajo. CSS es el lenguaje que decide cómo se ve cada cosa: colores, tamaños, espacios, columnas y movimiento. Con el mismo HTML y otro CSS, una página puede parecer una tienda, un periódico o el menú de un videojuego.

  • Escribir reglas CSS y conectarlas a tu página con un archivo externo.
  • Elegir exactamente los elementos que quieres con selectores: de tipo, de clase, de id, de atributo, combinadores, pseudoclases y pseudoelementos.
  • Predecir qué regla gana cuando dos se contradicen, usando la cascada, la especificidad y la herencia.
  • Escribir colores en cinco notaciones (nombre, hex, rgb(), hsl() y oklch()), comprobar su contraste y elegir la unidad adecuada (px, rem, em, %, vw, ch).
  • Controlar tamaños y espacios con el modelo de caja y box-sizing.
  • Distribuir elementos con flexbox y con grid, y saber cuándo conviene cada uno.
  • Colocar elementos con position y ordenar capas con z-index.
  • Crear páginas que se adaptan del teléfono al monitor con mobile first, media queries, clamp() e imágenes fluidas.
  • Ordenar tu CSS con variables, añadir transiciones y animaciones que respetan a quien prefiere menos movimiento, e investigar cualquier estilo con las herramientas del navegador.

Necesitas escribir HTML con soltura: etiquetas, los atributos class e id, y la estructura con <head> y <body>. Todo eso está en la Estación 13: HTML. También te ayuda recordar qué es una variable (Estación 7) y saber moverte por carpetas en la terminal (Estación 5). Los talleres de esta estación funcionan aquí mismo: editas el HTML y el CSS en dos pestañas y ves el resultado en una vista previa debajo.

Es una de las estaciones más largas del curso, porque CSS es enorme. No intentes hacerla de un tirón. Qué es CSS y cómo se conecta a tu página

Abre cualquier página HTML sin CSS y verás siempre lo mismo: el título grande y en negrita, los enlaces azules y subrayados, un pequeño margen alrededor de todo. Eso no lo escribiste tú. Cada navegador trae una hoja de estilos del navegador (en inglés, user agent stylesheet): un CSS de fábrica que da un aspecto mínimo a cualquier documento. Por eso un <h1> mide el doble que el texto normal y el <body> tiene 8 píxeles de margen.

CSS significa Cascading Style Sheets, «hojas de estilo en cascada». Una hoja de estilos es una lista de instrucciones sobre el aspecto de los elementos: «los títulos, en azul marino»; «las fotos, con esquinas redondeadas»; «el menú, en una fila». Lo de «en cascada» se refiere a que varias instrucciones pueden hablar del mismo elemento y hay un sistema para decidir cuál gana. Lo verás a fondo en la sección Cascada y herencia.

Piensa en una casa. El HTML son las paredes y las habitaciones: qué hay y dónde está cada cosa. El CSS es la pintura, los muebles y la decoración. La analogía se queda corta en un punto: CSS no solo pinta, también puede mover las habitaciones de sitio. Con CSS decides si el menú va arriba o a un lado, o si las fotos forman tres columnas o una sola.

CSS no es un lenguaje de programación como JavaScript. Es declarativo: describes el resultado que quieres («este título es azul y mide 32 píxeles») y el navegador se encarga de cómo lograrlo. Tiene funciones para calcular (calc(), clamp()) y variables, pero no tiene bucles ni instrucciones paso a paso.

Anatomía de una regla

Todo CSS está hecho de reglas. Una regla dice «a estos elementos, ponles estos estilos». Tiene dos partes:

  • El selector elige a qué elementos se aplica la regla. Aquí, h1 significa «todos los títulos <h1> de la página».
  • El bloque de declaraciones va entre llaves { }. Dentro hay una o más declaraciones.
  • Cada declaración tiene una propiedad (qué quieres cambiar, como color), dos puntos, un valor (cómo lo quieres, como navy) y termina en punto y coma.

Una hoja de estilos real tiene muchas reglas, cada una con varias declaraciones. Por convención se escribe una declaración por línea, con dos espacios de sangría. Al navegador le dan igual los espacios y saltos de línea; a las personas que leen tu código, no.

h1 {
  color: navy;
  font-size: 32px;
}

p {
  color: #333333;
  line-height: 1.6;
}

Antes de ejecutar el siguiente taller, predice: ¿de qué color será el título?, ¿qué párrafo se verá distinto y por qué? Después pulsa «Ejecutar». La pestaña HTML tiene la página; la pestaña CSS, los estilos.

Ahora modifica: cambia navy por darkred; añade text-align: center; dentro de la regla de h1; escribe una regla nueva para a con color: purple;. Si te equivocas, el botón «Reiniciar» devuelve el código original.

Fíjate en un detalle: el párrafo .nota recibe estilos de dos reglas a la vez. De la regla p le llega el tamaño de 18 píxeles, y de la regla .nota, el verde y la cursiva. Las dos reglas le dan un color distinto, y gana el de .nota. El porqué lo verás en la sección de cascada.

Un archivo de estilos enlazado

/* En css/estilos.css */
h1, h2 { color: navy; font-family: Georgia, serif; }

El archivo externo tiene tres ventajas. Cambias el aspecto de todo el sitio tocando un solo archivo. El navegador lo descarga una vez y lo guarda (eso se llama caché), así que las demás páginas cargan más rápido. Y el HTML queda limpio, dedicado solo al contenido.

La ruta del atributo href es una ruta relativa, igual que las de los enlaces y las imágenes: css/estilos.css significa «entra en la carpeta css, que está junto a este HTML, y abre estilos.css». La estructura más habitual de un sitio pequeño es esta:

mi-sitio/
├── index.html
├── css/
│   └── estilos.css
└── img/
    └── portada.jpg

Créala tú con la terminal de práctica. Crea la carpeta mi-sitio; dentro, el archivo index.html y las carpetas css e img; y dentro de css, el archivo estilos.css. Para terminar, escribe una regla dentro de estilos.css con echo. Si no recuerdas los comandos, escribe help.

En el index.html de ese sitio, la línea que conecta los estilos iría dentro del <head>:

<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Mi sitio</title>
  <link rel="stylesheet" href="css/estilos.css">
</head>

Comentarios

En CSS, un comentario empieza con /* y termina con */. Puede ocupar una línea o varias. El navegador lo ignora; sirve para explicar por qué hiciste algo o para separar secciones del archivo.

/* ===== Cabecera ===== */
.cabecera {
  background: #1d3557; /* azul de la marca */
}

En CSS no existe el comentario // … de JavaScript. Si escribes // fondo encima de una regla, el navegador lo toma como parte del selector, el selector deja de ser válido y la regla entera desaparece sin ningún aviso.

CSS no se queja: ignora lo que no entiende

Cuando JavaScript encuentra un error, se detiene y te lo dice. CSS hace lo contrario: si una declaración no es válida, el navegador la descarta y sigue con la siguiente, en silencio. Así una página nunca «se rompe» por un error de CSS, pero también es fácil no darse cuenta de que algo no se aplica.

Escribiste…Qué pasa
colour: red;La propiedad no existe (en CSS se escribe en inglés de Estados Unidos: color). Se ignora esa declaración.
color: 10px;El valor no tiene sentido para esa propiedad. Se ignora.
color: red sin ; y en la línea siguiente font-size: 20px;Sin el punto y coma, el navegador lee todo junto como un solo valor, red font-size: 20px, que no es válido. Se pierden las dos declaraciones.
Una llave } olvidadaLas reglas siguientes quedan «dentro» de la anterior: el navegador las interpreta como reglas anidadas y dejan de aplicarse donde esperabas. Es el error más confuso: revisa siempre que cada { tenga su }. Los editores como VS Code resaltan la pareja de cada llave.

Tu mejor aliada: las herramientas del navegador

Todos los navegadores traen herramientas para desarrolladores, que en Chrome y Edge se llaman DevTools. En la Estación 13 usaste su pestaña Elementos para ver el HTML. Para CSS son todavía más útiles, porque te muestran qué reglas se aplican a cada elemento y te dejan cambiarlas en vivo.

  1. Abre una página y haz clic derecho sobre cualquier elemento. Elige «Inspeccionar». También puedes pulsar F12 o Ctrl + Shift + I (en Mac, Cmd + Option + I).

  2. En el panel Elementos, a la izquierda, está el HTML. Haz clic en una etiqueta para seleccionarla. A la derecha, la pestaña Estilos (Styles) lista todas las reglas que afectan a ese elemento, con el archivo y la línea de donde vienen.

  3. Las declaraciones tachadas son las que perdieron contra otra regla. Si una declaración tiene un icono de advertencia, el navegador no la entendió: revisa si está bien escrita.

  4. Haz clic sobre un valor y cámbialo. Con las flechas ↑ y ↓ los números suben o bajan de 1 en 1, y con Shift pulsada, de 10 en 10. La casilla junto a cada declaración la activa o la desactiva.

  5. La pestaña Calculado (Computed) muestra el valor final de cada propiedad, el que de verdad usa el navegador. Allí también está el dibujo del modelo de caja, que verás más adelante.

Los cambios que haces en DevTools son temporales: desaparecen al recargar la página. Los profesionales los usan como laboratorio: prueban valores en vivo hasta que algo se ve bien y después copian la declaración a su archivo. Cuando algo «no funciona» en CSS, la primera pregunta siempre es: ¿qué dice DevTools de ese elemento?

Firefox tiene herramientas equivalentes, con un inspector de grid y flexbox especialmente bueno. En Safari primero hay que activar las funciones para desarrolladores en los ajustes, en la sección Avanzado. Los nombres de los paneles cambian un poco de una versión a otra; las ideas son las mismas.

Selectores: a quién le hablas

Una página real tiene cientos de elementos. Si quieres poner en rojo solo el precio de los productos agotados, necesitas una forma precisa de decir «ese, y ningún otro». Para eso están los selectores. Dominarlos es la mitad de saber CSS.

Para dar estilo, usa clases casi siempre. Los ids sirven para enlaces internos (href="#contacto") y para JavaScript, pero como selector pesan tanto que después cuesta sobrescribirlos (verás por qué en la próxima sección). Ponle a cada clase un nombre que diga qué es, no cómo se ve: .aviso-error sigue teniendo sentido si mañana el aviso pasa a ser naranja; .texto-rojo, no.

Las clases y los ids distinguen mayúsculas de minúsculas: .Precio no elige a class="precio". Los nombres de etiquetas y de propiedades, en cambio, no las distinguen, aunque se escriben siempre en minúsculas.

Selectores de atributo

Eligen elementos según sus atributos HTML. Van entre corchetes:

[disabled]             { opacity: 0.5; }        /* tiene el atributo disabled */
input[type="email"]    { border-color: steelblue; } /* type es exactamente "email" */
a[href^="https"]       { font-weight: bold; }    /* href empieza con "https" */
a[href$=".pdf"]        { color: crimson; }       /* href termina en ".pdf" */
img[alt*="logo"]       { width: 120px; }         /* alt contiene "logo" */

Una pseudoclase elige elementos según algo que no está escrito en el HTML: su estado (el ratón está encima, está marcado, tiene el foco) o su posición entre sus hermanos. Se escribe con dos puntos:

Nunca quites el contorno del foco (outline: none) sin poner otro indicador bien visible en :focus-visible. Quien navega con teclado lo necesita para saber dónde está. Y no escondas información importante detrás de :hover: en una pantalla táctil no hay ratón que pase por encima.

:has() llegó a todos los navegadores principales a finales de 2023. Durante años fue imposible elegir a un padre según sus hijos. Cuando tengas dudas sobre si algo moderno funciona, busca la propiedad en MDN: su etiqueta Baseline te dice desde cuándo funciona en Chrome, Edge, Firefox y Safari. «Ampliamente disponible» significa que lleva al menos dos años y medio en todos ellos.

Pseudoelementos: partes que no están en el HTML

Un pseudoelemento elige una parte de un elemento, o crea una cajita nueva dentro de él. Se escribe con dos pares de dos puntos (::), para distinguirlo de las pseudoclases:

  • ::before y ::after crean un contenido al principio o al final del elemento. Necesitan la propiedad content, aunque sea vacía (content: "").
  • ::first-letter y ::first-line: la primera letra o la primera línea de un texto.
  • ::placeholder: el texto de ejemplo de un campo de formulario.
  • ::marker: la viñeta o el número de un elemento de lista.
  • ::selection: el texto que la persona selecciona con el ratón.
.obligatorio::after {
  content: " *";
  color: crimson;
}

p::first-letter {
  font-size: 2em;
  font-weight: bold;
}

El texto que añades con content no está en el HTML y los lectores de pantalla no siempre lo leen. Úsalo para adornos, no para información esencial. En código antiguo verás :before con un solo par de dos puntos: los navegadores lo siguen aceptando por compatibilidad.

Cascada, especificidad y herencia

En el primer taller, el párrafo .nota recibía dos colores: uno de la regla p y otro de la regla .nota. En un proyecto real hay cientos de reglas y es normal que varias hablen del mismo elemento. El navegador no elige al azar: sigue un procedimiento llamado cascada. Si lo entiendes, dejarás de pelearte con CSS «que no hace caso».

La cascada en cuatro preguntas

Para cada propiedad de cada elemento, el navegador reúne todas las declaraciones que le aplican y se hace estas preguntas, en orden. Solo pasa a la siguiente si hay empate:

  1. ¿De dónde viene y lleva !important? Tus estilos ganan a la hoja de estilos del navegador. Una declaración marcada con !important se salta la fila (lo verás más abajo).

  2. ¿Está escrita en el atributo style del elemento? Un estilo en línea gana a cualquier selector de una hoja de estilos.

  3. ¿Qué selector es más específico? Gana el de mayor especificidad, una especie de «peso» que depende de qué tipos de selector usa.

  4. ¿Cuál aparece después? Si todo lo anterior empata, gana la última declaración que el navegador leyó. Por eso importa el orden de tus reglas y el orden de tus archivos <link>.

El algoritmo real tiene algunos pasos más, como las capas de cascada (@layer), que permiten agrupar reglas por prioridad, y los estilos de las animaciones. Son herramientas para proyectos grandes. Con estas cuatro preguntas explicas casi todo lo que te vas a encontrar.

Especificidad: el medallero

La especificidad se cuenta en tres columnas, que se escriben separadas por guiones: ids - clases - tipos.

  • Columna de ids: cada #algo suma 1.
  • Columna de clases: cada clase (.algo), cada selector de atributo ([type="email"]) y cada pseudoclase (:hover) suma 1.
  • Columna de tipos: cada etiqueta (p, li) y cada pseudoelemento (::before) suma 1.
  • No suman nada: el selector universal *, los combinadores (espacio, >, +, ~) ni la pseudoclase :where().

Funciona como el medallero de unos Juegos Olímpicos. Primero se comparan los oros; las platas solo cuentan si hay empate en oros, y los bronces solo si también empatan las platas. Un país con 1 oro va por delante de otro con 0 oros y 30 platas. En CSS, un solo id gana a cualquier cantidad de clases. La analogía tiene un límite: en el medallero nadie gana por llegar el último, y en CSS, si las tres columnas empatan, gana la regla que aparece después.

El error más común es pensar que «la última regla siempre gana». Solo gana si empata en especificidad. Si añades una regla al final del archivo y no hace efecto, compara pesos antes de echarle la culpa al navegador. La pestaña Estilos de DevTools te muestra tachada la declaración que perdió.

!important: el botón de emergencia

Si añades !important al final de un valor, esa declaración gana a todas las declaraciones normales, sin importar la especificidad:

.precio { color: black !important; }
#oferta .precio { color: red; }   /* pierde, aunque pesa más */

Parece práctico, pero es una trampa. Para ganarle a un !important necesitas otro !important con más especificidad, y el archivo se convierte en una carrera de armamento. Tiene usos legítimos: clases de utilidad que siempre deben aplicarse, pisar estilos de código ajeno que no puedes cambiar, o reglas de accesibilidad como la de movimiento reducido que verás más adelante. Si te encuentras usándolo para «arreglar» algo, casi siempre el problema real es un selector demasiado pesado en otra parte.

Herencia: lo que pasa de padres a hijos

Algunas propiedades se transmiten de un elemento a todo lo que tiene dentro. Si pones font-family y color en el body, todos los párrafos, listas y títulos los usan sin que escribas una regla para cada uno. A eso se le llama herencia.

Se heredan (sobre todo, las de texto)No se heredan (sobre todo, las de caja)
color, font-family, font-size, font-weight, font-style, line-height, text-align, letter-spacing, list-style, visibility, cursormargin, padding, border, background, width, height, display, position

Tiene lógica: si el borde se heredara, cada párrafo dentro de una tarjeta con borde tendría su propio borde. Ya viste la respuesta a la pregunta del taller anterior: el precio del ratón se veía gris porque heredaba el color de su li.

Un valor heredado siempre pierde contra cualquier regla que elija al elemento directamente, aunque sea la regla más débil y aunque venga de la hoja del navegador. La herencia solo actúa cuando nadie le ha dicho nada al elemento. Por eso un enlace dentro de un párrafo rojo sigue siendo azul: el navegador trae una regla propia para los enlaces.

Colores, unidades y variables

Casi todas las declaraciones de CSS llevan un color o una medida. Elegir bien cómo escribirlos hace que tu página se lea mejor, se adapte a cada persona y sea fácil de cambiar después.

Cinco formas de escribir el mismo color

Todas estas declaraciones pintan exactamente el mismo rojo anaranjado:

Hexadecimal es un sistema de numeración con 16 cifras: del 0 al 9 y de la a a la f. Lo verás a fondo en la Estación 18; por ahora basta con saber que 00 es «nada» y ff es «todo». #000000 es negro, #ffffff es blanco y #ff0000 es rojo puro. HSL se parece más a cómo hablamos de los colores. El tono (hue) es un ángulo en una rueda de colores: 0 es rojo, 120 verde y 240 azul. La saturación va de 0% (gris) a 100% (color puro). La luminosidad va de 0% (negro) a 100% (blanco). Es muy práctico para crear variantes: con el mismo tono, subes o bajas la luminosidad y obtienes una versión clara y otra oscura.

OKLCH es la notación más moderna, y funciona en todos los navegadores principales desde 2023. Su ventaja es que su luminosidad corresponde a lo que percibe el ojo humano. En HSL, hsl(60 100% 50%) (amarillo) y hsl(240 100% 50%) (azul) dicen tener la misma luminosidad, 50%, pero el amarillo se ve muchísimo más claro. En hexadecimal se añade una cuarta pareja: #ff634780. Dos palabras clave más: transparent (totalmente transparente) y currentColor, que significa «el mismo valor que tenga color», muy útil para bordes e iconos que siguen el color del texto.

Contraste: que se pueda leer

Un texto gris claro sobre fondo blanco puede verse elegante en tu monitor y ser ilegible para una persona mayor, para alguien con baja visión o para cualquiera que mire el teléfono bajo el sol. El contraste es la diferencia de luminosidad entre el texto y su fondo, y se mide con un número llamado relación de contraste: de 1:1 (ninguna diferencia) a 21:1 (negro sobre blanco).

Las pautas de accesibilidad web (WCAG 2.2, nivel AA, el que toman como referencia muchas leyes y normas) piden como mínimo:

  • 4.5:1 para el texto normal.
  • 3:1 para el texto grande (a partir de unos 24 píxeles, o unos 18.5 píxeles en negrita) y para las partes de la interfaz que hay que distinguir, como el borde de un campo o un icono que es un botón.

Un par de datos para calibrar el ojo: #767676 sobre blanco da 4.54:1, justo por encima del mínimo; tomato sobre blanco da 2.9:1 y no sirve para texto. Para medir, abre DevTools, haz clic en el cuadrito de color de una declaración y el selector de color te muestra la relación de contraste. También puedes usar el comprobador de contraste de WebAIM.

Alrededor de una de cada seis personas en el mundo vive con alguna discapacidad, y la visión baja es de las más frecuentes; con la edad, casi todo el mundo pierde sensibilidad al contraste. Un buen contraste no es un detalle estético: decide si alguien puede usar tu aplicación. En la Estación 17 verás accesibilidad y color con más detalle.

Variables CSS: ponle nombre a tus valores

Imagina que el verde de tu marca aparece en 30 reglas y el equipo decide cambiarlo. Buscar y reemplazar 30 veces es lento y fácil de hacer mal. En la Estación 7 aprendiste a guardar un valor con un nombre. CSS tiene su propia versión: las propiedades personalizadas, que casi todo el mundo llama variables CSS (en inglés, custom properties).

:root {
  --color-marca: #2a9d8f;
  --color-texto: #1d1d1f;
  --radio: 10px;
  --espacio: 1rem;
}

.boton {
  background: var(--color-marca);
  border-radius: var(--radio);
  padding: calc(var(--espacio) / 2) var(--espacio);
}
  • El nombre empieza con dos guiones (--color-marca) y distingue mayúsculas de minúsculas.
  • Se leen con var(--nombre). Puedes dar un valor de respaldo por si la variable no existe: var(--color-marca, teal).
  • :root es una pseudoclase que elige al elemento <html>. Las variables se heredan, así que si las defines ahí, toda la página puede usarlas.
  • Siguen la cascada: puedes redefinir una variable dentro de un componente o de una media query, y solo cambia allí.
  • calc() hace cuentas con valores de CSS, incluso mezclando unidades: calc(100% - 2rem).

La tarjeta oscura no repite ninguna regla: solo redefine dos variables, y el borde, el título y el botón las usan. Fíjate también en que .tarjeta lee --color-texto en su propio color. Si esa lectura estuviera solo en el body, la tarjeta oscura heredaría el color ya calculado del body y su texto seguiría oscuro. Una variable redefinida solo afecta a las declaraciones que la leen con var() en ese elemento o en sus descendientes.

A diferencia de las variables de JavaScript, las de CSS no se «ejecutan» una vez: el navegador recalcula todo lo que las usa cada vez que cambian. Por eso son perfectas para temas claro y oscuro, y porque JavaScript puede cambiarlas en vivo, algo que harás en la Estación 15. Existen también herramientas como Sass, que tienen variables propias con $; esas se convierten en valores fijos antes de llegar al navegador.

El modelo de caja y display

Le pones width: 300px a una tarjeta y DevTools dice que mide 350. Entre dos párrafos aparece un espacio que no recuerdas haber puesto. Un <span> ignora el alto que le das. Las tres sorpresas tienen la misma explicación: el modelo de caja.

Para el navegador, cada elemento es un rectángulo formado por cuatro capas, de dentro hacia fuera: el contenido, el relleno (padding), el borde (border) y el margen (margin).

Es como un cuadro colgado en la pared. La pintura es el contenido; el paspartú blanco que la rodea es el relleno; el marco de madera es el borde; y la distancia hasta el cuadro de al lado es el margen. La analogía falla en un punto: cuando dos cajas están una encima de otra, sus márgenes verticales pueden fundirse en uno solo. Dos cuadros en una pared nunca hacen eso.

Escribir padding, border y margin

padding y margin aceptan de uno a cuatro valores. Cuando hay cuatro, van en el sentido de las agujas del reloj empezando por arriba:

El borde necesita tres datos: grosor, estilo y color. border: 2px solid #264653;. Los estilos más usados son solid, dashed (rayas) y dotted (puntos). Para redondear las esquinas se usa border-radius: border-radius: 8px suaviza, y border-radius: 50% convierte un cuadrado en círculo.

border: 2px red; no dibuja nada. Falta el estilo, y el estilo por defecto de un borde es none. Escribe siempre los tres datos: border: 2px solid red;.

Márgenes: centrar y colapsar

Un elemento de bloque con un ancho definido se centra en horizontal con márgenes automáticos a los lados. Es el patrón del «contenedor» que verás en casi todas las páginas:

.contenedor {
  max-width: 60rem;       /* nunca más ancho que 960px */
  margin-inline: auto;    /* igual que margin-left: auto y margin-right: auto */
  padding-inline: 1rem;   /* aire a los lados en pantallas estrechas */
}

Fíjate en max-width en lugar de width: en un monitor grande mide 60rem, y en un teléfono se estrecha solo. Existen también min-width, min-height y max-height.

La otra sorpresa de los márgenes es el colapso de márgenes (margin collapsing). Cuando dos elementos de bloque están uno encima del otro, sus márgenes verticales no se suman: se funden y queda solo el mayor.

h2 { margin-bottom: 30px; }
p  { margin-top: 20px; }
/* Entre un h2 y el p siguiente quedan 30px, no 50px. */

El colapso solo ocurre con márgenes verticales y en el flujo normal de bloques. No ocurre entre elementos de un contenedor flex o grid, ni con márgenes horizontales. Otro caso confuso: el margen superior del primer hijo puede «salirse» de su padre si el padre no tiene borde ni relleno arriba. Si ves un hueco inexplicable encima de una sección, busca un margen de su primer hijo en DevTools.

La propiedad display decide cómo se coloca una caja respecto a las demás. Cada etiqueta HTML trae un valor por defecto: div, p, h1, ul o section son de bloque; span, a, strong o img son en línea. Con CSS lo puedes cambiar:

Cuando el contenido no cabe: overflow

Si le fijas una altura a una caja y el texto no cabe, el texto se sale por abajo y se monta sobre lo que viene después. La propiedad overflow decide qué hacer con lo que sobra: visible (se sale, es el valor por defecto), hidden (se corta), auto (aparece una barra de desplazamiento solo si hace falta) o scroll (barra siempre).

Evita fijar la altura de las cajas con texto. El texto cambia: una traducción al alemán es más larga, una persona agranda la letra, un nombre de producto no cabe. Usa min-height si necesitas una altura mínima y deja que la caja crezca. En DevTools, la pestaña Calculado muestra el dibujo del modelo de caja del elemento seleccionado, con sus cuatro medidas. Al pasar el ratón por encima, el navegador pinta cada capa sobre la página.

Flexbox: filas y columnas flexibles

Poner un logo a la izquierda y un menú a la derecha. Centrar un texto en vertical dentro de una caja. Repartir tres botones con el mismo espacio entre ellos. Durante años, estas tareas necesitaban trucos incómodos con tablas o con la propiedad float. Flexbox (Flexible Box Layout) se creó para resolverlas: coloca elementos en una fila o en una columna y reparte el espacio entre ellos.

Contenedor y elementos flexibles

Flexbox se activa en el padre con display: flex. Ese padre pasa a ser el contenedor flex, y sus hijos directos, los elementos flex (flex items). Las propiedades se reparten así: unas se escriben en el contenedor y deciden cómo se colocan todos; otras se escriben en un elemento y solo le afectan a él.

Flexbox solo afecta a los hijos directos del contenedor. Si pones display: flex en un <ul>, los <li> se ponen en fila, pero los enlaces que hay dentro de cada <li> no se enteran. Otro clásico: poner justify-content en los elementos en lugar de en el contenedor. No hace nada.

Las propiedades del contenedor

Este es tu laboratorio. Cambia los valores de justify-content, align-items y flex-direction uno por uno y ejecuta cada vez. Antes de cada cambio, predice dónde van a quedar A, B y C.

Algunas combinaciones para probar: justify-content: space-evenly; align-items: center y después flex-end (fíjate en que B es más alto); justify-content: center con align-items: center, la receta clásica para centrar en los dos ejes; y flex-direction: column con align-items: flex-start.

Las propiedades de cada elemento

Cada elemento flex puede decidir cuánto crece, cuánto encoge y de qué tamaño parte:

  • flex-grow: qué parte del espacio sobrante se lleva. Con 0 (el valor por defecto) no crece; si uno tiene 2 y otro 1, el primero se lleva el doble del sobrante.
  • flex-shrink: cuánto encoge si falta espacio. Por defecto 1: todos encogen por igual. Con 0 no encoge.
  • flex-basis: el tamaño de partida antes de repartir. Por defecto auto, que usa su width o el tamaño de su contenido.
  • flex es el atajo que las junta, en ese orden: flex: 1 1 200px. Tres formas muy usadas: flex: 1 (todos iguales, se reparten el espacio a partes iguales), flex: 0 0 250px (mide 250 y no se mueve de ahí) y flex: 1 1 250px (parte de 250 y crece o encoge según haga falta).
  • align-self: cambia la alineación en el eje cruzado solo para ese elemento.
  • order: cambia su posición visual. Úsalo con cuidado: quien navega con teclado o con lector de pantalla sigue el orden del HTML, no el visual.

Modifica y observa: cambia 150px por 300px (ya no caben tres por fila y saltan a la siguiente línea, donde vuelven a crecer); cambia flex: 1 1 150px por flex: 0 0 150px (dejan de crecer); vuelve al original y añade .tarjeta:first-child { flex-grow: 3; }.

Recetas que vas a usar mil veces

/* 1. Centrar algo en los dos ejes */
.portada {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100svh;
}

/* 2. Barra de navegación: logo a la izquierda, lo demás a la derecha */
.barra { display: flex; align-items: center; gap: 1rem; }
.barra .logo { margin-right: auto; }   /* el margen automático se come el espacio libre */

/* 3. Tarjeta con el botón siempre abajo, aunque el texto sea corto */

.tarjeta .boton { margin-top: auto; }

Por defecto, un elemento flex no encoge por debajo del ancho de su contenido más largo, como una dirección web o una palabra larguísima. El resultado: la fila se sale del contenedor. La solución es poner min-width: 0 en ese elemento (o overflow-wrap: anywhere en el texto). Si una fila flex «se rompe» en el teléfono, sospecha de esto primero.

En DevTools, los contenedores flex llevan una pequeña etiqueta «flex» junto a su etiqueta en el panel Elementos. Al pulsarla, el navegador dibuja sobre la página los elementos, los huecos y el espacio libre. Firefox muestra además por qué un elemento creció o encogió.

Grid: diseños en dos dimensiones

Flexbox piensa en una sola línea: una fila o una columna. Pero la estructura de una página (cabecera arriba, menú lateral, contenido y pie) o una galería de fotos alineadas en filas y columnas son problemas en dos dimensiones. Para eso existe CSS Grid: divides el contenedor en una cuadrícula y colocas cada elemento en sus celdas.

El vocabulario de la cuadrícula

  • El contenedor grid es el elemento con display: grid. Sus hijos directos son los elementos grid.
  • Las líneas separan columnas y filas. Se numeran desde 1; la última también se puede llamar -1.
  • Una pista (track) es una columna o una fila entera.
  • Una celda es la intersección de una fila y una columna. Un área es un rectángulo de varias celdas.
  • El hueco (gap) es el espacio entre pistas. No hay hueco en los bordes exteriores.

Definir columnas y filas

.galeria {
  display: grid;
  grid-template-columns: 200px 1fr 1fr;  /* tres columnas */
  gap: 16px;
}

La unidad fr (de fraction) es exclusiva de grid: representa una parte del espacio que queda libre. En el ejemplo, la primera columna mide 200 píxeles, y lo que sobra, descontados los huecos, se divide en dos partes iguales. 1fr 2fr haría la segunda columna el doble de ancha que la primera.

Tres herramientas más para las columnas:

  • repeat(4, 1fr) es lo mismo que escribir 1fr 1fr 1fr 1fr.
  • minmax(150px, 1fr) crea una pista que nunca baja de 150 píxeles y que crece hasta su parte del espacio libre.
  • grid-template-rows define las filas igual que las columnas. Si hay más elementos que celdas, grid crea filas nuevas solo; su alto se controla con grid-auto-rows, por ejemplo grid-auto-rows: minmax(120px, auto).

Con porcentajes, grid-template-columns: 33% 33% 33% más un gap suma más del 100% y la cuadrícula se sale del contenedor. 1fr 1fr 1fr reparte solo lo que queda después de descontar los huecos. Usa fr.

Colocar elementos

Sin más instrucciones, grid coloca a los hijos en orden, llenando cada fila de izquierda a derecha. Esa colocación automática basta muchas veces. Cuando quieres que un elemento ocupe más espacio, le dices entre qué líneas va:

.destacada { grid-column: 1 / 3; }    /* de la línea 1 a la 3: dos columnas */
.alta      { grid-row: span 2; }      /* ocupa dos filas desde donde caiga */
.banner    { grid-column: 1 / -1; }   /* de la primera a la última línea: todo el ancho */

Predice cómo quedará esta galería antes de ejecutar: ¿qué ocupará la foto 1?, ¿dónde caerá la foto 2?, ¿qué pasa con la 4?

La foto 1 ocupa dos columnas, así que la 2 cabe en la tercera columna de la primera fila. La 4 ocupa dos filas. Modifica: cambia .uno a grid-column: 1 / -1; después, a .cuatro añádele grid-column: 2 / 4. Observa cómo los demás elementos buscan hueco solos. (place-items: center centra el número en su caja: es el atajo de grid para align-items y justify-items a la vez.)

Áreas con nombre: dibuja tu diseño

Para la estructura de una página, grid tiene una forma muy visual: le pones nombre a cada zona y «dibujas» la cuadrícula con textos.

.pagina {
  display: grid;
  grid-template-columns: 200px 1fr;
  grid-template-areas:
    "cabecera cabecera"
    "lateral  contenido"
    "pie      pie";
  gap: 1rem;
}

.cabecera  { grid-area: cabecera; }
.lateral   { grid-area: lateral; }
.contenido { grid-area: contenido; }
.pie       { grid-area: pie; }

Cada texto entre comillas es una fila, y cada palabra, una columna. Si un nombre se repite, esa zona ocupa varias celdas. Las zonas tienen que ser rectángulos, y un punto (.) deja una celda vacía. Los espacios de más dentro de las comillas no importan: sirven para alinear el dibujo.

Pista para la misión

La fila del medio debe decir "contenido lateral", y las columnas deben ir al revés: 1fr 150px.

Fíjate en que el selector .pagina > * usa el combinador de hijo y el universal: da relleno y esquinas redondeadas a todos los hijos directos de la página.

Cuadrículas que se adaptan solas

Esta línea es una de las más útiles de todo CSS:

.productos {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(180px, 1fr));
  gap: 1rem;
}

Se lee así: «crea tantas columnas como quepan, cada una de al menos 180 píxeles, y reparte el espacio que sobre entre ellas». En un teléfono cabe una columna; en una tableta, tres o cuatro; en un monitor ancho, seis o más. Sin escribir ni una media query. La alternativa auto-fill se comporta igual cuando hay muchos elementos; la diferencia aparece cuando hay pocos: auto-fill deja pistas vacías al final y auto-fit estira los elementos para llenar la fila.

Posición, capas y movimiento

Una etiqueta de «oferta» en la esquina de una tarjeta. Una cabecera que se queda pegada arriba al hacer scroll. Una ventana emergente encima de todo. Una moneda que gira en la interfaz de tu juego. Nada de eso encaja en el orden normal de la página, y para eso están position, z-index, las transformaciones, las transiciones y las animaciones.

El flujo normal y cómo salir de él

Sin instrucciones especiales, el navegador coloca las cajas en el flujo normal: los elementos de bloque, uno debajo de otro; los elementos en línea, uno junto a otro como palabras. La propiedad position permite desplazar un elemento o sacarlo de ese flujo. Después, las propiedades top, right, bottom y left dicen a qué distancia colocarlo.

z-index: quién queda encima

Cuando dos elementos se superponen, por defecto queda encima el que aparece después en el HTML. z-index cambia ese orden: un número mayor queda más cerca de ti. Solo funciona en elementos con position distinto de static y en los hijos de un contenedor flex o grid.

Hay una trampa: los contextos de apilamiento. Algunos elementos crean un grupo de capas propio; por ejemplo, uno posicionado con un z-index distinto de auto, o uno con opacity menor que 1 o con transform. Sus hijos solo pueden ordenarse dentro de ese grupo.

Piensa en hojas de papel dentro de carpetas apiladas sobre una mesa. Puedes reordenar las hojas dentro de una carpeta como quieras, pero ninguna hoja puede quedar por encima de la carpeta de arriba, por mucho que le escribas un 9999. Cada carpeta es un contexto de apilamiento. Si un z-index: 9999 «no funciona», revisa dos cosas: que el elemento tenga position y en qué carpeta está.

Transformaciones

transform mueve, gira o escala un elemento de forma visual, sin afectar al flujo: los demás elementos no se enteran y no se recolocan.

.a { transform: translate(20px, -10px); } /* desplaza 20px a la derecha y 10px hacia arriba */
.b { transform: rotate(15deg); }          /* gira 15 grados */
.c { transform: scale(1.2); }             /* agranda un 20% */
.d { transform: translateY(-4px) rotate(-2deg); } /* se pueden combinar */

Transiciones: cambios suaves

Cuando pasas el ratón por un botón y cambia de color, el cambio es instantáneo. Una transición hace que ese cambio dure un tiempo:

.boton {
  background-color: #2a9d8f;
  transition: background-color 200ms ease, transform 200ms ease;
}

.boton:hover {
  background-color: #1f7a6f;
  transform: translateY(-2px);
}

Cada transición dice qué propiedad anima, cuánto dura (200ms o 0.2s) y con qué curva de velocidad: ease (el valor por defecto: arranca rápido y frena al final), linear, ease-in, ease-out o ease-in-out. Opcionalmente, un retraso.

Escribe la transición en el estado normal, no en el :hover. Así se anima al entrar y al salir. Solo se animan las propiedades que tienen valores intermedios (colores, medidas, opacity, transform); display no se puede animar así. Y para que las animaciones vayan fluidas, anima sobre todo transform y opacity: el navegador las mueve sin recalcular la posición de toda la página.

Animaciones con @keyframes

Una transición va de un estado a otro cuando algo cambia. Una animación puede tener muchos pasos, repetirse y empezar sola. Primero defines los fotogramas clave con @keyframes y después se la asignas a un elemento con animation:

@keyframes latido {
  0%   { transform: scale(1); }
  50%  { transform: scale(1.15); }
  100% { transform: scale(1); }
}

.corazon {
  animation: latido 1s ease-in-out infinite;
}

animation junta varias propiedades: el nombre, la duración, la curva, el número de repeticiones (infinite o un número), y opcionalmente el retraso, la dirección (alternate va y vuelve) y forwards, que deja el elemento como quedó en el último fotograma. from y to son sinónimos de 0% y 100%.

Respeta a quien prefiere menos movimiento

Para algunas personas, sobre todo con trastornos vestibulares (del equilibrio), las animaciones grandes o constantes provocan mareo, náuseas o dolor de cabeza. Los sistemas operativos tienen un ajuste de accesibilidad para pedir menos movimiento, con nombres como «Reducir movimiento» o «Quitar animaciones». CSS puede leerlo con la media query prefers-reduced-motion. La estrategia más segura es añadir el movimiento solo si la persona no ha pedido lo contrario:

@media (prefers-reduced-motion: no-preference) {
  .corazon {
    animation: latido 1s ease-in-out infinite;
  }
}

/* O al revés: anula el movimiento para quien lo pidió */
@media (prefers-reduced-motion: reduce) {
  .boton {
    transition: none;
  }
}

Modifica: cambia la duración de la transición a 1s para verla a cámara lenta; cambia alternate por nada y observa el salto al reiniciar cada vuelta; crea un @keyframes girar que vaya de rotate(0deg) a rotate(360deg) y úsalo en la moneda con linear. Si en tu sistema tienes activado «Reducir movimiento», la moneda no se mueve: es lo que debe pasar. Puedes simularlo en Chrome desde DevTools, en el panel Rendering (en español, Renderización), con la opción que emula prefers-reduced-motion.

Diseño adaptable, tipografía y orden

Tu página se va a ver en un teléfono de 360 píxeles de ancho, en una tableta, en un portátil y en un monitor de 2560. No vas a escribir una página para cada uno. El diseño adaptable (en inglés, responsive design; también se dice «diseño responsivo») consiste en escribir un solo HTML y un CSS que se reorganiza según el espacio disponible.

La base: el viewport y no romper lo que ya es fluido

Sin la etiqueta <meta name="viewport" content="width=device-width, initial-scale=1"> en el <head>, los navegadores móviles fingen tener una pantalla de unos 980 píxeles y encogen la página: todo se ve diminuto. Con ella, el ancho de la página es el ancho real del dispositivo. Ponla siempre.

La buena noticia es que el HTML, sin CSS, ya es adaptable: el texto se reparte en las líneas que caben. Somos nosotros quienes lo rompemos con anchos fijos. Por eso las primeras reglas del diseño adaptable son de sentido común: usa max-width en lugar de width, porcentajes y fr en lugar de píxeles fijos para los anchos, y flex-wrap o auto-fit para que las cosas bajen de línea cuando no caben.

Mobile first y media queries

Una media query es un bloque de CSS que solo se aplica si se cumple una condición sobre el dispositivo, normalmente el ancho de la ventana:

@media (min-width: 700px) {
  /* Estas reglas solo se aplican si la ventana mide 700px o más */
  .tarjetas { grid-template-columns: repeat(2, 1fr); }
}

La estrategia recomendada se llama mobile first («primero el móvil»). Escribes los estilos base para la pantalla más pequeña, que casi siempre es lo más sencillo (todo en una columna), y después añades media queries con min-width para ir agregando columnas y detalles a medida que hay espacio.

/* Base: teléfonos. Todo en una columna. */
.tarjetas {
  display: grid;
  gap: 1rem;
}

/* Desde 700px: dos columnas */
@media (min-width: 700px) {
  .tarjetas { grid-template-columns: repeat(2, 1fr); }
}

/* Desde 1100px: tres columnas */
@media (min-width: 1100px) {
  .tarjetas { grid-template-columns: repeat(3, 1fr); }
}

¿Por qué empezar por el móvil? Porque es más fácil añadir que quitar: la versión de una columna necesita pocas reglas, y las pantallas grandes suman cosas encima. Además te obliga a decidir qué es lo esencial de tu página. Y como hoy la mayoría de las visitas a la web llegan desde teléfonos, es la versión que más gente verá.

Las media queries no suman especificidad: una regla dentro de @media pesa lo mismo que fuera. Por eso, en mobile first, las media queries van después de los estilos base y ordenadas de menor a mayor min-width. Si pusieras la de 1100 antes que la de 700, en una ventana ancha ganaría la de 700 por aparecer después.

Los números de corte (en inglés, breakpoints) no tienen que coincidir con modelos concretos de teléfono. Busca el ancho en el que tu diseño empieza a verse mal y pon el corte ahí. Muchos proyectos empiezan con valores cercanos a 600, 900 y 1200 píxeles y los ajustan después.

En documentación reciente verás la sintaxis de rango, más fácil de leer: @media (width >= 700px) equivale a @media (min-width: 700px). Funciona en todos los navegadores principales desde 2023. Las dos formas son correctas.

Las media queries no solo miran el ancho. Otras muy útiles: (prefers-color-scheme: dark) si la persona usa el tema oscuro del sistema, (prefers-reduced-motion: reduce), que ya conoces, (hover: hover) si el dispositivo tiene un puntero que puede pasar por encima de las cosas, y print para cuando alguien imprime la página.

La vista previa de los talleres es una ventana pequeña, y las media queries de dentro miden su ancho, no el de tu pantalla. El JavaScript de este taller te dice cuánto mide. Ejecútalo, lee el número y predice cuántas columnas vas a ver.

Ahora juega con los cortes para ver cada versión sin cambiar el tamaño de nada. Cambia 900px por un número menor que el ancho que te imprimió (por ejemplo, 400px): deberías ver cuatro columnas. Después pon 2000px en las dos media queries: verás la versión de teléfono, con una columna y el título pequeño. En tu propio proyecto, DevTools tiene un modo dispositivo (Ctrl + Shift + M, o Cmd + Shift + M en Mac, con DevTools abierto) para elegir el ancho de la ventana. Aun así, prueba siempre en un teléfono de verdad: el tacto y el tamaño real no se simulan.

Tamaños fluidos con clamp()

Un título de 48 píxeles queda bien en un monitor y enorme en un teléfono. En lugar de cambiarlo en cada media query, puedes pedirle que crezca con la ventana, pero dentro de unos límites. Eso hace clamp(mínimo, preferido, máximo):

h1 {
  font-size: clamp(1.75rem, 1rem + 3vw, 3rem);
  /* nunca menos de 1.75rem (28px), nunca más de 3rem (48px),
     y en medio, crece con el ancho de la ventana */
}

.contenedor {
  width: min(100% - 2rem, 60rem);  /* el menor de los dos valores */
  margin-inline: auto;
}

En el valor preferido, mezcla rem con vw (1rem + 3vw), no uses solo vw. Un tamaño hecho solo de vw no crece cuando la persona hace zoom o sube el tamaño de letra de su navegador, y las pautas de accesibilidad piden que el texto se pueda ampliar hasta el doble.

Imágenes fluidas

Una foto de 1600 píxeles de ancho, sin CSS, se sale de la pantalla de un teléfono. Esta regla está en casi todos los proyectos:

img {
  max-width: 100%;   /* nunca más ancha que su contenedor */
  height: auto;      /* el alto se ajusta para no deformarla */
  display: block;    /* quita el pequeño hueco que deja debajo por ser «en línea» */
}

.miniatura {
  width: 100%;
  aspect-ratio: 16 / 9;  /* proporción fija, sea cual sea la foto */
  object-fit: cover;     /* recorta la foto para llenar la caja sin deformarla */
}

object-fit: cover es ideal para tarjetas y galerías donde las fotos tienen proporciones distintas. Para mandar archivos más pequeños a los teléfonos existen los atributos HTML srcset y sizes, y el elemento <picture>; eso es HTML y rendimiento, y lo retomarás en la Estación 17.

Las media queries preguntan por el ancho de la ventana. A veces lo que importa es el ancho del hueco donde está un componente: la misma tarjeta puede estar en una columna estrecha o en una ancha. Para eso existen las consultas de contenedor (@container), disponibles en todos los navegadores principales desde 2023. Cuando domines las media queries, son el siguiente paso natural.

Tipografía web

La mayor parte de una página es texto, así que la tipografía decide si se lee con gusto o con esfuerzo. Lo primero es la familia de letra, con font-family. Se escribe una lista de opciones: si la primera no está disponible, el navegador prueba la siguiente. Termina siempre con una familia genérica: serif (con remates, como Georgia), sans-serif (sin remates), monospace (todas las letras igual de anchas) o system-ui (la letra del sistema operativo).

body {
  font-family: system-ui, -apple-system, "Segoe UI", Roboto, sans-serif;
}
h1, h2 {
  font-family: Georgia, "Times New Roman", serif;  /* los nombres con espacios, entre comillas */
}

Para usar una fuente que no viene en las computadoras, lo más común es Google Fonts (fonts.google.com), un catálogo gratuito de más de mil familias. Eliges una, marcas los grosores que necesitas y el sitio te da unas líneas para pegar en el <head>, parecidas a estas:

<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@400;700&display=swap">
body {
  font-family: "Inter", system-ui, sans-serif;
}

Las dos primeras líneas adelantan la conexión con los servidores de Google para ganar tiempo. En la tercera, wght@400;700 pide solo los grosores normal y negrita (cada grosor es un archivo más que descargar, así que pide solo los que uses) y display=swap hace que el texto se muestre enseguida con una fuente de respaldo y se cambie a la definitiva cuando termine de llegar.

Cada visita que carga una fuente desde Google conecta con servidores de Google, y eso tiene implicaciones de privacidad que algunas normativas miran con lupa. Por eso muchos equipos descargan los archivos de la fuente (formato .woff2) y los sirven desde su propio sitio con la regla @font-face:

@font-face {
  font-family: "Inter";
  src: url("../fuentes/inter.woff2") format("woff2");
  font-weight: 400;
  font-display: swap;
}

Después de la familia, cuatro decisiones hacen casi toda la diferencia:

  • Tamaño: para texto corrido, al menos 1rem (16 píxeles). Los títulos, en una escala clara por encima.
  • Interlineado (line-height): alrededor de 1.5 para párrafos y entre 1.1 y 1.3 para títulos. Escríbelo sin unidad: así cada elemento lo multiplica por su propio tamaño de letra. Con 1.5em, los hijos heredarían los píxeles ya calculados del padre, aunque su letra sea más grande.
  • Largo de línea: las líneas de entre 45 y 75 caracteres se leen mejor. max-width: 65ch en los párrafos lo consigue.
  • Grosor (font-weight): 400 es normal y 700 es negrita. Solo funcionan los grosores que cargaste.

Este texto es difícil de leer a propósito. Tu misión: arreglarlo solo con CSS.

Pista para la misión

Hay que cambiar tres valores de p (tamaño, interlineado y color) y añadir uno (max-width en ch). Si la vista previa es estrecha, las líneas ya son cortas por sí solas; añade el límite igualmente, porque en una pantalla ancha sí hará falta.

Tema claro y oscuro con variables

Las variables CSS y las media queries se combinan muy bien. Si toda tu página usa variables para los colores, el tema oscuro es redefinir unas pocas:

:root {
  --fondo: #ffffff;
  --texto: #1d1d1f;
  --marca: #2a9d8f;
}

@media (prefers-color-scheme: dark) {
  :root {
    --fondo: #121417;
    --texto: #e8e8ea;
    --marca: #5cc8b8;
  }
}

body {
  background: var(--fondo);
  color: var(--texto);
}

Así funciona este mismo curso: el botón de tema de la cabecera y tu preferencia del sistema cambian unas cuantas variables, y todo lo demás las sigue.

Buenas prácticas y organización

Un archivo de CSS crece deprisa. Estas costumbres lo mantienen manejable:

  • Un orden fijo en el archivo: primero las variables, después un pequeño reinicio (box-sizing, márgenes del body, imágenes fluidas), luego los estilos base de las etiquetas, la estructura de la página, los componentes y, al final de cada bloque o del archivo, las media queries de menor a mayor. Separa las secciones con comentarios.
  • Clases para dar estilo y especificidad baja. Evita los ids en los selectores, las cadenas largas como .pagina .contenido .lista li a y el !important. Si todas tus reglas pesan poco, cambiar algo nunca es una guerra.
  • Nombres que describen qué es, no cómo se ve. Muchos equipos usan la convención BEM (bloque, elemento, modificador): .tarjeta, .tarjeta__titulo, .tarjeta--destacada.
  • No te repitas: colores, espacios y radios, en variables.
  • Anidamiento con moderación: el CSS actual permite escribir una regla dentro de otra (.tarjeta { & h2 { … } }), y funciona en los navegadores principales desde finales de 2023. Es cómodo, pero anidar muchos niveles crea selectores largos y pesados.
  • Herramientas: Prettier da formato a tu CSS al guardar y Stylelint avisa de errores; los verás en la Estación 25. Frameworks como Tailwind CSS o Bootstrap aceleran el trabajo, pero están hechos de CSS: aprende primero la base y los entenderás de verdad.

Pon en orden esta hoja de estilos mobile first. Piensa en qué necesita estar antes para que lo de después funcione y en qué debe ganar en caso de empate:

  1. :root { --marca: #2a9d8f; --espacio: 1rem; }
  2. *, *::before, *::after { box-sizing: border-box; }
  3. body { margin: 0; font-family: system-ui, sans-serif; line-height: 1.5; }
  4. .tarjetas { display: grid; gap: var(--espacio); }
  5. @media (min-width: 600px) { .tarjetas { grid-template-columns: repeat(2, 1fr); } }
  6. @media (min-width: 1000px) { .tarjetas { grid-template-columns: repeat(4, 1fr); } }

Las variables van primero para que todo lo demás pueda leerlas (aunque técnicamente funcionarían en cualquier lugar, es la convención). El reinicio y los estilos base van antes que los componentes. Y las media queries van al final, de menor a mayor, porque en mobile first cada una debe ganar a lo anterior en caso de empate.
