Lo que vas a lograr

Cada página que visitas, desde una tienda en línea hasta la ficha de un videojuego o el perfil de una red social, empieza siendo un archivo de texto con HTML. HTML le dice al navegador qué es cada cosa: esto es un título, esto un párrafo, esto un enlace, esto un campo para escribir tu correo. Si lo haces bien, tu página funciona en cualquier pantalla, la entienden los buscadores y la puede usar también una persona ciega o que navega solo con el teclado.

  • Explicar qué es HTML, qué es un lenguaje de marcado y en qué se diferencia de JavaScript.
  • Escribir el esqueleto completo de una página (doctype, html, head, body, meta y title) y abrirla en tu navegador.
  • Estructurar texto con encabezados en orden, párrafos, énfasis y listas.
  • Enlazar páginas con rutas absolutas y relativas sin perderte entre carpetas.
  • Insertar imágenes con un texto alternativo que de verdad sirva.
  • Organizar una página con elementos semánticos (header, nav, main, article…) y presentar datos en tablas.
  • Construir formularios accesibles con validación del navegador (required, pattern, min, max).
  • Revisar tu HTML con el validador del W3C, la pestaña Elementos de las DevTools y una lista básica de accesibilidad.

Necesitas saber crear carpetas y archivos, y moverte entre ellas con rutas como ../: lo viste en la Estación 5: Tu taller. También te ayudará recordar qué es una URL y qué hace el navegador cuando pide una página (Estación 3: Internet). De JavaScript solo usarás console.log y un par de funciones en algunos ejercicios; lo demás lo harás en HTML puro, aquí mismo, con vista previa.

Qué es HTML

Imagina que recibes este texto sin ningún formato:

Tarta de manzana Lista en 40 minutos Ingredientes 3 manzanas 200 g de harina Pasos Pela las manzanas

Tú adivinas que «Tarta de manzana» es el título y que «3 manzanas» es un ingrediente, porque ya has visto muchas recetas. La computadora no adivina: para ella todo es una fila de caracteres. Hace falta marcar cada trozo para decir qué es. Eso hace HTML: son las siglas en inglés de HyperText Markup Language, «lenguaje de marcado de hipertexto».

  • Un lenguaje de marcado es un sistema de marcas que se ponen alrededor del texto para indicar qué es cada parte: un título, un párrafo, una lista.
  • Hipertexto es texto con enlaces a otros textos. Es la idea que dio origen a la web: páginas que te llevan a otras páginas.

Piensa en una receta impresa que alguien marca con rotuladores: en verde el título, en amarillo los ingredientes, en azul los pasos. Las marcas no cambian las palabras; dicen qué papel cumple cada una. HTML hace lo mismo con etiquetas. La analogía tiene un límite: algunas marcas de HTML además hacen cosas, como un enlace que te lleva a otra página o un campo donde puedes escribir.

HTML no es un lenguaje de programación

En la Línea 2 aprendiste JavaScript, que es un lenguaje de programación: tiene variables, decisiones, bucles y funciones, y sirve para calcular y decidir. HTML no tiene nada de eso. No puede sumar dos números ni decidir si muestra un mensaje. Solo describe el contenido y su estructura. Por eso se dice que HTML es declarativo: declaras qué hay, y el navegador decide cómo mostrarlo.

En la web trabajan tres lenguajes juntos, cada uno con su tarea:

LenguajeResponde a…EjemploDónde lo aprendes
HTML¿Qué es cada cosa?«Esto es un encabezado y esto es un botón.»Esta estación
CSS¿Cómo se ve?«Los encabezados van en azul y el botón tiene esquinas redondeadas.»Estación 14
JavaScript¿Qué pasa cuando…?«Cuando pulses el botón, suma un producto al carrito.»Estación 15

Separar las tareas tiene una ventaja enorme: puedes cambiar todo el aspecto de una página sin tocar su HTML, y el contenido sigue teniendo sentido aunque el CSS no cargue.

Etiquetas, elementos y atributos

Una marca de HTML se llama etiqueta (en inglés, tag). Se escribe entre los signos < y >. Casi siempre van en pareja: una etiqueta de apertura como <p> y una etiqueta de cierre con barra, como </p>. Todo el conjunto, con lo que queda en medio, es un elemento.

Las etiquetas de apertura pueden llevar atributos: datos extra con la forma nombre="valor" que ajustan el elemento. Por ejemplo, un enlace necesita saber adónde lleva:

Algunas reglas que conviene saber desde ya:

  • Escribe las etiquetas en minúsculas. HTML no distingue mayúsculas (<P> funciona), pero todo el mundo usa minúsculas y así se lee mejor.
  • Pon los valores de los atributos entre comillas dobles: href="contacto.html". Sin comillas funciona a veces, y el día que el valor tenga un espacio, falla.
  • Separa los atributos con espacios: <img src="tarta.jpg" alt="Tarta de manzana">. El orden de los atributos no importa.
  • Hay elementos vacíos (en inglés, void elements) que no tienen contenido ni etiqueta de cierre, como <br> (salto de línea), <img> (imagen) o <input> (campo de formulario). Verás código que los escribe con barra final, <br />: es válido, pero el navegador ignora esa barra. Elige un estilo y sé constante.

Elementos dentro de elementos

Los elementos se pueden meter unos dentro de otros. A eso se le llama anidar. Un párrafo puede contener un texto importante, una lista contiene elementos de lista, y toda la página vive dentro de un elemento html. La regla de oro: lo último que abres es lo primero que cierras, como las cajas que se guardan unas dentro de otras.

Etiquetas cruzadas

<p>Hornea <strong>40 minutos</p></strong>

Bien anidadas

<p>Hornea <strong>40 minutos</strong></p>

Al elemento que contiene a otro se le llama padre, y al contenido, hijo. En el ejemplo bueno, p es el padre de strong. Esta forma de hablar en familia la usarás mucho en CSS y JavaScript.

El navegador perdona (y eso no siempre es bueno)

JavaScript se detiene con un error rojo si escribes algo mal. HTML no: el navegador intenta adivinar qué quisiste decir y sigue adelante. Es una decisión de diseño de la web, para que una página con errores se vea de todos modos. El problema es que adivina en silencio, y a veces adivina distinto de lo que esperabas.

En este taller hay un párrafo con una caja div dentro. Un párrafo no puede contener elementos de bloque (lo verás en la sección de texto), así que el navegador lo «arregla» a su manera. El JavaScript de la pestaña JS solo imprime cómo quedó el HTML después de que el navegador lo leyera; no hace falta que lo entiendas todavía.

El navegador cerró el párrafo antes de la caja, dejó «y fin del párrafo.» suelto, y al encontrar el </p> final sin pareja creó un párrafo vacío. Nada avisa del error. Por eso existen los validadores de HTML, que verás en la sección Revisa tu HTML.

Seguro que has oído «HTML5». Fue la gran revisión de HTML que se completó en 2014 y el nombre se quedó como etiqueta de marketing. Hoy HTML no tiene números de versión: es un estándar vivo (HTML Living Standard) que mantiene el grupo WHATWG, formado por los fabricantes de navegadores, y que el W3C respalda desde un acuerdo de 2019. Se le añaden cosas poco a poco y cada navegador las incorpora a su ritmo. Para saber si puedes usar algo nuevo, busca el elemento en MDN y mira la tabla «Compatibilidad con navegadores» o la etiqueta Baseline, que indica si ya funciona en todos los navegadores principales.

El esqueleto de una página

En los talleres escribes trozos sueltos de HTML y el curso añade el resto por ti. Un archivo de verdad, el que subirás a internet, necesita un esqueleto: unas pocas líneas fijas que le dicen al navegador qué tipo de documento es, en qué idioma está y cómo leer sus caracteres. Es siempre el mismo, así que en una semana lo escribirás de memoria.

<!doctype html>
<html lang="es">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Tarta de manzana · Recetas de Ana</title>
  </head>
  <body>
    <h1>Tarta de manzana</h1>
    <p>Lista en 40 minutos.</p>
  </body>
</html>

Línea por línea:

LíneaQué hace
<!doctype html>La declaración de tipo de documento. No es un elemento: avisa al navegador de que es HTML moderno. Sin ella, el navegador entra en modo peculiar (quirks mode), que imita errores de navegadores de los años noventa y hace que tu CSS se comporte raro.
<html lang="es">El elemento raíz: contiene todo lo demás. El atributo lang indica el idioma. Con él, un lector de pantalla elige la voz y la pronunciación correctas, y el navegador sabe cuándo ofrecerte traducir.
<head>La cabeza: información sobre la página que no se dibuja en la ventana.
<meta charset="utf-8">Dice que el texto usa la codificación UTF-8, la forma de convertir letras en bytes que incluye tildes, eñes, emojis y cualquier alfabeto. Va la primera dentro de head.
<meta name="viewport" …>Le pide al móvil que use el ancho real de la pantalla. Sin esta línea, los navegadores móviles dibujan la página como si la pantalla fuera mucho más ancha (a menudo unos 980 píxeles) y la encogen: todo sale diminuto.
<title>El título del documento. Aparece en la pestaña, en los marcadores, en los resultados de los buscadores y es lo primero que anuncia un lector de pantalla al abrir la página.
<body>El cuerpo: todo lo que se ve. Encabezados, textos, imágenes, formularios.

Tres confusiones muy comunes: <head> no es lo mismo que <header> (la cabecera visible de la página, que verás en la sección de semántica); <title> no es lo mismo que <h1> (el título visible dentro de la página); y el contenido visible nunca va dentro de head.

Si tu página muestra «EspaÃ±a» en lugar de «España», hay un desacuerdo de codificación: el archivo se guardó en UTF-8 pero el navegador lo leyó con otra codificación. Revisa dos cosas: que la línea <meta charset="utf-8"> esté al principio del head (debe aparecer dentro de los primeros 1024 bytes del archivo) y que tu editor guarde en UTF-8. VS Code lo muestra abajo a la derecha, en la barra de estado.

En internet verás plantillas con user-scalable=no o maximum-scale=1 dentro del viewport. Eso impide ampliar la página con los dedos, y deja fuera a quien ve poco. Las pautas de accesibilidad exigen que el texto se pueda ampliar al menos al doble. Usa solo width=device-width, initial-scale=1.

Hay más cosas que pueden ir en el head: una descripción para los buscadores (<meta name="description" content="…">), el enlace a tu hoja de estilos (<link rel="stylesheet" href="estilos.css">, en la Estación 14) o tus programas de JavaScript (<script src="app.js" defer></script>, en la Estación 15).

Ordena el esqueleto

Pon estas líneas en orden y dales la sangría correcta: cada elemento que está dentro de otro va un nivel más a la derecha. Recuerda que meta charset es siempre lo primero dentro de head.

  1. <!doctype html>
  2. <html lang="es">
  3. <head>
  4. <meta charset="utf-8">
  5. <title>Mis recetas</title>
  6. </head>
  7. <body>
  8. <h1>Mis recetas</h1>
  9. </body>
  10. </html>

La sangría (los espacios al principio de cada línea) no cambia nada para el navegador. Es para las personas: con un vistazo ves qué está dentro de qué. En los equipos se usa un formateador automático como Prettier, que viste en la Estación 5, para que todo el código tenga la misma sangría sin discutirlo.

Cómo lee el navegador tu archivo

Sigue la lectura paso a paso. El navegador lleva la cuenta de qué elementos tiene abiertos en cada momento, como una pila de cajas: cuando encuentra un cierre, cierra la caja de arriba. En esta traza, el panel «Consola» hace de pantalla: muestra el texto que va apareciendo en la ventana.

  </head>

Tu primer archivo de verdad

Ahora hazlo fuera del curso, en tu computadora, con el editor que instalaste en la Estación 5:

  1. Crea una carpeta llamada mi-web y ábrela en VS Code (menú Archivo › Abrir carpeta).

  2. Crea dentro un archivo llamado index.html. El nombre index es especial: cuando alguien visita una carpeta de un sitio web, el servidor le entrega el archivo index.html de esa carpeta.

  3. En el archivo vacío escribe un signo de exclamación, !, y elige la primera sugerencia de la lista. Es un atajo de Emmet, una herramienta que viene incluida en VS Code, y genera el esqueleto completo.

  4. Revisa lo que generó: pone lang="en" (inglés). Cámbialo a lang="es" y cambia el texto de <title>. Si quieres que Emmet ponga español siempre, puedes cambiar la variable lang en el ajuste emmet.variables de VS Code.

  5. Dentro de body escribe un h1 y un párrafo. Guarda con Ctrl + S (en Mac, Cmd + S).

  6. Abre el archivo en el navegador: haz doble clic sobre él en tu explorador de archivos o arrástralo a una ventana del navegador. En la barra de direcciones verás algo como file:///C:/Users/ana/mi-web/index.html: el navegador está leyendo un archivo de tu disco, no de internet.

  7. Cambia algo en el editor, guarda y recarga el navegador con F5 (o Cmd + R). Este ciclo, editar, guardar, recargar, es tu día a día con HTML. Hay extensiones de VS Code que recargan la página solas al guardar, pero no las necesitas para esta estación.

Practica el mismo ajuste aquí. Este esqueleto es el que genera Emmet. Cambia el idioma a español, pon un título que describa la página y añade un h1 dentro de body. Pulsa «Ejecutar» para comprobarlo.

Fíjate en que Emmet escribe <!DOCTYPE html> y UTF-8 en mayúsculas. Da igual: el doctype y el nombre de la codificación no distinguen mayúsculas de minúsculas. En este curso los escribimos en minúsculas.

Texto con estructura: encabezados, párrafos y listas

Casi todo lo que hay en una página es texto. Un texto largo sin estructura cansa y se abandona: nadie lee un muro de palabras. Con unos pocos elementos le das forma, y esa forma sirve a la vez para leer con los ojos, para escuchar con un lector de pantalla y para que un buscador entienda de qué trata la página.

Encabezados: el índice de tu página

HTML tiene seis niveles de encabezado (en inglés, heading): de <h1>, el más importante, a <h6>, el menos. Funcionan como el índice de un libro:

<h1>Recetas de Ana</h1>             <!-- el título del libro -->
  <h2>Postres</h2>                  <!-- un capítulo -->
    <h3>Tarta de manzana</h3>       <!-- una sección del capítulo -->
    <h3>Flan de huevo</h3>
  <h2>Platos salados</h2>
    <h3>Tortilla de patatas</h3>

La sangría del ejemplo es solo para que veas la jerarquía; en un archivo real los encabezados no van unos dentro de otros. Tres reglas:

  • Un solo h1 por página, que diga de qué trata, parecido al title. HTML permite varios, pero la recomendación general es uno.
  • No te saltes niveles al bajar: después de un h2 viene un h3, no un h4. Al subir sí puedes saltar: de un h4 puedes volver a un h2 cuando empieza un capítulo nuevo.
  • Elige el nivel por su lugar en el índice, nunca por su tamaño. Si un h2 te parece demasiado grande, se cambia con CSS. Usar h4 «porque se ve más pequeño» rompe el índice.

En la encuesta de 2024 de WebAIM a usuarios de lectores de pantalla, el 71,6 % dijo que, en una página larga, lo primero que hace para encontrar información es saltar de encabezado en encabezado. Y en el análisis de 2026 de WebAIM sobre el millón de páginas de inicio más visitadas, el 41,8 % se saltaba niveles de encabezado. Un índice roto deja a mucha gente a oscuras.

Encabezados elegidos por tamaño

<h3>Tarta de manzana</h3>
<h1>Ingredientes</h1>
<h5>Para 6 personas</h5>
<h1>Pasos</h1>

Encabezados elegidos por jerarquía

<h1>Tarta de manzana</h1>
<h2>Ingredientes</h2>
<p>Para 6 personas.</p>
<h2>Pasos</h2>

Fíjate en «Para 6 personas»: no es un título de nada, es un dato. Su lugar es un párrafo, aunque quieras que se vea pequeño.

Hasta 2025, los navegadores dibujaban más pequeño un h1 colocado dentro de ciertos elementos como section o article, por una idea antigua de la especificación que nunca llegó a funcionar en los lectores de pantalla. Esa regla se eliminó del estándar en 2025 y los navegadores la están retirando. Otra razón para elegir el nivel por jerarquía y dejar el tamaño a CSS.

Párrafos, saltos de línea y separadores

  • <p> es un párrafo: un bloque de texto con una idea. Es el elemento que más vas a escribir.
  • <br> es un salto de línea dentro de un mismo texto. Úsalo solo cuando el salto forma parte del contenido: las líneas de una dirección postal o los versos de un poema. Nunca lo uses para separar párrafos o para dejar espacio: eso se hace con <p> y con CSS.
  • <hr> es un cambio de tema entre párrafos, como los asteriscos que separan escenas en una novela. El navegador lo dibuja como una línea horizontal.

Importancia y énfasis

Hay dos parejas de elementos que se ven igual pero significan cosas distintas:

ElementoSignificaSe ve (por defecto)Ejemplo
<strong>Importancia, seriedad o urgenciaNegrita<strong>No abras el horno</strong> durante los primeros 20 minutos.
<em>Énfasis: la palabra que acentuarías al hablar, que puede cambiar el sentidoCursivaYo <em>no</em> dije eso.
<b>Llamar la atención sin añadir importancia: palabras clave, nombres de productoNegritaLleva <b>harina de fuerza</b>.
<i>Otra voz o registro: palabras en otro idioma, términos técnicos, pensamientosCursivaUna <i lang="fr">tarte tatin</i> es una tarta invertida.

La regla práctica: si solo quieres que se vea en negrita o cursiva, es trabajo de CSS; si el texto de verdad es importante o enfático, usa strong o em. Ten en cuenta que muchos lectores de pantalla no cambian la voz con estos elementos en su configuración por defecto, así que nunca confíes en la negrita sola para transmitir algo vital: dilo también con palabras.

Otros elementos de texto útiles, todos en línea:

  • <code> para fragmentos de código: <code>console.log</code>.
  • <mark> para resaltar, como un rotulador: los resultados de una búsqueda.
  • <small> para la letra pequeña: avisos legales, derechos de autor.
  • <sub> y <sup> para subíndices y superíndices: H2O, 20 m2.
  • <blockquote> para una cita larga en su propio bloque y <q> para una cita corta dentro de una frase (el navegador añade las comillas).

Elementos de bloque y elementos en línea

Ya habrás notado que un h1 o un p siempre empiezan en una línea nueva, mientras que strong se queda dentro de la frase. Por defecto, los elementos se muestran de dos maneras:

  • De bloque: empiezan en una línea nueva y ocupan todo el ancho disponible, como los párrafos de un libro. Ejemplos: h1…h6, p, ul, ol, li, blockquote, div.
  • En línea (en inglés, inline): fluyen dentro del texto, uno detrás de otro, como palabras. Ejemplos: a (los enlaces), strong, em, mark, code, img, span.

Hay dos elementos sin ningún significado, que existen para agrupar cuando nada más encaja: <div> (una caja genérica de bloque) y <span> (un trozo genérico en línea). Los usarás sobre todo para darles estilo con CSS. En este taller, el CSS dibuja un borde continuo alrededor de los elementos de bloque y uno punteado alrededor de los elementos en línea. Míralo antes de tocar nada:

Ahora investiga: agranda o achica mentalmente la ventana, o escribe una frase muy larga en el primer párrafo. Los bloques ocupan todo el ancho aunque su texto sea corto; los elementos en línea solo ocupan lo que mide su contenido. Si quieres cambiar cómo se muestra un elemento, eso se hace con la propiedad display de CSS, que verás en la Estación 14.

Un párrafo solo puede contener elementos en línea. Si metes un bloque dentro de <p> (otro párrafo, una lista, un div), el navegador cierra el párrafo antes, como viste en el taller «El navegador corrige en silencio». Al revés sí vale: los bloques contienen elementos en línea sin problema.

El estándar actual de HTML ya no habla de «bloque» y «en línea», sino de categorías de contenido: el «contenido de flujo» (casi todo) y el «contenido de frase» (el texto y los elementos que van dentro de él). Para empezar, la idea de bloque y en línea te sirve y es la que usa CSS.

Listas

Las listas están por todas partes: los ingredientes de una receta, los pasos de una instalación, el menú de un sitio. HTML tiene tres tipos:

  • <ul>, lista sin orden (unordered list): el orden no importa. Se dibuja con viñetas.
  • <ol>, lista ordenada (ordered list): el orden importa. Se numera sola.
  • <dl>, lista de descripciones: pares de término (<dt>) y descripción (<dd>), como un glosario.

Dentro de ul y ol, cada elemento va en un <li> (list item). Y solo li: nada de texto suelto ni párrafos directamente dentro de la lista. Para hacer una sublista, métela dentro de un li. Predice cómo se verá este código y después ejecútalo:

Caracteres especiales y entidades

¿Cómo escribes en una página el texto «usa <p> para los párrafos»? Si escribes <p> tal cual, el navegador cree que abres un párrafo. Para eso existen las entidades (en inglés, character references): códigos que empiezan con & y terminan con ; y que el navegador cambia por un carácter.

EscribesSe veCuándo la necesitas
&lt;<Siempre que quieras mostrar el signo «menor que».
&gt;>Para el signo «mayor que» (por simetría con &lt;).
&amp;&Para mostrar el propio signo &, sobre todo si le sigue texto que parece una entidad.
&quot;"Comillas dobles dentro del valor de un atributo que ya va entre comillas dobles.
&nbsp;(espacio)Un espacio de no separación: une dos palabras para que nunca queden en líneas distintas, como en 10&nbsp;km.

Enlaces y rutas

Sin enlaces no hay web: habría páginas sueltas, como folletos sin dirección. Un enlace (en inglés, link o hyperlink) se crea con el elemento <a>, de anchor, «ancla», y su atributo href, que indica el destino:

<a href="https://developer.mozilla.org/es/">Documentación de MDN en español</a>

El texto entre las etiquetas es lo que la persona ve y pulsa. El href puede ser de dos tipos: una URL absoluta o una ruta relativa.

URL absolutas: la dirección completa

Una URL absoluta incluye todo: protocolo, dominio y ruta, como https://es.wikipedia.org/wiki/Tarta. La anatomía de una URL la viste en la Estación 3. Úsalas para enlazar a otros sitios. Si olvidas el protocolo y escribes href="es.wikipedia.org", el navegador lo toma por una ruta relativa y busca una carpeta llamada «es.wikipedia.org» dentro de tu sitio.

Rutas relativas: el camino desde donde estás

Para enlazar páginas de tu propio sitio se usan rutas relativas: indicaciones que parten de la carpeta donde está la página que contiene el enlace. Es la misma idea de las rutas de la terminal que practicaste en la Estación 5: .. sube una carpeta y un nombre seguido de / entra en ella. Saltos dentro de la página, correo y teléfono

  • Fragmentos: si un elemento tiene un atributo id, puedes enlazar directo a él con #: <h2 id="pasos">Pasos</h2> y <a href="#pasos">Ir a los pasos</a>. También desde otra página: href="tarta.html#pasos". Un id debe ser único en la página, no puede tener espacios y distingue mayúsculas.
  • Correo: href="mailto:ana@ejemplo.com" abre el programa de correo de quien pulsa.
  • Teléfono: href="tel:+59899123456" ofrece llamar, muy útil en móviles. Escribe el número con el prefijo internacional y sin espacios.

Abrir en otra pestaña: con moderación

El atributo target="_blank" abre el enlace en una pestaña nueva. Úsalo poco: quien navega ya sabe abrir pestañas si quiere (con la rueda del ratón o Ctrl + clic), y una pestaña que aparece sin aviso desorienta, sobre todo a quien usa un lector de pantalla o tiene dificultades cognitivas. Si lo usas, avísalo en el texto del enlace: «(se abre en otra pestaña)».

Antes se recomendaba añadir siempre rel="noopener" junto a target="_blank", porque la página nueva podía controlar la tuya con JavaScript. Desde 2021, todos los navegadores principales aplican ese comportamiento solos. Añadirlo no hace daño, y lo verás en mucho código existente.

Qué texto poner en un enlace

El texto de un enlace debe decir adónde lleva, incluso leído fuera de contexto. Los lectores de pantalla pueden mostrar una lista con todos los enlaces de la página, y una lista con diez «haz clic aquí» no sirve de nada. Los buscadores también usan ese texto para entender la página de destino.

Texto que no dice nada

<p>Para ver la receta del flan,
  <a href="flan.html">haz clic aquí</a>.</p>

Texto que describe el destino

<p>También te puede gustar la
  <a href="flan.html">receta del flan de huevo</a>.</p>

Un enlace lleva a otro sitio; un botón hace algo (enviar un formulario, abrir un menú, añadir al carrito). Si lo que quieres es una acción, usa <button>, que verás en los formularios. Confundirlos hace que el teclado y los lectores de pantalla se comporten de forma inesperada.

Los errores de rutas más comunes al publicar una web: usar la barra invertida de Windows (img\logo.png): en las URL siempre es /. Poner espacios, tildes o eñes en los nombres de archivo: usa minúsculas y guiones, como tarta-de-manzana.html. Y fiarse de las mayúsculas: en Windows y macOS Logo.PNG y logo.png suelen ser el mismo archivo, pero la mayoría de servidores web usan Linux, donde son dos archivos distintos. La página funciona en tu computadora y falla al publicarla.

Imágenes que todos pueden entender

Una foto del plato terminado hace que una receta dé ganas de cocinarla. Pero no todo el mundo ve las imágenes: una persona ciega las escucha, alguien con una conexión lenta puede no recibirlas y un buscador no «mira» fotos como tú. Para todos ellos, HTML tiene un texto que sustituye a la imagen.

El elemento img

<img src="img/tarta.jpg"
     alt="Tarta de manzana recién horneada, con las láminas de manzana en espiral"
     width="800" height="600">
  • img es un elemento vacío: no tiene etiqueta de cierre.
  • src (source, «origen») es la ruta de la imagen. Sigue las mismas reglas de rutas que los enlaces.
  • alt es el texto alternativo: lo que sustituye a la imagen cuando no se puede ver. Es obligatorio.
  • width y height son el ancho y el alto originales en píxeles, sin escribir «px». Con ellos, el navegador reserva el hueco antes de que la imagen llegue y el texto no da saltos mientras lees. Con CSS podrás mostrarla más pequeña sin deformarla.

Cómo escribir un buen texto alternativo

La pregunta clave no es «¿qué se ve?», sino «¿qué aporta esta imagen aquí?». La misma foto puede necesitar textos distintos según dónde esté. Estos son los casos típicos:

Tipo de imagenQué escribirEjemplo
Informativa: aporta contenido (una foto del plato, un producto)Lo importante de la imagen para esa página, en una frasealt="Tarta de manzana recién horneada, con la masa dorada"
Decorativa: solo adorna (un separador, un fondo, un icono junto a un texto que ya lo dice)Un alt vacío. Así el lector de pantalla la saltaalt=""
Funcional: está dentro de un enlace o un botón (un logo que lleva a la portada, una lupa para buscar)Adónde lleva o qué hace, no cómo esalt="Recetas de Ana, inicio"
Con texto: un cartel, un menú en fotoEl texto que contienealt="Oferta: 2 por 1 en todas las tartas"
Compleja: un gráfico, un mapa, un diagramaUn resumen breve en alt y la información completa en el texto de la página (por ejemplo, en una tabla)alt="Gráfico de calorías por porción; los datos están en la tabla siguiente"

Errores típicos: empezar con «imagen de» o «foto de» (el lector de pantalla ya anuncia que es una imagen); dejar el nombre del archivo; escribir un párrafo entero; repetir palabra por palabra el texto que ya está al lado. Y el peor: olvidar el atributo. Un alt="" vacío dice «esta imagen es decorativa»; un alt que falta dice «no sé», y cada lector de pantalla lo resuelve a su manera.

En el análisis de WebAIM de 2026 sobre el millón de páginas de inicio más visitadas, más de la mitad (el 53,1 %) tenía al menos una imagen sin texto alternativo. Es uno de los errores de accesibilidad más frecuentes de la web, y de los más fáciles de evitar.

Imágenes con pie de foto

Si una imagen necesita un pie visible para todo el mundo, usa <figure> y <figcaption>. El pie no sustituye al alt: el alt describe la imagen y el pie la comenta, así que no repitas lo mismo en los dos.

<figure>
  <img src="img/abuela.jpg" alt="Mujer mayor amasando sobre una mesa de madera enharinada"
       width="800" height="600">
  <figcaption>Mi abuela Rosa, que me enseñó esta receta en 1998.</figcaption>
</figure>

PNG (.png)Capturas de pantalla, gráficos con bordes nítidos, imágenes con transparencia.

HTML semántico: cada cosa con su nombre

Con div y CSS puedes construir cualquier diseño. Muchas páginas están hechas así, cajas dentro de cajas sin ningún significado. A eso se le llama, con humor, «sopa de divs». Se ven bien, pero para un lector de pantalla, un buscador o la persona de tu equipo que abre el código, todas las cajas son iguales. Semántica significa «relativo al significado»: HTML semántico es elegir, para cada parte de la página, el elemento que dice qué es.

Sopa de divs

<div class="cabecera">…</div>
<div class="menu">…</div>
<div class="contenido">
  <div class="receta">…</div>
</div>
<div class="pie">…</div>

Elementos semánticos

<header>…</header>
<nav>…</nav>
<main>
  <article>…</article>
</main>
<footer>…</footer>

Los dos se pueden ver idénticos. La diferencia está en lo que entienden las máquinas. El atributo class de la izquierda es una etiqueta para CSS, que verás en la Estación 14; el navegador no sabe que «cabecera» significa cabecera.

Los elementos que organizan una página

ElementoQué representaEjemplos

<nav>Un bloque de enlaces de navegación importantesMenú principal, índice de la página
<main>El contenido principal, lo que es único de esta página. Solo uno visible por páginaLa receta, el artículo, la ficha del producto

Regiones: el mapa para quien no ve

Varios de estos elementos crean regiones (en inglés, landmarks): zonas con nombre a las que un lector de pantalla puede saltar directamente, como los carteles de las salidas de una estación de metro. main, nav, aside y search siempre son regiones. header y footer lo son cuando pertenecen a toda la página, no cuando están dentro de un article o un section. Y un section solo se convierte en región si le das un nombre accesible, algo que verás en la Estación 17.

¿article, section o div?

Es la duda más común. Hazte estas preguntas en orden:

  1. ¿Tendría sentido por sí solo, fuera de esta página, por ejemplo compartido en una red social o en un lector de noticias? Entonces es un article.
  2. ¿Es un grupo temático de contenido, con su propio encabezado, dentro de algo más grande? Entonces es un section.
  3. ¿Solo necesitas una caja para darle estilo o para agrupar cosas sin un significado propio? Entonces es un div. No está prohibido: úsalo sin culpa cuando ningún otro elemento encaje.

Una receta completa es un article; sus «Ingredientes» y «Pasos» son section; y la caja que usas para poner la foto al lado del texto es un div.

Por qué importa

  • Para las personas. Los lectores de pantalla, los programas de control por voz y la navegación por teclado dependen de la semántica. Es la base de la accesibilidad: que cualquier persona, con o sin discapacidad, pueda usar lo que construyes.
  • Para los buscadores. Google y los demás leen tu HTML para entender la página: el title, el texto de los enlaces y el alt de las imágenes les dicen de qué trata. Seamos honestos: la propia guía de Google dice que el orden de los encabezados es genial para los lectores de pantalla, pero que para su buscador da igual. La razón principal para escribir buen HTML son las personas.
  • Para otras herramientas. El modo lectura del navegador, los traductores automáticos y los asistentes que resumen páginas funcionan mejor cuando encuentran main, article y encabezados claros.
  • Para tu equipo. <nav> se entiende de un vistazo; <div class="menu-top-2"> hay que investigarlo.

Existe un conjunto de atributos llamado ARIA (role, aria-label…) que sirve para añadir significado a elementos que no lo tienen. La primera regla que da el propio W3C para usarlo es: si existe un elemento HTML nativo con el significado y el comportamiento que necesitas, usa ese elemento. Un <button> de verdad siempre es mejor que un <div role="button">. ARIA se ve en la Estación 17.

En este taller, el CSS muestra el nombre de cada elemento semántico y dibuja su borde, para que veas la estructura. Investiga el código y luego modifica: añade una tercera section llamada «Consejos» dentro del article, y un enlace más en el menú.

Tablas de datos

Algunos datos tienen forma de cuadrícula: la clasificación de un torneo, el horario de clases, la información nutricional de un alimento. Cada valor tiene sentido por su fila y por su columna: «12» no dice nada, pero «Lu, victorias: 12» sí. Para eso existen las tablas.

<table>
  <caption>Torneo de karts: clasificación tras 5 carreras</caption>
  <thead>
    <tr>
      <th scope="col">Piloto</th>
      <th scope="col">Victorias</th>
      <th scope="col">Puntos</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Lu</th>
      <td>3</td>
      <td>71</td>
    </tr>
    <tr>
      <th scope="row">Nico</th>
      <td>2</td>
      <td>64</td>
    </tr>
  </tbody>
</table>
ElementoQué es
<table>La tabla entera.
<caption>El título de la tabla. Va justo después de <table>. Un lector de pantalla lo anuncia al entrar.
<thead>, <tbody>, <tfoot>Agrupan las filas de cabecera, de datos y de totales. tfoot es opcional.
<tr>Una fila (table row).
<th>Una celda de encabezado (table header). Con scope="col" es el encabezado de su columna; con scope="row", de su fila.
<td>Una celda de datos (table data).

¿Por qué tanto detalle con th y scope? Porque una persona que escucha la tabla no ve las columnas. Cuando llega a la celda «64», el lector de pantalla puede decirle «Nico, Puntos, 64» gracias a esos encabezados. Sin ellos, solo oiría un número suelto.

Las tablas no tienen bordes por defecto; el CSS de este taller se los pone. Predice cuántas filas y columnas verás, ejecuta, y después modifica: añade una fila para una tercera jugadora, Sol, con 0 victorias y 58 puntos, y una columna «Carreras» con el valor 5 para todos.

Una celda puede ocupar varias columnas con colspan="2" o varias filas con rowspan="2", como en un horario donde una clase dura dos horas. Úsalos con moderación: cuanto más irregular es una tabla, más difícil es de entender, sobre todo escuchándola.

Durante años, las páginas se maquetaban con tablas: una celda para el menú, otra para el contenido. No lo hagas. Una tabla anuncia «aquí hay datos en filas y columnas», y el lector de pantalla leerá tu menú como si fuera una hoja de cálculo. Para colocar cosas en pantalla se usa CSS (flexbox y grid, en la Estación 14).

Formularios: pedir datos a las personas

Buscar un producto, iniciar sesión, dejar un comentario, pagar una compra, apuntarte a un torneo: todo eso pasa por un formulario. Es la parte de HTML donde la página deja de solo mostrar y empieza a preguntar. También es donde más errores de accesibilidad se cometen, así que conviene aprenderlo bien desde el principio.

El formulario más pequeño

<form action="/buscar" method="get">
  <label for="busqueda">¿Qué receta buscas?</label>
  <input id="busqueda" name="q" type="search">
  <button type="submit">Buscar</button>
</form>
  • <form> agrupa los campos. Su atributo action dice adónde se envían los datos (una dirección de un servidor, el programa que los recibe y que aprenderás a escribir en la Estación 29). method dice cómo: get pone los datos en la URL (/buscar?q=tarta), útil para búsquedas que se pueden compartir; post los envía por dentro de la petición, lo adecuado para datos personales o que cambian algo.
  • <label> es la etiqueta visible del campo: el texto que dice qué hay que escribir.
  • <input> es el campo donde se escribe. Es un elemento vacío.
  • <button> es el botón que envía el formulario.

label, id y name: tres piezas que se confunden

Cada campo necesita tres cosas, y cada una tiene un trabajo distinto:

AtributoVa enSirve para
for="busqueda"labelDecir a qué campo pertenece la etiqueta. Su valor debe ser el id del campo.
id="busqueda"el campoIdentificar el campo dentro de la página. Único en toda la página.
name="q"el campoPonerle nombre al dato cuando se envía: el servidor recibe q=tarta. Sin name, el dato no se envía.

Cuando for y id coinciden, pasan dos cosas buenas: al hacer clic en el texto de la etiqueta, el cursor salta al campo (y en una casilla pequeña, marcarla es mucho más fácil), y el lector de pantalla anuncia la etiqueta al llegar al campo: «¿Qué receta buscas?, campo de búsqueda». También puedes meter el campo dentro de la etiqueta, <label>Nombre <input name="nombre"></label>, y no necesitas for.

El placeholder, ese texto gris de ejemplo dentro del campo, no es una etiqueta. Desaparece en cuanto empiezas a escribir (y ya no recuerdas qué pedía el campo), suele tener poco contraste y no todos los lectores de pantalla lo anuncian. Úsalo, si quieres, para un ejemplo: placeholder="ana@ejemplo.com", pero siempre con un label visible. En el análisis de WebAIM de 2026, el 51 % de las páginas de inicio más visitadas tenía campos sin etiqueta.

El atributo type de input cambia qué se puede escribir y cómo se ve. En el móvil, además, cambia el teclado: con type="email" aparece la @ y con type="tel", el teclado numérico. Si no escribes type, el campo es de texto.

Textos largos, listas desplegables y opciones

  • <textarea> es un campo de varias líneas, para mensajes o comentarios. A diferencia de input, tiene etiqueta de cierre, y su atributo rows indica cuántas líneas se ven.
  • <select> es una lista desplegable. Cada opción es un <option>: su value es lo que se envía y su contenido, lo que se ve.
  • Los grupos de radio y de checkbox se envuelven en un <fieldset> con una <legend>: la leyenda es la pregunta del grupo, y el lector de pantalla la anuncia al entrar en él.
<label for="dificultad">Dificultad</label>
<select id="dificultad" name="dificultad">
  <option value="facil">Fácil</option>
  <option value="media" selected>Media</option>
  <option value="dificil">Difícil</option>
</select>

<fieldset>
  <legend>¿Para cuántas personas?</legend>
  <input type="radio" id="p2" name="personas" value="2">
  <label for="p2">2</label>
  <input type="radio" id="p4" name="personas" value="4" checked>
  <label for="p4">4</label>
  <input type="radio" id="p6" name="personas" value="6">
  <label for="p6">6</label>
</fieldset>

Fíjate en que los tres radio tienen el mismo name (así el navegador sabe que son un grupo y solo deja marcar uno) pero distinto id (cada uno necesita su etiqueta). selected y checked marcan la opción elegida al cargar.

required, checked, selected o disabled son atributos booleanos: basta con que estén para que valgan «sí». Por eso required="false" sigue siendo obligatorio. Para desactivarlos, quita el atributo entero.

Botones

<button> tiene tres tipos. type="submit" envía el formulario; type="reset" lo vacía (casi nunca es buena idea: es fácil pulsarlo sin querer); type="button" no hace nada por sí solo y espera a que JavaScript le dé una tarea. Ojo: dentro de un formulario, un button sin type es de envío. Si pones un botón «Mostrar contraseña» sin type="button", al pulsarlo enviarás el formulario.

Validación: el navegador revisa antes de enviar

Validar es comprobar que los datos tienen sentido antes de aceptarlos. HTML trae una validación nativa: con unos atributos, el navegador revisa el formulario al pulsar «Enviar» y, si algo falla, lo detiene y muestra un aviso junto al campo.

min, max, stepEl rango de un número o una fecha, y de cuánto en cuánto sube<input type="number" name="edad" min="12" max="99">
patternQue el texto encaje con un patrón (una expresión regular)<input name="cp" pattern="[0-9]{5}">

El atributo pattern usa expresiones regulares, un minilenguaje para describir formas de texto. [0-9]{5} significa «exactamente cinco caracteres del 0 al 9», el formato de un código postal de España o de México. El patrón tiene que encajar con todo el valor, no con una parte. Cuando uses pattern, explica el formato en un texto visible junto al campo; el atributo title ayuda, pero no todos los navegadores lo muestran.

<label for="usuario">Nombre de usuario</label>
<input id="usuario" name="usuario" required pattern="[A-Za-z0-9_]{3,15}"
       title="De 3 a 15 letras sin tilde, números o guion bajo">
<p>De 3 a 15 caracteres: letras sin tilde, números o guion bajo.</p>

Primera: un campo con pattern o type="email" pero sin required se acepta vacío; si es obligatorio, añade required. Segunda: type="email" solo revisa la forma; «ana@correo» sin punto se considera válido, así que la única prueba real de que un correo existe es enviarle un mensaje. Tercera: si tu pattern tiene un error de escritura, el navegador lo ignora en silencio y acepta cualquier cosa. Pruébalo siempre con datos buenos y malos.

La validación del navegador es una ayuda para la persona que llena el formulario, no una medida de seguridad. Cualquiera puede desactivarla con las DevTools o enviar datos sin pasar por tu página. El servidor siempre debe volver a comprobar todo. Lo verás en la Estación 29 y en la Estación 31.

Añade el atributo autocomplete a los campos de datos personales: autocomplete="name", "email", "tel", "street-address". El navegador ofrecerá rellenarlos con los datos guardados. Ahorra tiempo a todo el mundo y es especialmente útil para personas con dificultades motoras o de memoria; las pautas de accesibilidad lo piden para los datos de la propia persona.

Pruébalo: un formulario de contacto

La vista previa del curso no puede enviar formularios de verdad a ningún servidor. Por eso este taller tiene un ayudante en la pestaña JS: al pulsar «Enviar», le pide al navegador que revise el formulario y, si todo está bien, muestra en la consola los pares name = valor que se enviarían. Predice primero: ¿qué pasará si pulsas «Enviar» sin escribir nada? ¿Y si escribes un mensaje de 5 letras? ¿Aparecerá la casilla del boletín en los datos si no la marcas?

Ahora modifica: añade un campo tel opcional con su etiqueta y autocomplete="tel", y un campo «¿Cuántas veces has hecho la receta?» de tipo number con min="0" y max="50". Prueba a escribir 80 y a enviar.

Los fallos de formulario más comunes, que el navegador no te va a señalar: un for que no coincide con ningún id (por ejemplo, for="email" e id="correo"); dos campos con el mismo id; un campo sin name, cuyo dato se pierde sin avisar; un grupo de radio con name distintos, donde se pueden marcar todas las opciones a la vez; y un botón sin type que envía el formulario cuando no debía.
