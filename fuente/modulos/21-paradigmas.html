Lo que vas a lograr

Un juego de verdad tiene cientos de enemigos, objetos y misiones. Una tienda en línea tiene productos, carritos, pagos y descuentos. Si todo eso vive en variables sueltas y en funciones que cambian cualquier cosa desde cualquier lugar, el programa se vuelve imposible de entender. En esta estación vas a aprender las dos grandes formas de poner orden que usa la industria: la programación orientada a objetos, que agrupa datos y comportamiento en objetos que cuidan su propio estado, y la programación funcional, que construye programas con funciones puras y datos que no cambian. JavaScript permite las dos, y los buenos programas las combinan.

  • Distinguir el código imperativo del declarativo y reconocer los paradigmas principales.
  • Crear clases con constructor, propiedades y métodos, e instanciar objetos con new.
  • Saber qué vale this en cada momento y evitar los errores típicos cuando se pierde.
  • Proteger el estado de un objeto con campos privados (#), getters y setters, y usar miembros static.
  • Reutilizar comportamiento con herencia (extends y super) y aprovechar el polimorfismo.
  • Explicar cómo funcionan las clases por debajo: los prototipos y la cadena de prototipos.
  • Elegir la composición cuando la herencia se vuelve rígida.
  • Escribir funciones puras, separar los efectos secundarios y trabajar con datos inmutables.
  • Crear funciones de orden superior, componer funciones y usar currying sencillo.
  • Decidir qué enfoque conviene en cada parte de un juego o de una tienda, y combinarlos.

Necesitas manejar funciones, funciones flecha, closures y callbacks (Estación 10: Funciones) y arrays y objetos, incluidos map, filter, reduce, el operador spread (...) y la diferencia entre una referencia y una copia (Estación 11: Colecciones). También usarás try/catch (Estación 12: Depuración). Si en la Estación 19: Estructuras de datos viste alguna class, aquí vas a entender todo lo que hay detrás.

Qué es un paradigma

Cuando un programa tiene 50 líneas, cualquier organización funciona. Cuando tiene 50 000 y lo tocan cinco personas, la organización lo es todo. Un paradigma de programación es una forma de pensar y de organizar un programa: qué piezas usas para construirlo y cómo se comunican entre sí. No es un lenguaje ni algo que se instala: es un estilo. La palabra viene del griego y significa «modelo» o «ejemplo».

Imperativo y declarativo: el cómo y el qué

Los paradigmas se agrupan en dos grandes familias:

  • En la programación imperativa le dices a la computadora cómo hacer algo, paso a paso, cambiando variables por el camino. Es lo que haces desde la Estación 7: crear un contador, recorrer una lista con for, sumar en cada vuelta.
  • En la programación declarativa describes qué resultado quieres y dejas que otra pieza (una función, el navegador, una base de datos) decida cómo conseguirlo.

Imperativo es darle indicaciones a un taxista: «dobla a la derecha, sigue tres cuadras, para en la esquina». Declarativo es darle la dirección: «al Museo de Arte, por favor». En los dos casos llegas, pero en el segundo confías en que el taxista sabe el camino. La analogía tiene un límite: en programación lo declarativo no es magia. Alguien escribió el código imperativo que hace el trabajo (el navegador, el motor de la base de datos o la función filter); tú simplemente no tienes que repetirlo.

Mira la misma tarea resuelta de las dos maneras: obtener los nombres de los productos que cuestan menos de 20.

const productos = [
  { nombre: "Café", precio: 4.5 },
  { nombre: "Audífonos", precio: 35 },
  { nombre: "Libreta", precio: 12 },
  { nombre: "Mochila", precio: 48 },
];

// Imperativo: cómo recorrer, cuándo guardar, dónde acumular
const baratos = [];
for (let i = 0; i < productos.length; i++) {
  if (productos[i].precio < 20) {
    baratos.push(productos[i].nombre);
  }
}

// Declarativo: qué quiero (los que cuestan menos de 20, solo su nombre)
const baratos2 = productos
  .filter((p) => p.precio < 20)
  .map((p) => p.nombre);

Las familias se cruzan. La orientación a objetos suele ser imperativa por dentro: sus métodos cambian el estado del objeto paso a paso. La programación funcional es una forma de programación declarativa. Existen más paradigmas (el lógico, como Prolog; el orientado a eventos, que usaste en la Estación 15 con addEventListener), pero estos son la base de casi todo lo que vas a leer.

JavaScript es un lenguaje multiparadigma: la documentación de MDN lo describe como un lenguaje que admite estilos orientado a objetos, imperativo y declarativo, como la programación funcional. En una misma app vas a mezclar clases, bucles y map/filter. La pregunta útil no es «¿cuál es el mejor paradigma?», sino «¿cuál encaja en esta parte del programa?».

Las ideas no son nuevas. Lisp (1958) ya trataba las funciones como datos, la base de la programación funcional. Simula (Noruega, década de 1960) inventó las clases y los objetos para simular sistemas como las filas de un banco, y Smalltalk (década de 1970) popularizó el término «orientado a objetos». JavaScript nació en 1995 tomando ideas de los dos mundos: funciones como valores, de Scheme (un pariente de Lisp), y objetos basados en prototipos, del lenguaje Self.

En los equipos profesionales casi nadie es «puramente» orientado a objetos ni «puramente» funcional. Lo que se valora es saber qué herramienta encaja en cada parte del sistema y respetar el estilo que ya usa el proyecto. Al final de esta estación verás criterios concretos para decidir.

Clases y objetos

En la Estación 11 creaste objetos con llaves: { nombre: "Slime", vida: 30 }. Funciona para uno. Ahora imagina que tu juego necesita 40 enemigos, cada uno con nombre, vida y la capacidad de recibir daño. Copiar y pegar el objeto 40 veces es lento y peligroso: basta un error de tipeo (vdia en lugar de vida) en uno solo para que falle ese enemigo, y es muy difícil de encontrar.

Una primera solución ya la conoces: una función que fabrica objetos.

function crearEnemigo(nombre, vida) {
  return {
    nombre: nombre,
    vida: vida,
    recibirDanio(cantidad) {
      this.vida = Math.max(0, this.vida - cantidad);
    },
  };
}

const slime = crearEnemigo("Slime", 30);
const lobo = crearEnemigo("Lobo", 45);

Funciona, y tiene nombre: función fábrica. Es la misma idea que usaste con crearCola en la Estación 19. La programación orientada a objetos ofrece una herramienta pensada exactamente para esto: la clase.

Clase, instancia, propiedades y métodos

La programación orientada a objetos (POO; en inglés, object-oriented programming u OOP) organiza el programa en objetos que juntan dos cosas: sus datos y las acciones que pueden hacer con esos datos. Una clase (class) es la plantilla que describe cómo son y qué saben hacer los objetos de un tipo. Cada objeto concreto creado con esa plantilla se llama instancia.

Una clase es como el plano de una casa, y las instancias son las casas construidas con ese plano. Todas tienen las mismas habitaciones, pero en cada una vive gente distinta y los muebles cambian. El límite de la analogía: en JavaScript el plano no se guarda en un cajón después de construir. Cada casa queda conectada a él (lo verás en la sección Prototipos), y si le agregas algo al plano, todas las casas lo reciben.

Así se escribe una clase para los personajes del juego:

class Personaje {
  constructor(nombre, vidaMaxima) {
    this.nombre = nombre;
    this.vidaMaxima = vidaMaxima;
    this.vida = vidaMaxima;
  }

  recibirDanio(cantidad) {
    this.vida = Math.max(0, this.vida - cantidad);
  }

  estaVivo() {
    return this.vida > 0;
  }

  describir() {
    return `${this.nombre}: ${this.vida}/${this.vidaMaxima} de vida`;
  }
}

const lyra = new Personaje("Lyra", 120);
const bruno = new Personaje("Bruno", 90);
lyra.recibirDanio(30);
console.log(lyra.describir());   // Lyra: 90/120 de vida
console.log(bruno.describir());  // Bruno: 90/90 de vida

Pieza por pieza:

  • class Personaje { … } declara la clase. Por convención, el nombre de una clase empieza con mayúscula (PascalCase): Personaje, Producto, CarritoDeCompras. Así distingues de un vistazo la plantilla de sus instancias, que van en minúscula (lyra, bruno).
  • El constructor es un método especial que se ejecuta automáticamente cada vez que creas una instancia. Sus parámetros son los datos iniciales del objeto.
  • this significa, dentro de la clase, «el objeto con el que estoy trabajando ahora». this.vida = vidaMaxima crea en el objeto nuevo una propiedad llamada vida.
  • Los métodos son las funciones que pertenecen a la clase: recibirDanio, estaVivo y describir. Se escriben sin la palabra function y sin comas entre ellos. Sus nombres son verbos, como aprendiste en la Estación 10.
  • new Personaje("Lyra", 120) crea una instancia nueva usando la clase.

Todo objeto tiene estado (los valores de sus propiedades en un momento dado: Lyra tiene 90 de vida) y comportamiento (lo que sabe hacer: recibir daño, describirse). Juntar las dos cosas en un mismo lugar es la idea central de la POO.

Qué pasa exactamente con new

new parece una sola palabra, pero hace cuatro trabajos. Míralos uno por uno:

this: el objeto a la izquierda del punto

Ya conoces la regla de la Estación 11: cuando llamas a un método con objeto.metodo(), dentro del método this es el objeto que está a la izquierda del punto. En lyra.describir(), this es lyra; en bruno.describir(), this es bruno. Con las clases esa regla se vuelve imprescindible: un único método sirve para todas las instancias precisamente porque this cambia según quién lo llame. Y dentro del constructor, this es el objeto recién creado por new. Sigue este programa paso a paso y observa cómo this apunta a un cofre distinto en cada llamada:

class Cofre {
  constructor(monedas) {
    this.monedas = monedas;
  }
  abrir() {
    const botin = this.monedas;
    this.monedas = 0;
    return botin;
  }
}

const cofreA = new Cofre(50);
const cofreB = new Cofre(20);
const bolsa = cofreA.abrir();
console.log(bolsa, cofreA.monedas, cofreB.monedas);

Dentro de un método, escribir vida a secas busca una variable llamada vida, no la propiedad del objeto. vida = vida - cantidad; da ReferenceError: vida is not defined. Para hablar de las propiedades del objeto, escribe siempre this.vida.

const lyra = Personaje("Lyra", 120); da TypeError: Class constructor Personaje cannot be invoked without 'new': «el constructor de la clase no se puede llamar sin new». Una clase no es una función normal: para crear instancias siempre va new delante.

En la Estación 10 viste que puedes llamar a una función declarada con function antes de la línea donde la escribes. Con las clases no pasa: igual que con let y const, usar una clase antes de su declaración da ReferenceError: Cannot access 'Personaje' before initialization. Declara tus clases arriba, antes de usarlas.

Campos: propiedades declaradas en la clase

Desde 2022, JavaScript permite declarar propiedades directamente en el cuerpo de la clase, fuera del constructor. Se llaman campos (fields) y son cómodos para valores iniciales que no dependen de los parámetros:

class Enemigo {
  nivel = 1;      // campo: toda instancia empieza en nivel 1
  botin = [];     // cada instancia recibe su PROPIO array vacío

  constructor(nombre, vida) {
    this.nombre = nombre;
    this.vida = vida;
  }

  subirNivel() {
    this.nivel++;
    this.vida += 10;
  }
}

El valor de un campo se calcula de nuevo en cada new, así que dos enemigos nunca comparten el mismo array botin. Los campos se crean justo antes de que se ejecute el cuerpo del constructor.

¿Clase u objeto literal?

No todo necesita una clase. Si solo existe un objeto de ese tipo (la configuración del juego) o si son datos sin comportamiento (un producto que llega de un servidor en formato JSON), un objeto literal con llaves es más sencillo. Usa una clase cuando vas a crear muchos objetos con la misma forma y el mismo comportamiento, o cuando el objeto tiene reglas que proteger, que es justo el tema de la siguiente sección.
