Lo que vas a lograr

Hasta ahora tus programas eran una lista de instrucciones que se ejecutaba una sola vez, de arriba abajo. En cuanto un programa crece, la misma cuenta aparece en cinco lugares distintos, y cambiarla obliga a buscarla en todos. Las funciones resuelven eso: le pones nombre a un trozo de lógica, lo escribes una vez y lo usas todas las veces que quieras, con datos distintos. Son la pieza con la que se organiza cualquier app o videojuego, desde el botón de «Comprar» hasta el cálculo del daño de un ataque.

  • Explicar para qué sirve una función y reconocer cuándo conviene crear una.
  • Declarar funciones, llamarlas y seguir con la vista el «viaje» que hace la ejecución.
  • Distinguir parámetros de argumentos, y usar valores por defecto.
  • Devolver resultados con return y saber cuándo conviene imprimir y cuándo devolver.
  • Escribir la misma función como declaración, como expresión y como función flecha.
  • Pasar funciones como argumentos (callbacks) para que otra función las llame.
  • Predecir qué variables se ven desde cada parte del programa (ámbito global, de función y de bloque) y explicar por qué var confunde.
  • Entender de forma intuitiva los closures, la pila de llamadas y la recursión.
  • Dividir un problema en funciones pequeñas, puras y con nombres que son verbos.
  • Construir un kit de utilidades para un juego de rol: daño, curación, niveles y barra de vida.

Vas a usar dentro de las funciones todo lo que ya sabes: variables con let y const (Estación 7: Variables), condiciones con if (Estación 8: Decisiones) y bucles for y while (Estación 9: Bucles). Si alguno de esos temas todavía te cuesta, repasa su resumen antes de seguir. Todo el código de esta estación se ejecuta aquí mismo, en el navegador.

Por qué existen las funciones

Imagina que estás programando un juego de rol. El héroe ataca a un slime, el slime ataca al héroe y, de vez en cuando, una trampa golpea al héroe. En los tres casos el daño se calcula igual: el ataque menos la defensa, y como mínimo 1 punto, para que ningún golpe haga cero. Sin funciones, el código queda así:

// El héroe ataca al slime
let danioAlSlime = ataqueHeroe - defensaSlime;
if (danioAlSlime < 1) {
  danioAlSlime = 1;
}
vidaSlime = vidaSlime - danioAlSlime;

// El slime ataca al héroe
let danioAlHeroe = ataqueSlime - defensaHeroe;
if (danioAlHeroe < 1) {
  danioAlHeroe = 1;
}
vidaHeroe = vidaHeroe - danioAlHeroe;

// Una trampa golpea al héroe
let danioTrampa = 25 - defensaHeroe;
if (danioTrampa < 1) {
  danioTrampa = 1;
}
vidaHeroe = vidaHeroe - danioTrampa;

Funciona, pero tiene tres problemas que empeoran a medida que el juego crece:

  • Cambiar la regla es peligroso. Si mañana decides que el daño mínimo es 2, tienes que encontrar y cambiar tres lugares. En un juego real serían treinta, y basta con olvidar uno para crear un error difícil de encontrar.
  • Es largo. Cuatro líneas repetidas tres veces. Cuanto más código, más sitios donde equivocarse.
  • No dice qué hace. Para entender que esas líneas «calculan un daño» tienes que leerlas enteras y deducirlo.

Ahora el mismo programa con una función:

function calcularDanio(ataque, defensa) {
  let danio = ataque - defensa;
  if (danio < 1) {
    danio = 1;
  }
  return danio;
}

vidaSlime = vidaSlime - calcularDanio(ataqueHeroe, defensaSlime);
vidaHeroe = vidaHeroe - calcularDanio(ataqueSlime, defensaHeroe);
vidaHeroe = vidaHeroe - calcularDanio(25, defensaHeroe);

La regla está escrita una sola vez. Si cambia, la cambias en un sitio y los tres usos se actualizan solos. Y las tres últimas líneas se leen casi como una frase: «a la vida del slime réstale el daño que calcula el ataque del héroe contra la defensa del slime».

Una función es un bloque de código con nombre que hace una tarea concreta. La escribes una vez (eso es definir la función) y después la llamas, es decir, le pides que se ejecute, cada vez que la necesitas y con los datos de ese momento. Todavía no te preocupes por los detalles de la sintaxis: en las próximas paradas vas a ver cada pieza por separado.

Las funciones existen por dos razones que vas a oír toda tu carrera:

  1. No repetirse. En la industria se resume con la sigla DRY, del inglés Don't Repeat Yourself, «no te repitas». Cada regla del programa debería vivir en un solo lugar. La verás a fondo en la Estación 25: Código limpio.
  2. Darle nombre a una idea. Cuando lees calcularDanio(...) no necesitas saber cómo se calcula el daño para entender qué pasa. Es la abstracción que conociste en la Estación 4: Pensar como programador: esconder los detalles detrás de un nombre claro.

Una función es como una receta escrita en una tarjeta. Escribes la receta del licuado una vez: «pon la fruta y la leche, licúa 30 segundos, sirve». Cada vez que quieres un licuado sigues la tarjeta, y un día usas fresa y otro, plátano. La fruta es el dato que cambia; la receta es siempre la misma. El límite de la analogía: una persona que cocina improvisa y rellena lo que falta. La computadora sigue la función al pie de la letra y no adivina nada que no esté escrito.

Declarar y llamar una función

Empecemos por la función más sencilla posible: una que no recibe nada y no entrega nada, solo hace algo. Esta muestra el menú de un juego:

function mostrarMenu() {
  console.log("1. Jugar");
  console.log("2. Opciones");
  console.log("3. Salir");
}

Esto es una declaración de función: la forma clásica de crear una. Tiene cuatro piezas:

  • La palabra reservada function, que le avisa a JavaScript de que empieza una función.
  • El nombre, mostrarMenu. Sigue las mismas reglas que los nombres de variables (camelCase, sin espacios, no puede empezar con un número).
  • Los paréntesis (). Aquí están vacíos porque la función no necesita datos; en la próxima parada los vas a llenar.
  • El cuerpo: las instrucciones entre llaves { }. Se escriben con sangría, igual que dentro de un if, para que se vea qué pertenece a la función.

Aquí viene la parte que más sorprende al principio: declarar una función no la ejecuta. Si escribes solo esas cinco líneas y ejecutas el programa, no aparece nada en la consola. Declarar es escribir la receta, no cocinar. Para que el cuerpo se ejecute tienes que llamar a la función (también se dice invocar): escribir su nombre seguido de paréntesis.

mostrarMenu();   // ahora sí se imprimen las tres líneas
mostrarMenu();   // y otra vez, las mismas tres

Este es el mapa completo de una función. Todavía no conoces todas las piezas, pero vas a ir llenando cada una en las próximas paradas:

Parece magia, y tiene una explicación que verás en la sección Ámbito. Parámetros y argumentos

mostrarMenu hace siempre exactamente lo mismo. Pero muchas veces quieres que una función haga casi lo mismo, con un dato que cambia. Imagina que quieres saludar a cada persona que entra al juego. Sin una forma de pasarle el nombre, tendrías que escribir saludarAna, saludarLeo, saludarKai… una función por persona. Justo lo que queríamos evitar.

La solución es dejar un hueco en la función para ese dato:

function saludar(nombre) {
  console.log("Hola, " + nombre + ". ¡Te damos la bienvenida!");
}

saludar("Ana");   // Hola, Ana. ¡Te damos la bienvenida!
saludar("Leo");   // Hola, Leo. ¡Te damos la bienvenida!

Aquí aparecen dos palabras que se confunden mucho, así que vale la pena separarlas bien:

  • Un parámetro es la variable que escribes entre los paréntesis de la declaración: nombre. Es un hueco con nombre. Dentro del cuerpo lo usas como cualquier otra variable.
  • Un argumento es el valor concreto que pones entre los paréntesis de la llamada: "Ana", "Leo". En cada llamada, el argumento se guarda en el parámetro antes de ejecutar el cuerpo.

Piensa en un formulario de papel que dice «Nombre: ______». La línea en blanco es el parámetro: está en el formulario desde que se imprimió. Lo que escribes encima, «Ana», es el argumento. Cada llamada a la función es un formulario nuevo, con su propia línea rellenada. La analogía falla en un punto: un formulario te deja la línea vacía si no escribes nada, y JavaScript, en ese caso, pone undefined (lo verás en un momento).

En inglés se dice parameter y argument. Mucha gente, incluso con experiencia, usa las dos palabras como si fueran lo mismo, y casi siempre se entiende por el contexto. Pero cuando algo falla, distinguirlas te ayuda a pensar: ¿el problema está en cómo definí la función o en cómo la llamé?

Varios parámetros: el orden manda

Una función puede tener tantos parámetros como necesite, separados por comas. Los argumentos se asignan por posición: el primer argumento va al primer parámetro, el segundo al segundo, y así. JavaScript no mira los nombres ni los tipos: solo el orden.

El parámetro no tiene que llamarse como tu variable

Un error de razonamiento muy común es creer que, para pasarle un dato a una función, la variable tiene que llamarse igual que el parámetro. No es así. El parámetro recibe el valor, venga de donde venga:

function saludar(nombre) {
  console.log("Hola, " + nombre);
}

const heroe = "Lyra";
const invitado = "Kai";
saludar(heroe);        // dentro de la función, nombre vale "Lyra"
saludar(invitado);     // ahora nombre vale "Kai"
saludar("Sol");        // un valor escrito directamente también sirve
saludar("Dr. " + heroe);  // y el resultado de una expresión: "Dr. Lyra"

Antes de ejecutar el cuerpo, JavaScript calcula cada argumento hasta tener un valor y lo guarda en el parámetro correspondiente. La función no sabe ni le importa si ese valor vino de una variable llamada heroe, de un texto escrito a mano o de una suma.

Cambiar un parámetro no cambia tu variable

Cuando pasas un número, un texto o un booleano, el parámetro recibe una copia del valor. Si la función cambia su parámetro, cambia su copia, no tu variable:

function subirNivel(nivel) {
  nivel = nivel + 1;
  console.log("Dentro de la función:", nivel);   // 5
}

let miNivel = 4;
subirNivel(miNivel);
console.log("Fuera de la función:", miNivel);    // 4, no cambió

Si quieres que la función cambie tu variable, la forma limpia es que la función devuelva el nuevo valor y que tú lo guardes: miNivel = subirNivel(miNivel);. Eso es justo lo que vas a aprender en la próxima parada, con return.

Con las listas y los objetos que verás en la Estación 11: Colecciones la historia cambia: la función no recibe una copia del contenido, sino una forma de llegar al mismo contenido, y lo que cambie dentro sí se nota fuera. Por ahora, con números, textos y booleanos, quédate con esta regla: el parámetro es una copia.

Valores por defecto

A veces un parámetro casi siempre tiene el mismo valor. Puedes escribir ese valor en la declaración, con un =, y se usará cuando la llamada no lo indique. Se llama valor por defecto (o parámetro predeterminado; en inglés, default parameter):

function crearEnemigo(tipo = "slime", nivel = 1) {
  console.log("Aparece un " + tipo + " de nivel " + nivel);
}

crearEnemigo();                // Aparece un slime de nivel 1
crearEnemigo("goblin");        // Aparece un goblin de nivel 1
crearEnemigo("dragón", 20);    // Aparece un dragón de nivel 20
crearEnemigo(undefined, 5);    // Aparece un slime de nivel 5

El valor por defecto se usa cuando el argumento falta o vale undefined. Con cualquier otro valor, aunque sea «vacío», se usa ese valor. Predice estas llamadas:

null, 0 y el texto vacío "" son valores de verdad, así que no activan el valor por defecto. Solo la ausencia (o undefined) lo hace. Esto viene de la documentación oficial de JavaScript en MDN, y es una diferencia importante con un truco antiguo que todavía verás en código viejo:

  nivel = nivel || 1;

Valor por defecto moderno

El truco con || que conociste en la Estación 8 trata a 0 como «falso», así que un nivel 0 legítimo se convierte en 1. Los valores por defecto llegaron a JavaScript en la versión de 2015 (ES2015) y funcionan en todos los navegadores actuales y en Node.js, así que úsalos sin miedo.

Pon los parámetros con valor por defecto al final de la lista. Así la llamada más común es la más corta: crearEnemigo("goblin"). Si el parámetro opcional estuviera primero, tendrías que escribir crearEnemigo(undefined, "goblin"), que es feo y fácil de equivocar.

Devolver un resultado con return

Hasta ahora, todas nuestras funciones imprimían. Pero la mayoría de las veces no quieres mostrar el resultado de un cálculo: quieres seguir usándolo. Restar el daño a la vida, sumar el envío al precio, comparar la puntuación con el récord. Si la función solo imprime, el número aparece en la pantalla y el programa lo pierde: no hay forma de guardarlo en una variable.

Para eso existe return. Es una palabra reservada que hace dos cosas a la vez: termina la función en ese mismo momento y entrega un valor al lugar donde se la llamó. Ese valor se llama valor de retorno (en inglés, return value).

function calcularIVA(precio) {
  return precio * 0.16;
}

const iva = calcularIVA(250);           // iva vale 40
const total = 250 + calcularIVA(250);   // total vale 290
console.log(calcularIVA(100));          // imprime 16

La idea clave es esta: cuando la función termina, la llamada se reemplaza por el valor devuelto. Donde decía calcularIVA(250), para el resto de esa línea es como si dijera 40. Por eso puedes usar una llamada en cualquier lugar donde usarías un número: en una suma, en una comparación, dentro de otra llamada.

Imprimir no es devolver

Esta es, probablemente, la confusión más común de quien empieza con funciones. Las dos versiones de abajo parecen hacer lo mismo cuando las pruebas con un console.log, pero solo una sirve para seguir calculando:

Imprime, pero no devuelve

function doble(n) {
  console.log(n * 2);
}

const resultado = doble(5) + 1;
// Se imprime 10, pero doble(5)
// vale undefined, y undefined + 1
// da NaN.
console.log(resultado);   // NaN

Devuelve el valor

function doble(n) {
  return n * 2;
}

const resultado = doble(5) + 1;
// doble(5) vale 10, y 10 + 1
// da 11.

console.log(resultado);   // 11

Una función sin return también entrega un valor al terminar: undefined. Por eso doble(5) + 1 en la versión de la izquierda da NaN («no es un número»), el valor especial que conociste en la Estación 7.

console.log es para las personas: muestra algo en la pantalla y el programa no puede volver a usarlo. return es para el programa: entrega un valor que puedes guardar, sumar, comparar o pasar a otra función. Por regla general, las funciones que calculan algo deben devolver, y deja que quien las llama decida si lo imprime.

return termina la función en el acto

Cuando se ejecuta un return, la función se acaba ahí. Las líneas que haya después dentro de la función no se ejecutan. Esto es muy útil para salir en cuanto ya tienes la respuesta. Por ejemplo, esta función busca el primer múltiplo de un número dentro de un rango:

function primerMultiplo(divisor, desde, hasta) {
  for (let n = desde; n <= hasta; n++) {
    if (n % divisor === 0) {
      return n;       // sale de la FUNCIÓN entera, no solo del bucle
    }
  }
  return null;        // solo se llega aquí si no hubo ningún múltiplo
}

console.log(primerMultiplo(7, 50, 60));   // 56
console.log(primerMultiplo(7, 1, 6));     // null

En la Estación 9 usabas break para salir de un bucle. Un return dentro de un bucle es más fuerte: no solo sale del bucle, sale de toda la función. Y devolver null cuando no hay resultado es una convención muy usada: «vacío a propósito», como viste en la Estación 7.

Varios return: una salida para cada caso

Una función puede tener varios return, uno por cada caso. Es la misma idea de las cláusulas de guarda de la Estación 8: resuelve primero los casos especiales y sal, para que el caso normal quede al final, sin sangrías de más.

function calcularEnvio(totalCompra) {
  if (totalCompra >= 500) {
    return 0;          // envío gratis
  }
  if (totalCompra >= 200) {
    return 30;         // envío reducido
  }
  return 60;           // envío normal
}

console.log(calcularEnvio(750));   // 0
console.log(calcularEnvio(250));   // 30
console.log(calcularEnvio(80));    // 60

Fíjate en que no hace falta ningún else: si la primera condición se cumple, el return ya sacó a la ejecución de la función y las líneas de abajo no se leen.

Funciones que responden sí o no

Una función puede devolver un booleano, y entonces se puede usar directamente dentro de un if. Su nombre suele empezar con es, tiene o puede, para que la condición se lea como una pregunta:

Rodeo innecesario

function esMayorDeEdad(edad) {
  if (edad >= 18) {
    return true;
  } else {
    return false;
  }
}

Devuelve la comparación

function esMayorDeEdad(edad) {
  return edad >= 18;
}

if (esMayorDeEdad(17)) {
  console.log("Puede comprar");
}

Las dos funcionan igual. La comparación edad >= 18 ya es un booleano (true o false), así que puedes devolverla tal cual.

Poner el valor en la línea siguiente al return. Este código devuelve undefined, no el saludo:

function obtenerSaludo() {
  return
    "Hola";
}

JavaScript tiene una regla llamada inserción automática de punto y coma: si una línea termina en return, entiende return; y la función sale sin valor. Escribe siempre el valor (o al menos su comienzo) en la misma línea que return.

Una función devuelve un solo valor. Si necesitas entregar varios datos a la vez (por ejemplo, el nuevo nivel y la experiencia que sobra), se agrupan en una lista o en un objeto, que verás en la Estación 11: Colecciones. Por ahora, si necesitas dos resultados, usa dos funciones.

Funciones como valores: expresiones, flechas y callbacks

En JavaScript una función es un valor, igual que un número o un texto. Eso significa que puedes guardarla en una variable, pasarla a otra función como argumento o devolverla desde otra función. Por eso se dice que en JavaScript las funciones son de primera clase (en inglés, first-class functions): tienen los mismos derechos que cualquier otro dato. Esta idea abre la puerta a dos formas nuevas de escribir funciones y a una técnica que vas a usar en todas partes: los callbacks.

Expresiones de función

En vez de declarar la función con su nombre, puedes crearla sin nombre y guardarla en una constante:

const saludar = function (nombre) {
  return "Hola, " + nombre;
};

console.log(saludar("Ana"));   // Hola, Ana

Esto es una expresión de función: una función escrita en un lugar donde JavaScript espera un valor, aquí a la derecha del =. La función no tiene nombre propio (se dice que es una función anónima): la llamas por el nombre de la constante que la guarda. Fíjate en el punto y coma del final: toda la línea es una asignación, como const x = 5;.

Funciones flecha

Desde 2015, JavaScript tiene una forma más corta de escribir expresiones de función: la función flecha (en inglés, arrow function). Se quita la palabra function y se pone una flecha => (un igual y un mayor que) entre los parámetros y el cuerpo:

const saludar = (nombre) => {
  return "Hola, " + nombre;
};

Y si el cuerpo es una sola expresión, puedes quitar también las llaves y el return. El resultado de la expresión se devuelve solo. Esto se llama retorno implícito:

const saludar = (nombre) => "Hola, " + nombre;
const doble = (n) => n * 2;
const sumar = (a, b) => a + b;
const tirarDado = () => Math.floor(Math.random() * 6) + 1;

Las reglas de los paréntesis, según la documentación de MDN:

  • Con un solo parámetro, los paréntesis son opcionales: n => n * 2 también es válido. Aun así, muchas herramientas que dan formato al código, como Prettier, los ponen siempre por defecto, y en este curso también los pondremos: así todas las flechas se ven igual.
  • Con cero parámetros o con varios, son obligatorios: () => … y (a, b) => ….
  • No puede haber un salto de línea entre los parámetros y la flecha. Después de la flecha, sí.

Las tres formas que conoces ya hacen lo mismo. Esta tabla resume cuándo se usa cada una:

Comprueba que las tres dan el mismo resultado. Después modifica el programa: añade una función flecha triple que devuelva el triple de un número, y una función flecha esPar que devuelva true si un número es par (pista: el operador %).

Usar llaves en una flecha y olvidar el return. Con llaves, el cuerpo es un bloque normal y el retorno implícito desaparece:

const triple = (n) => { n * 3 };      // devuelve undefined
const triple = (n) => { return n * 3 }; // bien
const triple = (n) => n * 3;            // bien, sin llaves

La regla: sin llaves, devuelve solo; con llaves, necesita return. Cuando conozcas los objetos en la Estación 11, recuerda además que para devolver un objeto con retorno implícito hay que rodearlo de paréntesis: () => ({ vida: 100 }), porque si no, JavaScript confunde sus llaves con las del cuerpo.

Las funciones flecha no son idénticas a las otras en todo: no tienen su propio this ni su propio arguments, y no pueden usarse para crear objetos con new. Son detalles que solo importan cuando trabajas con objetos y clases, y los verás en la Estación 21: Paradigmas. Para todo lo que haces en esta estación, son intercambiables.

Callbacks: pasar una función a otra función

Si una función es un valor, puedes pasarla como argumento. La función que recibes así se llama callback (en español a veces «función de devolución de llamada»): una función que le entregas a otra para que ella la llame cuando corresponda. Y la función que recibe (o devuelve) otras funciones se llama función de orden superior.

function calcular(a, b, operacion) {
  return operacion(a, b);     // llama a la función que le pasaron
}

const sumar = (x, y) => x + y;
const multiplicar = (x, y) => x * y;

console.log(calcular(6, 3, sumar));             // 9
console.log(calcular(6, 3, multiplicar));       // 18
console.log(calcular(6, 3, (x, y) => x - y));   // 3

calcular no sabe qué operación va a hacer: esa decisión se la pasa quien la llama. En la última línea, la función flecha se escribe directamente como argumento, sin guardarla antes en una constante. Es muy habitual cuando el callback es corto y solo se usa una vez.

Mira bien la diferencia entre sumar y sumar(). Sin paréntesis estás hablando de la función, como quien pasa la tarjeta de la receta. Con paréntesis la estás ejecutando ahora mismo y lo que obtienes es su resultado. Para pasar un callback, se pasa la función, sin paréntesis.

JavaScript trae muchas funciones que reciben callbacks. Una de las más sencillas es setTimeout(funcion, milisegundos): guarda tu función y la llama cuando pasa el tiempo indicado. Predice el orden de las tres líneas antes de ejecutar:

Escribir addEventListener("click", atacar()), con paréntesis. Parece razonable, pero así atacar se ejecuta una sola vez, en el momento de cargar la página, y lo que se le entrega al botón es su resultado (undefined), no la función. Después, los clics no hacen nada y no aparece ningún mensaje de error. Es uno de los fallos más repetidos en los foros de principiantes. Los callbacks van a aparecer en casi todas las estaciones que siguen: para transformar listas en la Estación 11 (map, filter…), para reaccionar a clics y teclas en la Estación 15 y para esperar datos de internet en la Estación 16. Siempre es la misma idea: le entregas una función a alguien para que la llame cuando toque.

Ámbito: dónde vive cada variable

Un programa real tiene cientos de funciones. Si todas sus variables fueran visibles desde cualquier sitio, dos funciones que usan un contador i o un total se pisarían entre sí, y un cambio en una parte del programa rompería otra que no tiene nada que ver. Para evitarlo, cada variable existe solo en una zona del programa.

Esa zona se llama ámbito (en inglés, scope): la parte del programa donde una variable existe y se puede usar. En JavaScript moderno hay tres niveles:

  • Ámbito global: lo que declaras fuera de toda función y de todo bloque. Se ve desde cualquier parte del programa.
  • Ámbito de función (o local): los parámetros y las variables que declaras dentro de una función. Solo existen mientras esa función se está ejecutando, y cada llamada crea las suyas, nuevas.
  • Ámbito de bloque: las variables que declaras con let o const dentro de unas llaves { }, como las de un if, un for o un while. Solo existen dentro de esas llaves.

La regla para saber qué ve cada parte del código es una sola: desde dentro se ve hacia fuera, desde fuera no se ve hacia dentro. Cuando usas un nombre, JavaScript lo busca primero en el ámbito más cercano y, si no está, sube al que lo rodea, y así hasta el global. Como esto depende de dónde está escrito el código, se llama ámbito léxico.

Mismo nombre, distinta variable

¿Qué pasa si dentro de una función declaras una variable con el mismo nombre que una global? Se crea otra variable, que tapa a la de fuera mientras dura la función. Se llama sombreado (en inglés, shadowing):

let puntos = 100;

function reiniciar() {
  let puntos = 0;                  // otra variable, solo de la función
  console.log("Dentro:", puntos);  // 0
}

reiniciar();
console.log("Fuera:", puntos);     // 100: la global no cambió

Es legal, pero confunde: quien lee el código puede creer que reiniciar pone los puntos a cero. Evítalo usando nombres distintos. Algunos equipos lo prohíben con herramientas de revisión automática como ESLint, que tiene una regla para eso llamada no-shadow.

Por qué las variables globales son peligrosas

Una función puede leer y cambiar las variables globales, porque desde dentro se ve hacia fuera. Parece cómodo, pero tiene un precio:

La función cambia una global

let vida = 100;

function recibirGolpe(danio) {
  vida = vida - danio;
}

recibirGolpe(30);
// ¿Quién cambió vida? Hay que leer
// todas las funciones para saberlo.

Recibe y devuelve

function recibirGolpe(vida, danio) {
  return vida - danio;
}

let vida = 100;
vida = recibirGolpe(vida, 30);
// El cambio se ve aquí mismo,
// en la línea que lo hace.

Con la versión de la izquierda, cualquier función del programa puede estar cambiando vida, y cuando tiene un valor extraño tienes que revisarlas todas. Con la de la derecha, la función solo trabaja con lo que recibe, y el cambio ocurre a la vista, en la línea que la llama.

Usa el ámbito global para lo mínimo: constantes que todo el programa comparte (const GRAVEDAD = 9.8;) y poco más. Todo lo demás, pásalo por parámetros y devuélvelo con return. Muchos equipos escriben en MAYÚSCULAS las constantes globales de configuración para que se reconozcan de un vistazo.

Un último detalle importante: como cada llamada crea variables locales nuevas, una función no recuerda nada de una llamada a la siguiente:

function contarVisita() {
  let visitas = 0;
  visitas = visitas + 1;
  return visitas;
}

console.log(contarVisita());   // 1
console.log(contarVisita());   // 1 otra vez, no 2

Cada llamada empieza con visitas en 0. ¿Y si quisieras que una función recordara algo entre llamadas, sin usar una variable global? Esa es la pregunta que responden los closures, en la próxima parada.

Por qué var confunde

En la Estación 7 quedó pendiente explicar por qué no se usa var, la forma de declarar variables que existía antes de 2015. Ahora que conoces el ámbito, se entiende. var tiene tres comportamientos que sorprenden:

  1. No respeta los bloques. Una variable declarada con var dentro de un if o de un for existe en toda la función que lo contiene (o en todo el programa, si no hay función). Se «escapa» del bloque.
  2. Se puede usar antes de declararla, y vale undefined. En vez de darte un error que te avise, te da un valor vacío en silencio.
  3. Se puede declarar dos veces sin ningún aviso: var x = 1; var x = 2; es válido. Con let, la segunda línea da SyntaxError: Identifier 'x' has already been declared.

Detrás del segundo comportamiento hay un mecanismo con nombre propio: hoisting (en español a veces «elevación»). Antes de ejecutar un ámbito, JavaScript lo recorre y registra todas las declaraciones que hay en él. El código no se mueve de sitio, pero el efecto es como si las declaraciones subieran al principio. function sumar(a, b) {
  return a + b;
}

console.log(restar(5, 1));   // ReferenceError: Cannot access 'restar' before initialization
const restar = (a, b) => a - b;

La regla práctica: usa const por defecto, let cuando necesites reasignar, y nunca var en código nuevo. Si encuentras var en código antiguo (y lo vas a encontrar), recuerda sus tres rarezas: se escapa de los bloques, vale undefined antes de su línea y se puede redeclarar.

Funciones que recuerdan: closures

Acabas de ver que una función olvida sus variables locales al terminar. Pero hay una excepción muy útil, y ocurre cuando una función se crea dentro de otra función.

Una función que nace dentro de otra puede usar las variables de la función que la rodea (desde dentro se ve hacia fuera). Y aquí viene lo sorprendente: las sigue pudiendo usar aunque la función de fuera ya haya terminado. La función interna «se lleva» esas variables consigo. La combinación de una función con las variables del lugar donde nació se llama closure (en español a veces «clausura»; la documentación de MDN en español usa el término en inglés).

Así se resuelve el contador que no recordaba nada:

function crearContador() {
  let cuenta = 0;
  return function () {
    cuenta = cuenta + 1;
    return cuenta;
  };
}
const contar = crearContador();
console.log(contar());
console.log(contar());

Imagina que la función interna, al nacer, guarda en una mochila las variables que tiene alrededor. Vaya donde vaya, lleva la mochila y puede abrirla cada vez que se ejecuta. El límite de la analogía: en la mochila no hay copias, sino las variables mismas. Si cambian, la función ve el cambio; y si la función las cambia, el cambio se queda para la próxima vez.

Cada vez que llamas a crearContador() se crea una variable cuenta nueva, y la función que sale se lleva esa. Por eso dos contadores no se mezclan. Predice la salida y después modifica: crea un tercer contador, contarVidas, y úsalo dos veces.

Los closures también sirven para fabricar funciones configuradas. Esta función no calcula nada por sí misma: crea funciones que aplican un porcentaje de bonificación, y cada una recuerda el suyo:

function crearBonificador(porcentaje) {
  return (puntos) => puntos + puntos * porcentaje / 100;
}

const bonusFinDeSemana = crearBonificador(50);
const bonusNovato = crearBonificador(10);

console.log(bonusFinDeSemana(200));   // 300
console.log(bonusNovato(200));        // 220

La trampa clásica de var que viste antes se entiende ahora mejor. En este taller, cada vuelta del bucle crea un callback para setTimeout. Con var hay una sola i para todo el bucle, y los tres callbacks recuerdan la misma, que al final vale 4. Con let, cada vuelta tiene su propia j, y cada callback recuerda la suya. La pila de llamadas y un adelanto de recursión

Las funciones pueden llamar a otras funciones, que a su vez llaman a otras. Una tienda calcula el total, el total necesita el impuesto, el impuesto necesita redondear… Cada función, al terminar, tiene que volver exactamente al lugar desde el que la llamaron, y con sus propias variables intactas. ¿Cómo lleva JavaScript la cuenta de todo eso?

Con la pila de llamadas (en inglés, call stack): una lista donde el intérprete de JavaScript anota qué función se está ejecutando y desde dónde la llamaron. Cada llamada pone un elemento nuevo encima; cada función que termina quita el suyo y la ejecución sigue en la de abajo, justo donde se había quedado.

Piensa en una pila de platos en la cocina de un restaurante. Solo puedes poner un plato encima de todo y solo puedes quitar el de arriba. El último que pusiste es el primero que sale. En informática se llama LIFO, del inglés Last In, First Out. La analogía tiene un límite: cada «plato» de la pila de llamadas lleva escrito qué función es, dónde estaba y sus variables locales.

La pila de llamadas no es solo una idea para entender: la vas a ver escrita cada vez que algo falle dentro de una función. Si en calcularIVA escribieras Math.rond en vez de Math.round y ejecutaras el archivo con Node.js, el mensaje de error incluiría la pila en el momento del fallo, de arriba (la más reciente) abajo:

$ node tienda.js
TypeError: Math.rond is not a function
    at calcularIVA (/home/tu/tienda.js:2:15)
    at calcularTotal (/home/tu/tienda.js:5:15)
    at Object.<anonymous> (/home/tu/tienda.js:8:13)
    …(y algunas líneas internas de Node.js)

Se lee así: el error ocurrió en calcularIVA (línea 2, columna 15), que había sido llamada por calcularTotal (línea 5), que había sido llamada desde el programa principal (línea 8). Ese listado se llama traza de la pila (en inglés, stack trace), y aprenderás a leerlo para cazar errores en la Estación 12: Depuración. Qué es la pila por dentro, en la memoria de la computadora, lo verás en la Estación 22: Cómo se ejecuta el código.

Un adelanto: funciones que se llaman a sí mismas

Si una función puede llamar a cualquier otra, ¿puede llamarse a sí misma? Sí. Se llama recursión, y es una forma de repetir sin bucles: la función resuelve una parte pequeña del problema y le pide a otra copia de sí misma que resuelva el resto.

function cuentaAtras(n) {
  if (n === 0) {                // caso base: aquí se detiene
    console.log("¡Despegue!");
    return;
  }
  console.log(n);
  cuentaAtras(n - 1);           // se llama a sí misma con un número menor
}

cuentaAtras(3);   // 3, 2, 1, ¡Despegue!

Toda función recursiva necesita un caso base: una condición en la que ya no se llama a sí misma. Sin él, cada llamada apila un plato nuevo y la pila crece hasta que se acaba el espacio. En Chrome y en Node.js ese error se llama RangeError: Maximum call stack size exceeded («se superó el tamaño máximo de la pila de llamadas»); en Firefox, InternalError: too much recursion. Es lo que en inglés se conoce como stack overflow, el desbordamiento de pila que da nombre al famoso foro de preguntas de programación.

La recursión es una herramienta potente para problemas que se dividen en versiones más pequeñas de sí mismos (recorrer carpetas dentro de carpetas, por ejemplo), y la estudiarás a fondo en la Estación 20: Algoritmos. Diseñar con funciones: pequeñas, puras y con buen nombre

Ya sabes escribir funciones. La pregunta que queda es la que más importa en proyectos de verdad: ¿cómo decides qué funciones escribir? Un programa no se diseña línea por línea, sino tarea por tarea.

Funciones puras

Mira estas dos versiones de recibirDanio. Hacen «lo mismo», pero una es mucho más fácil de usar sin sorpresas:

Impura: depende de fuera y cambia cosas fuera

let vida = 100;

function recibirDanio(danio) {
  vida = vida - danio;
  console.log("Vida: " + vida);
}

Pura: solo usa lo que recibe

function recibirDanio(vida, danio) {
  return Math.max(0, vida - danio);
}

// Math.max(0, x) devuelve x,
// pero nunca menos de 0.

Una función pura cumple dos condiciones:

  1. Con las mismas entradas, siempre devuelve la misma salida. recibirDanio(100, 30) da 70 hoy, mañana y dentro de un año. No depende de variables globales, de la hora ni del azar.
  2. No tiene efectos secundarios. Un efecto secundario (en inglés, side effect) es cualquier cosa que la función cambia o provoca fuera de sí misma: modificar una variable global, imprimir en la consola, guardar un archivo, enviar datos por internet.

La versión de la izquierda falla las dos: su resultado depende de una global y, además, cambia esa global e imprime. La de la derecha es pura. ¿Por qué importa?

  • Se puede probar sola. Para comprobar que funciona, basta con llamarla y mirar lo que devuelve. En la Estación 26: Pruebas verás que las funciones puras son las más fáciles de probar automáticamente.
  • Se puede reutilizar. Sirve para el héroe, para el slime y para el jefe final, porque no está atada a ninguna variable concreta.
  • Se entiende leyendo solo su código. No tienes que buscar por todo el programa qué más le afecta.

Otros ejemplos de funciones impuras: una que usa Math.random() (cada llamada puede dar algo distinto) o una que depende de la fecha actual. No son «malas»: un programa que no imprime ni guarda nada no le sirve a nadie. La estrategia habitual es que la mayoría de las funciones sean puras (los cálculos, las reglas del juego) y que unas pocas, bien identificadas, se encarguen de lo impuro (mostrar, guardar, pedir datos). En la Estación 21: Paradigmas verás un estilo de programación entero construido sobre esta idea.

Reglas prácticas para escribir buenas funciones

  • Una función, una tarea. Si su nombre necesita «y», probablemente son dos.
  • Nombre con verbo, que diga qué hace y no cómo lo hace: calcularEnvio, no sumarCincuentaSiEsMenorQueDoscientos.
  • Corta. No hay un número mágico, pero si una función no cabe en la pantalla, suele estar haciendo demasiado.
  • Pocos parámetros. Hasta tres se manejan bien. Con más, crece el riesgo de pasarlos en otro orden; en la Estación 11 verás cómo agruparlos en un objeto.
  • Recibe por parámetros, entrega con return. Evita leer o cambiar variables globales.
  • Devuelve en vez de imprimir, salvo en las funciones cuyo trabajo es justamente mostrar (mostrarMenu, mostrarEstado).
  • Sal pronto de los casos especiales con un return al principio, y deja el caso normal al final.

En los equipos es habitual escribir encima de cada función importante un comentario que explica qué recibe y qué devuelve, con un formato llamado JSDoc. Los editores como VS Code lo leen y te lo muestran cuando pasas el ratón por encima de cualquier llamada a esa función:

/**
 * Calcula el daño de un ataque. Nunca devuelve menos de 1.
 * @param {number} ataque - Poder de ataque de quien golpea.
 * @param {number} defensa - Defensa de quien recibe el golpe.
 * @returns {number} Puntos de vida que se restan.
 */
function calcularDanio(ataque, defensa) {
  return Math.max(1, ataque - defensa);
}

La misma idea en otro lenguaje

Las funciones no son un invento de JavaScript: existen en todos los lenguajes de programación, con la misma estructura de entradas, cuerpo y salida. Así se escribe calcularDanio en Python, el lenguaje que aprenderás en la Estación 36. Cambia la palabra (def en vez de function), el cuerpo se marca con sangría en vez de llaves y los nombres se escriben con guion bajo, pero reconocerás cada pieza. Predice las tres líneas y ejecuta:

Parámetros, valor por defecto (critico=False), return: todo lo que aprendiste hoy se traslada casi palabra por palabra. Por eso aprender bien las funciones en un lenguaje te ahorra la mitad del trabajo en el siguiente.

Resumen

  • Una función es un bloque de código con nombre que hace una tarea. Se declara una vez y se llama con paréntesis (nombre()) cada vez que se necesita. Declarar no ejecuta nada.
  • Los parámetros son los huecos de la declaración; los argumentos, los valores de cada llamada. Se asignan por posición. Si faltan, valen undefined; si sobran, se ignoran.
  • Un valor por defecto (nivel = 1) se usa solo cuando el argumento falta o es undefined, no con null, 0 ni "".
  • return termina la función y entrega un valor: la llamada se reemplaza por ese valor. Sin return, la función devuelve undefined. console.log es para las personas; return, para el programa.
  • Las funciones son valores: se pueden guardar en constantes (expresiones y funciones flecha) y pasar a otras funciones (callbacks). Se pasa atacar, no atacar().
  • Flechas: sin llaves devuelven solas ((n) => n * 2); con llaves necesitan return.
  • Ámbito: global, de función y de bloque. Desde dentro se ve hacia fuera; desde fuera no se ve hacia dentro. Cada llamada crea variables locales nuevas.
  • var se escapa de los bloques, vale undefined antes de su línea y se puede redeclarar. Usa const y let. Las declaraciones function se pueden llamar antes de su línea; las flechas en const, no.
  • Un closure es una función que recuerda las variables del lugar donde nació, aunque esa función de fuera ya haya terminado. La pila de llamadas lleva la cuenta de qué función se ejecuta y adónde volver; la recursión (una función que se llama a sí misma) necesita un caso base.
  • Diseña con funciones pequeñas, con nombre de verbo y, siempre que puedas, puras: mismas entradas, misma salida, sin efectos secundarios.

Autoevaluación

Responde sin mirar arriba y, en las preguntas con código, predice antes de elegir. Si fallas alguna, lee la explicación: equivocarse aquí es la forma más barata de aprender.

En function saludar(nombre) { … } y la llamada saludar("Ana"), ¿qué es "Ana"?

  1. Un parámetro.

    El parámetro es nombre, el hueco de la declaración. "Ana" es lo que se pone en ese hueco.

  2. Un argumento.

    Correcto: es el valor concreto de esta llamada, y se guarda en el parámetro nombre antes de ejecutar el cuerpo.

  3. El valor de retorno.

    El valor de retorno es lo que la función entrega con return. "Ana" es lo que la función recibe.

  4. Una variable global.

    No se declaró ninguna variable: es un valor escrito directamente en la llamada.

Un programa tiene solo estas líneas. ¿Qué imprime?

function avisar() {
  console.log("¡Cuidado!");
}
  1. ¡Cuidado!

    Solo se imprimiría si alguna línea llamara a avisar().

  2. undefined

    No se imprime nada, ni siquiera undefined: no se ejecuta ningún console.log.

  3. Un error, porque la función no se usa.

    Declarar una función y no usarla es válido. No da error.

  4. Nada.

    Correcto: declarar una función no la ejecuta. Hace falta llamarla: avisar();.

¿Qué imprime este programa?

function doble(n) {
  console.log(n * 2);
}
const r = doble(4);
console.log(r);
  1. 8 y 8

    La función imprime 8, pero no lo devuelve, así que r no vale 8.

  2. Solo 8

    Se ejecutan dos console.log: el de dentro de la función y el de la última línea.

  3. 8 y después undefined

    Correcto: la función imprime 8 y, como no tiene return, devuelve undefined, que es lo que guarda r.

  4. undefined y después 8

    El orden es el de ejecución: primero corre doble(4), que imprime 8; después se imprime r.

Con function crearEnemigo(tipo = "slime") { return tipo; }, ¿qué devuelve crearEnemigo(null)?

  1. null

    Correcto: el valor por defecto solo se usa si el argumento falta o es undefined. null es un valor que alguien pasó a propósito.

  2. "slime"

    Eso pasaría con crearEnemigo() o con crearEnemigo(undefined), no con null.

  3. undefined

    Se pasó null, y JavaScript no lo convierte en undefined.

  4. Un error.

    Pasar null como argumento es válido.

¿Qué imprime console.log(triple(4)) si const triple = (n) => { n * 3 };?

  1. 12

    Sería 12 sin llaves: (n) => n * 3. Con llaves, el retorno implícito desaparece.

  2. undefined

    Correcto: con llaves, el cuerpo es un bloque normal y hace falta return. Sin él, la función devuelve undefined.

  3. Un error de sintaxis.

    La sintaxis es válida; el problema es que no devuelve nada. Por eso este error cuesta encontrarlo.

  4. NaN

    No se hace ninguna operación con el resultado: solo se imprime, y es undefined.

¿Qué pasa al ejecutar esto?

function empezar() {
  const vidas = 3;
}
empezar();
console.log(vidas);
  1. Imprime 3.

    vidas solo existe dentro de empezar, y además desaparece cuando la función termina.

  2. Imprime undefined.

    Una variable que no existe en ese ámbito no vale undefined: da error.

  3. ReferenceError: vidas is not defined

    Correcto: desde fuera no se ve lo que hay dentro de una función.

  4. Nada: la línea se ignora.

    JavaScript no ignora nombres desconocidos: lanza un error y detiene el programa.

¿Qué pasa al ejecutar esto?

if (true) {
  var a = 1;
  let b = 2;
}
console.log(a);
console.log(b);
  1. Da error en las dos últimas líneas.

    var no respeta los bloques, así que a sí existe fuera de las llaves.

  2. Imprime 1 y 2.

    let sí respeta el bloque: b no existe fuera.

  3. Imprime undefined y 2.

    a vale 1: la asignación ocurrió dentro del if, y var dejó escapar la variable con su valor. Y b no existe fuera.

  4. Imprime 1 y después da ReferenceError en la línea de b.

    Correcto: var se escapa del bloque; let, no.

¿Qué pasa con boton.addEventListener("click", atacar());?

  1. atacar se ejecuta una vez al leer esa línea, y los clics no hacen nada.

    Correcto: con paréntesis se ejecuta en ese momento, y al botón le llega su resultado (undefined), no la función.

  2. atacar se ejecuta en cada clic.

    Eso pasa con addEventListener("click", atacar), sin paréntesis.

  3. Da un error de sintaxis.

    La sintaxis es válida. El fallo es de lógica, y no aparece ningún mensaje de error: por eso cuesta encontrarlo.

  4. atacar se ejecuta dos veces por clic.

    No hay nada que haga que se ejecute dos veces. De hecho, con los clics no se ejecuta nunca.

¿Qué imprime la última línea?

function crearContador() {
  let cuenta = 0;
  return () => {
    cuenta++;
    return cuenta;
  };
}
const c1 = crearContador();
const c2 = crearContador();
c1();
c1();
console.log(c2());
  1. 3

    c1 y c2 no comparten cuenta: cada llamada a crearContador crea una nueva.

  2. 1

    Correcto: c2 tiene su propia cuenta, que empezaba en 0. Las dos llamadas a c1 no la tocan.

  3. 0

    c2() suma 1 antes de devolver la cuenta.

  4. Un error, porque cuenta ya no existe.

    La función interna recuerda cuenta aunque crearContador haya terminado: eso es un closure.

¿Cuál de estas funciones es pura?

  1. function sumarPuntos(p) { total = total + p; }

    Cambia una variable global: tiene un efecto secundario.

  2. function tirarDado() { return Math.floor(Math.random() * 6) + 1; }

    Llamada igual, puede devolver algo distinto cada vez. Una función pura siempre da lo mismo con las mismas entradas.

  3. function mostrarVida(v) { console.log("Vida: " + v); }

    Imprimir en la consola es un efecto secundario.

  4. function area(base, altura) { return base * altura; }

    Correcto: solo usa lo que recibe, siempre devuelve lo mismo con las mismas entradas y no cambia nada fuera.

¿Qué imprime este programa?

function buscar() {
  for (let i = 1; i <= 5; i++) {
    if (i === 3) {
      return i;
    }
    console.log(i);
  }
  return 0;
}
console.log(buscar());
  1. 1 2 3 4 5 y 0

    El return corta la función cuando i vale 3: el bucle no sigue.

  2. 1 y 2

    Falta una línea: el valor devuelto (3) también se imprime, con el console.log de fuera.

  3. 1, 2 y 3

    Correcto: dentro del bucle se imprimen 1 y 2; con i igual a 3, return sale de la función, y el 3 lo imprime el console.log de la última línea.

  4. 1, 2, 3 y 0

    Después de un return no se ejecuta nada más de la función, así que nunca se llega a return 0.

¿Qué imprime este programa?

console.log(doble(3));
function doble(n) {
  return n * 2;
}
  1. 6

    Correcto: las declaraciones de función están listas desde el principio de su ámbito (hoisting), así que se pueden llamar desde líneas anteriores.

  2. ReferenceError

    Eso pasaría si doble fuera una flecha guardada en const: no se puede usar antes de su línea.

  3. undefined

    La función ya está completa antes de la primera línea, así que devuelve 6.

  4. TypeError: doble is not a function

    Eso pasaría con una expresión de función guardada en var: la variable existe, pero vale undefined hasta su línea.

Glosario

Función
Bloque de código con nombre que hace una tarea. Se define una vez y se puede ejecutar muchas veces, con datos distintos.
Declaración de función
Forma clásica de crear una función: function nombre(parámetros) { … }. Se puede llamar incluso desde líneas anteriores.
Llamar (invocar) una función
Pedir que se ejecute su cuerpo, escribiendo su nombre seguido de paréntesis: saludar().
Parámetro
Variable escrita entre los paréntesis de la declaración. Es un hueco con nombre que recibe un valor en cada llamada.
Argumento
Valor concreto que se pasa en una llamada y se guarda en el parámetro correspondiente, según su posición.
return
Instrucción que termina una función y entrega un valor (el valor de retorno) al lugar donde se la llamó. Sin return, la función devuelve undefined.
Valor por defecto
Valor que toma un parámetro cuando el argumento falta o es undefined: function f(nivel = 1). En inglés, default parameter.
Expresión de función
Función escrita donde se espera un valor, por ejemplo guardada en una constante: const f = function () { … };.
Función anónima
Función sin nombre propio. Se usa guardándola en una variable o pasándola directamente a otra función.
Función flecha
Forma corta de escribir una función: (n) => n * 2. Sin llaves devuelve el resultado sola (retorno implícito). En inglés, arrow function.
Funciones de primera clase
Característica de lenguajes como JavaScript en los que una función es un valor: se puede guardar, pasar como argumento y devolver.
Callback
Función que se pasa como argumento a otra función para que esta la llame cuando corresponda, como en setTimeout(avisar, 2000).
Función de orden superior
Función que recibe otras funciones como argumentos o que devuelve una función.
Ámbito (scope)
Zona del programa donde una variable existe y se puede usar. Desde dentro se ve hacia fuera; desde fuera no se ve hacia dentro.
Ámbito global
Lo que está fuera de toda función y de todo bloque. Sus variables se ven desde cualquier parte del programa.
Ámbito de función (local)
Zona de los parámetros y variables declarados dentro de una función. Solo existen mientras se ejecuta esa llamada.
Ámbito de bloque
Zona entre llaves { } (de un if, un for…). Las variables declaradas ahí con let o const solo existen dentro.
Sombreado (shadowing)
Declarar dentro de un ámbito una variable con el mismo nombre que otra de fuera. La de dentro tapa a la de fuera mientras dura su ámbito.
Hoisting
Mecanismo por el que JavaScript registra las declaraciones de un ámbito antes de ejecutarlo. Por eso una declaración de función se puede llamar antes de su línea y var vale undefined antes de la suya.
Zona muerta temporal
Tramo entre el inicio de un bloque y la línea donde se declara una variable con let o const, en el que usarla da ReferenceError.
Closure (clausura)
Combinación de una función con las variables del lugar donde se creó, que puede seguir usando aunque la función que la rodeaba ya haya terminado.
Pila de llamadas
Registro con el que el intérprete sabe qué función se está ejecutando y adónde volver cuando termine. La última llamada en entrar es la primera en salir. En inglés, call stack.
Recursión
Técnica en la que una función se llama a sí misma. Necesita un caso base que la detenga; sin él, la pila de llamadas se desborda.
Función pura
Función que, con las mismas entradas, siempre devuelve la misma salida y no tiene efectos secundarios.
Efecto secundario
Cualquier cambio que una función provoca fuera de sí misma: modificar una variable global, imprimir, guardar un archivo, enviar datos.
