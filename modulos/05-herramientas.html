Lo que vas a lograr

Hasta ahora todo pasó dentro del navegador. Para crear apps y videojuegos de verdad necesitas un lugar de trabajo propio: un editor donde escribir el código, una terminal para darle órdenes a la computadora, Node.js para ejecutar JavaScript y Git para guardar puntos de control de tu trabajo. En esta estación vas a montar ese taller, paso a paso, y a perderle el miedo a la pantalla negra.

  • Escribir sin buscar los símbolos del programador ({ } [ ] | \ ` ~ @ #) en un teclado de España o de Latinoamérica, y entender qué es una tecla muerta.
  • Instalar Visual Studio Code en español, con guardado automático, formato al guardar y las sugerencias de IA desactivadas mientras aprendes.
  • Explicar qué es una terminal y qué es un shell, y distinguir bash, zsh, PowerShell, cmd, Git Bash y WSL.
  • Moverte por las carpetas con pwd, ls y cd, usando rutas absolutas y relativas, ., .. y ~.
  • Crear, leer, copiar, mover y borrar archivos y carpetas desde la terminal, sabiendo qué comandos no tienen vuelta atrás.
  • Instalar la versión LTS de Node.js, comprobarla con node --version y npm --version, y ejecutar un archivo .js.
  • Abrir la consola de las DevTools del navegador y usarla como calculadora de JavaScript.
  • Instalar y configurar Git, y crear tus primeros puntos de guardado con git init, git add, git commit y git log.
  • Resolver los problemas más comunes: comandos «no reconocidos», la política de ejecución de PowerShell, OneDrive y los espacios o acentos en las rutas.

Antes de empezar

Te conviene haber pasado por la Estación 2: Cómo funciona una computadora, donde viste qué son los archivos, las carpetas y el sistema operativo, y por la Estación 4: Pensamiento computacional, porque la terminal, igual que un algoritmo, hace exactamente lo que le escribes. En la Estación 3 ya abriste las DevTools del navegador: aquí usarás otra de sus pestañas.

Necesitas una computadora con Windows 10 u 11, macOS o Linux, conexión a internet y permiso para instalar programas. Con una tableta o un teléfono no se pueden instalar estas herramientas: puedes hacer toda la estación con la terminal de práctica del curso y dejar las instalaciones para cuando tengas una computadora. Es una estación larga. Hazla en dos o tres sesiones: por ejemplo, teclado y editor el primer día; terminal y archivos el segundo; Node.js y Git el tercero.

El mapa de tu taller

Programar es, sobre todo, escribir archivos de texto con instrucciones y pedirle a la computadora que las ejecute. Para eso bastaría con el Bloc de notas, pero sería como construir un mueble solo con un cuchillo de cocina: se puede, aunque vas a sufrir. Los programadores trabajan con un conjunto pequeño de herramientas que se repite en casi todas las empresas del mundo. Son las que vas a instalar hoy.

Para entenderlo

Piensa en un taller de carpintería. El editor es tu mesa de trabajo, donde das forma a las piezas. La terminal es el mostrador donde le pides cosas al encargado del taller, que es el sistema operativo. Node.js es la máquina que pone en marcha lo que construiste. Git es el cuaderno donde apuntas cómo quedó el mueble al final de cada día, para poder volver a esa versión. La analogía falla en algo importante: en un taller real el encargado entiende pedidos vagos; la computadora no. Solo acepta órdenes escritas exactamente como ella las espera.

Antes de instalar nada

Cinco minutos de preparación te ahorran horas de problemas:

  1. Averigua tu sistema operativo y su versión. En Windows: Configuración > Sistema > Información. En Mac: menú Apple > Acerca de esta Mac. En Linux: busca «Acerca de» en la configuración. Anótalo: las instrucciones cambian según el sistema.

  2. Comprueba que puedes instalar programas. Si la computadora es del trabajo o de un centro de estudios, puede que no te dejen. En ese caso pide ayuda al equipo de informática o usa la terminal de práctica del curso mientras tanto.

  3. Descarga solo de los sitios oficiales. Escribe tú la dirección en la barra del navegador en vez de hacer clic en el primer resultado de un buscador: a veces los primeros resultados son anuncios que imitan la página real y reparten versiones con virus. Las direcciones oficiales son code.visualstudio.com, nodejs.org y git-scm.com. En la Estación 3 aprendiste a leer el dominio real de una dirección: úsalo aquí.

  4. Decide dónde vivirán tus proyectos. Vas a crear una carpeta llamada proyectos dentro de tu carpeta personal, fuera de OneDrive, iCloud o Dropbox. Verás por qué en la sección Si algo falla. La crearás desde la terminal, más adelante.

  5. Abre un archivo de notas. Apunta cada cosa que instales y cada error que veas, copiado tal cual. Si te atascas, esas notas son lo primero que te pedirá quien te ayude.

Cómo leer las instrucciones de esta estación

Vas a ver muchos bloques como este, que muestran lo que se escribe en una terminal y lo que responde:

$ node --version
v24.21.0

El signo $ del principio no se escribe: indica «aquí empieza lo que tecleas tú». Lo que aparece debajo, sin $, es la respuesta de la computadora. Cuando algo cambia según el sistema operativo, lo verás en una tabla con una columna para Windows, otra para macOS y otra para Linux.

Consejo de oficio

Instalar y configurar herramientas es parte del trabajo, no un trámite previo. Los equipos profesionales dedican días enteros a preparar la computadora de cada persona nueva, y casi todos tienen un documento de «cómo montar tu entorno». Lo que hagas hoy es tu primera versión de ese documento.

El teclado del programador

El código usa símbolos que casi nunca escribes en un mensaje: llaves { } para agrupar instrucciones, corchetes [ ] para listas, la barra vertical |, la barra invertida \, la comilla invertida `, la virgulilla ~. En los teclados en español muchos de ellos están escondidos. Buscarlos cada vez corta tu concentración, así que vale la pena dedicar unos minutos a encontrarlos ahora.

Cómo leer una tecla

Una tecla puede tener hasta tres símbolos dibujados. Cuál sale depende de qué otra tecla mantengas pulsada:

AltGr es la tecla Alt que está a la derecha de la barra espaciadora (su nombre viene de Alternate Graphic, «gráfico alternativo»). No es lo mismo que la Alt de la izquierda. En Windows, si tu teclado no tiene AltGr, Ctrl + Alt hace lo mismo. En Mac, el papel de AltGr lo hace la tecla Opción (⌥).

¿Tu teclado es de España o de Latinoamérica?

Hay dos distribuciones de teclado en español muy extendidas, y los símbolos están en sitios distintos. Una distribución de teclado es el mapa que usa el sistema operativo para decidir qué carácter corresponde a cada tecla física. Para saber cuál tienes, mira la tecla que está a la derecha de la Ñ:

  • Si tiene dibujado { y [, es un teclado latinoamericano.
  • Si tiene dibujados los acentos ´ y ¨, y a su derecha hay una tecla con la Ç, es un teclado de España.

Lo importante es que el sistema operativo esté configurado con la misma distribución que tu teclado físico. Si no coinciden, las teclas escribirán símbolos distintos de los que tienen dibujados. En Windows lo revisas en Configuración > Hora e idioma > Idioma y región; en macOS, en Configuración del Sistema > Teclado > Fuentes de entrada; en Linux, en la sección de teclado o de región de la configuración.

Si usas Mac

En Mac las combinaciones cambian según la distribución elegida («Español», «Español - ISO» o «Latinoamericano»), así que no te damos una tabla que podría no coincidir con la tuya. Usa el Visor de teclado: haz clic en el menú de entrada de la barra de menús y elige Mostrar visor de teclado. Si no ves ese menú, actívalo en Configuración del Sistema > Teclado > Fuentes de entrada. Con el visor abierto, mantén pulsada Opción (y luego Opción + Mayús): el dibujo te muestra qué símbolo sale en cada tecla.

En Windows existe algo parecido: el teclado en pantalla. Ábrelo con Windows + Ctrl + O y pulsa sus teclas Mayús o AltGr para ver cómo cambian los símbolos.

Teclas muertas

Seguro te pasó: pulsas la tecla del acento y no aparece nada. Escribes una a y aparece á. Esa tecla es una tecla muerta (en inglés, dead key): no escribe nada por sí sola, sino que espera a la siguiente tecla para combinarse con ella. Es muy útil para escribir en español, pero en programación da sorpresas. Si quieres el símbolo solo, pulsa la tecla muerta y después la barra espaciadora.

Lo que querías y lo que salió

Querías:   `a`
Pulsaste:  `   a   `
Salió:     à
(y el último ` sigue esperando otra tecla)

Cómo se hace

`  y luego Espacio   →  `
a                    →  `a
`  y luego Espacio   →  `a`

En España son teclas muertas `, ^, ´, ¨ y la ~ de AltGr + 4. En el teclado latinoamericano lo son ´, ¨, ^ y `. Prueba el detector de abajo: haz clic en la caja de la vista previa y pulsa teclas. Cuando pulses una tecla muerta, el detector te lo dirá; mira qué aparece en la caja cuando pulses la siguiente.

No hace falta que entiendas el código: lo aprenderás en la Estación 15. Por ahora usa la vista previa. «Posición» es el nombre en inglés de la tecla física según un teclado estadounidense: por eso la Ñ aparece como Semicolon, que es lo que hay en ese lugar en un teclado de Estados Unidos.

«De repente mi teclado escribe otros símbolos»

Si tenías todo bien y de pronto las teclas escriben cosas raras (la Ñ pone ;, las comillas salen en otro sitio), casi seguro cambiaste de distribución sin querer. En Windows, Windows + Espacio y Alt + Mayús saltan entre las distribuciones instaladas. Mira el indicador de idioma junto al reloj y vuelve a la tuya. Si no usas otras distribuciones, puedes quitarlas en la configuración de idioma para que no vuelva a pasar.

Consejo de oficio

Algunas personas que programan mucho cambian su teclado a la distribución de Estados Unidos, donde llaves y corchetes están a un solo toque. No lo necesitas para este curso. Si algún día lo haces, recuerda que los dibujos de tus teclas ya no coincidirán con lo que escriben, y que la Ñ y los acentos se escriben de otra forma.

En la práctica tienes un ejercicio para cazar los diez símbolos. Hazlo hasta que te salgan sin mirar la tabla.

El editor: Visual Studio Code

Un editor de código es un programa para escribir archivos de texto pensado para programar. A diferencia de Word, guarda solo texto, sin formato oculto: el archivo contiene exactamente las letras que ves, que es lo que necesita la computadora. A diferencia del Bloc de notas, te ayuda: colorea las partes del código según lo que son (a eso se le llama resaltado de sintaxis), te sugiere palabras mientras escribes, marca errores, abre muchos archivos a la vez y trae una terminal dentro.

Vas a usar Visual Studio Code (también llamado VS Code), de Microsoft. Es gratuito, funciona en Windows, macOS y Linux, y es el editor más usado por quienes programan desde hace años. Lo que aprendas en él te sirve en casi cualquier empresa.

VS Code no es Visual Studio

Microsoft tiene otro programa con un nombre casi igual, Visual Studio (sin «Code»), mucho más pesado y pensado sobre todo para C# y C++. Si al descargar ves «Visual Studio Community» o un instalador que te pide elegir «cargas de trabajo», estás en el sitio equivocado. El que quieres se descarga desde code.visualstudio.com y su icono es azul.

La primera vez que lo abres

Si tu sistema operativo está en español, VS Code suele detectarlo y te ofrece instalar el paquete de idioma en español con una notificación abajo a la derecha. Acepta y reinicia VS Code cuando te lo pida. Si no aparece la notificación:

  1. Abre la paleta de comandos con Ctrl + Mayús + P (en Mac, Cmd + Mayús + P). Es un buscador de todas las acciones que VS Code sabe hacer.

  2. Escribe display y elige Configure Display Language.

  3. Elige Español (si no está instalado, VS Code lo descarga: es la extensión «Spanish Language Pack for Visual Studio Code», de Microsoft) y reinicia cuando te lo pida.

Desde ahora los menús están en español. Los nombres de los comandos se pueden buscar en español y también en inglés, algo útil cuando sigas un tutorial en inglés.

Las zonas de la ventana

VS Code publica una versión nueva cada semana, así que cualquier captura de pantalla envejece rápido. Lo que no cambia es la organización de la ventana en zonas:

  1. Barra de actividades. Los iconos de la izquierda cambian lo que muestra la barra lateral: Explorador (archivos), Buscar, Control de código fuente (Git), Ejecutar y depurar, y Extensiones.
  2. Barra lateral. Con el Explorador activo, muestra los archivos y carpetas de la carpeta que abriste.
  3. Editor. Donde escribes. Cada archivo abierto es una pestaña. Un círculo relleno en la pestaña significa «hay cambios sin guardar».
  4. Panel. Debajo del editor. Aquí vive la terminal integrada, una terminal dentro de VS Code que empieza en la carpeta de tu proyecto. Ábrela desde el menú Terminal > Nuevo terminal. En teclados en español, el atajo para mostrarla u ocultarla suele ser Ctrl + Ñ (en teclados de Estados Unidos es Ctrl + `); el menú Ver muestra junto a Terminal el atajo real de tu teclado.
  5. Barra de estado. Abajo del todo: en qué línea y columna está el cursor, el lenguaje del archivo y, si usas Git, en qué rama estás.
  6. Centro de comandos. Arriba, en la barra de título. Sirve para buscar archivos por nombre. Si escribes > al principio, se convierte en la paleta de comandos.

Abre carpetas, no archivos sueltos

Un proyecto es una carpeta con varios archivos dentro. Por eso en VS Code se trabaja abriendo la carpeta completa: Archivo > Abrir carpeta. Así el Explorador muestra todo el proyecto, la terminal integrada empieza en esa carpeta y las búsquedas recorren todos sus archivos.

La primera vez que abras una carpeta, VS Code te preguntará si confías en los autores de sus archivos. Esa función se llama confianza del área de trabajo (Workspace Trust): en una carpeta en la que no confías, VS Code desactiva lo que podría ejecutar código automáticamente. Responde que sí confías solo en las carpetas que creaste tú o que vienen de alguien de confianza.

Cuatro ajustes que te van a ahorrar disgustos

Abre la configuración con Ctrl + , (Cmd + , en Mac). Arriba hay un buscador: escribe el nombre del ajuste y cámbialo ahí mismo.

1. Guardado automático. El error más frecuente del primer mes es ejecutar un archivo que no guardaste y no entender por qué «no cambia nada». Busca files.autoSave y elige onFocusChange: VS Code guarda el archivo cada vez que el foco sale de él, por ejemplo cuando haces clic en la terminal para ejecutarlo. También existe afterDelay, que guarda un segundo después de que dejas de escribir. Es la opción que activa el menú Archivo > Guardado automático, pero tiene un inconveniente que verás en el punto siguiente.

2. Formato al guardar. Un formateador es una herramienta que ordena el aspecto del código: sangrías, espacios, comillas, saltos de línea. No cambia lo que el código hace, solo cómo se ve. El más usado en JavaScript se llama Prettier. Instálalo como extensión (lo ves en el apartado siguiente) y después activa estos dos ajustes: editor.formatOnSave (marcado) y editor.defaultFormatter (elige Prettier - Code formatter). Según la descripción oficial del ajuste, el formato no se aplica en los guardados automáticos «tras un retraso» (afterDelay), solo cuando guardas tú. Con onFocusChange no tienes ese problema.

3. Desactiva la IA mientras aprendes. Las versiones actuales de VS Code traen funciones de inteligencia artificial integradas: un chat y sugerencias en línea, que son fragmentos de código en gris que aparecen solos mientras escribes y que aceptas con Tab. Durante las líneas 1 y 2 del curso te pedimos que las apagues. Busca chat.disableAIFeatures y márcalo. Según la documentación de VS Code, este ajuste desactiva y oculta el chat y las sugerencias en línea, y desactiva las extensiones de Copilot. También puedes llegar a él desde el menú del chat, en la barra de título, con la opción Learn How to Hide AI Features.

Idea clave

No es una norma contra la IA: es una norma a favor de tu cerebro. Cuando una herramienta completa el código por ti, la sensación de «lo entiendo» aparece sin que lo hayas practicado, y la práctica es lo que construye la habilidad. En la Estación 1 viste por qué conviene usar la IA como tutora y no como piloto. En la Estación 37 aprenderás a programar con IA de forma profesional, cuando ya puedas juzgar lo que te propone. Para volver a activarla, desmarca el mismo ajuste.

4. El tamaño de letra. Busca editor.fontSize y súbelo hasta leer cómodo. Parece un detalle, pero vas a pasar muchas horas mirando esa pantalla.

Extensiones: pocas y de confianza

Una extensión es un complemento que añade funciones a VS Code, como las aplicaciones que instalas en un teléfono. Ábrelas con el icono de cuadraditos de la barra de actividades o con Ctrl + Mayús + X, busca por nombre y pulsa Instalar. Para esta etapa del curso necesitas solo dos:

ExtensiónPublicada porQué hace
Prettier - Code formatterPrettier (identificador esbenp.prettier-vscode)El formateador. Trae Prettier incluido, así que funciona sin instalar nada más.
ESLintMicrosoft (identificador dbaeumer.vscode-eslint)Un linter: un programa que revisa tu código en busca de errores probables y malas prácticas, y los subraya. Esta extensión usa el ESLint instalado en cada proyecto, así que no hará nada hasta que configures uno en la Estación 25. Instálala ya para tenerla lista.

Impacto

Una extensión es código de otra persona que se ejecuta en tu computadora, con acceso a tus archivos. Se han encontrado extensiones maliciosas en la tienda de VS Code que imitaban el nombre de otras populares. Antes de instalar una, mira quién la publica (las de editores verificados muestran una marca junto al nombre), cuántas descargas tiene y cuándo se actualizó. Instala solo las que necesites y borra las que ya no uses.

Tus ajustes como texto

Todo lo que cambias en la pantalla de configuración se guarda en un archivo de texto llamado settings.json. Puedes verlo con la paleta de comandos: escribe Abrir configuración de usuario (JSON) (en inglés, Preferences: Open User Settings (JSON)). Con los ajustes de esta sección, tendrá algo así:

{
  "files.autoSave": "onFocusChange",
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "chat.disableAIFeatures": true,
  "editor.fontSize": 16
}

Es un formato llamado JSON, que conocerás a fondo en la Estación 11. Fíjate en las comas: van entre cada ajuste, pero no después del último. Si lo editas a mano y te equivocas, VS Code subraya el error en rojo.

Consejo de oficio

Muchos equipos guardan un archivo de ajustes dentro de cada proyecto (en una carpeta .vscode) para que todas las personas formateen el código igual. Así nadie discute por espacios o comillas: lo decide Prettier.

La terminal: hablarle a la computadora por escrito

Hasta ahora has usado la computadora con el ratón: abres carpetas con doble clic, arrastras archivos, pulsas botones. Esa forma de uso se llama interfaz gráfica. Existe otra, más antigua y todavía imprescindible: escribir órdenes. Se llama línea de comandos (en inglés, command line interface o CLI), y el programa donde la usas es la terminal.

¿Por qué aprender algo que parece de otra época? Porque muchas herramientas de programación no tienen botones: Node.js, Git y miles de utilidades solo se usan escribiendo comandos. Porque los servidores donde se publican las apps casi nunca tienen pantalla. Y porque un comando se puede copiar, repetir y automatizar; una serie de clics, no.

Terminal y shell: dos piezas

La terminal es la ventana: recibe lo que tecleas y muestra texto. El shell (en inglés, «caparazón»; se pronuncia «shel») es el programa que vive dentro de esa ventana y entiende tus órdenes: las interpreta, pone en marcha el programa que corresponde y te muestra la respuesta. En la práctica mucha gente usa las dos palabras como sinónimos. Fíjate en lo que pasa cuando escribes un comando:

El prompt: la terminal te espera

Cuando la terminal está lista para recibir una orden, muestra un prompt (en inglés, «indicador»): un texto al principio de la línea que termina en un signo como $, % o >. Suele decirte quién eres, en qué computadora estás y en qué carpeta:

ShellEjemplo de prompt
bash en Linuxana@portatil:~$
zsh en macOSana@MacBook-de-Ana ~ %
Git Bash en Windowsana@PORTATIL MINGW64 ~ y, en la línea de abajo, $
PowerShell en WindowsPS C:\Users\Ana>
Terminal de práctica del cursotu@terminal:~$

El símbolo ~ que aparece en varios de ellos significa «tu carpeta personal». Lo verás en detalle en la próxima sección.

Anatomía de un comando

Un comando tiene hasta tres tipos de piezas, separadas por espacios:

$ ls -l fotos
  • El comando: el nombre del programa que quieres usar. Aquí, ls (de list, «listar»).
  • Las opciones (también llamadas flags, «banderas»): empiezan con - o -- y cambian cómo trabaja el comando. -l pide el formato largo, con tamaños y fechas.
  • Los argumentos: sobre qué actúa el comando. Aquí, la carpeta fotos.

Los espacios importan: ls -l es el comando ls con una opción, pero ls-l es un comando que no existe. Las mayúsculas también: los comandos se escriben en minúscula. Prueba el analizador de abajo. Cambia la línea entre comillas por otros comandos y observa cómo se separan las piezas.

Este analizador es una simplificación. Si pruebas git commit -m Hola verás que dice que commit y Hola son argumentos, pero en realidad commit es un subcomando de Git y Hola es el valor de la opción -m. Cada programa define sus propias reglas; la idea general, comando más opciones más argumentos, se mantiene.

Haz clic en la pantalla negra y escribe cada comando seguido de Enter:

  1. pwd para saber dónde estás.
  2. ls para ver qué hay aquí.
  3. ls fotos para mirar dentro de fotos sin entrar.
  4. cat notas.txt para leer el archivo de notas.

El silencio es buena señal

Muchos comandos no dicen nada cuando todo sale bien. Si escribes un comando y vuelve a aparecer el prompt sin ningún mensaje, normalmente es que funcionó. Los mensajes suelen aparecer cuando hay algo que contar o algo que falló.

«No se reconoce» o «command not found»

Si escribes algo que no es un comando, como hola, el shell responde con un error. En bash verás bash: hola: command not found (u «orden no encontrada»), en zsh zsh: command not found: hola y en PowerShell un mensaje que empieza por «El término 'hola' no se reconoce como nombre de un cmdlet…». Es la forma de decir «no conozco ningún programa con ese nombre». Revisa la ortografía, los espacios y las mayúsculas. Si el comando es de un programa que acabas de instalar, mira la sección Si algo falla.

Idea clave

Si un comando se queda trabajando y no te devuelve el prompt, pulsa Ctrl + C. En la terminal, esa combinación no copia: interrumpe el programa que está en marcha. Es el botón de emergencia de la terminal, y es seguro usarlo.

Moverte por las carpetas: rutas

En el explorador de archivos ves las carpetas y haces doble clic para entrar. En la terminal no hay ratón: tienes que decir por escrito dónde quieres ir. Para eso sirven las rutas. Una ruta (en inglés, path) es la dirección de un archivo o de una carpeta: el camino que hay que recorrer para llegar hasta ella, carpeta por carpeta.

El árbol y tu carpeta personal

Como viste en la Estación 2, las carpetas se organizan unas dentro de otras, como las ramas de un árbol puesto boca abajo. Arriba del todo está la raíz: en macOS y Linux se escribe /; en Windows, cada disco tiene la suya, como C:\. Dentro de la raíz, en algún lugar, está tu carpeta personal: la carpeta de tu usuario, donde viven tus documentos, tus descargas y, desde hoy, tus proyectos. En la terminal se abrevia con el símbolo ~.

DóndeTu carpeta personal (~)Una ruta de ejemplo

Windows, en Git Bash/c/Users/Ana/c/Users/Ana/proyectos/juego

Fíjate en la barra que separa las carpetas: Windows usa la barra invertida \ y los demás la barra normal /. PowerShell acepta las dos. En la web y en JavaScript siempre se usa /, así que acostúmbrate a ella.

Users y Usuarios

En un Windows en español, el explorador de archivos muestra la carpeta C:\Usuarios, pero su nombre real es C:\Users. Es solo una traducción en pantalla. En la terminal verás siempre el nombre real, Users. Algo parecido pasa en macOS con carpetas como Escritorio, que en la terminal se llama Desktop.

La carpeta actual

La terminal siempre está «dentro» de una carpeta: la carpeta actual (en inglés, working directory, «directorio de trabajo»). Es el punto de partida de todo lo que hagas: ls lista la carpeta actual, mkdir crea carpetas dentro de ella, node busca los archivos en ella. Cuando abres una terminal nueva, la carpeta actual es tu carpeta personal. pwd te dice cuál es, y el comando cd (de change directory, «cambiar de directorio») te mueve a otra. Rutas absolutas y relativas

Hay dos formas de escribir una ruta, igual que hay dos formas de explicar dónde vives:

  • Una ruta absoluta empieza desde la raíz: /home/ana/proyectos/juego. Es como dar la dirección completa con país, ciudad, calle y número: funciona desde cualquier lugar. En macOS y Linux empieza con /; en Windows, con la letra del disco, como C:\.
  • Una ruta relativa parte de la carpeta actual: juego, proyectos/juego o ../fotos. Es como decir «la segunda puerta a la derecha»: solo tiene sentido si sabes desde dónde se empieza.

Y hay tres atajos que vas a usar a diario:

Dos superpoderes: Tab y el historial

Autocompletar con Tab. Escribe las primeras letras de un archivo o carpeta y pulsa Tab: la terminal completa el nombre. Si hay varias opciones, no completa; en bash, pulsa Tab otra vez para ver la lista (la terminal de práctica la muestra a la primera). Usa Tab siempre: escribes menos y, sobre todo, no te equivocas de nombre. Si Tab no completa nada, es una pista de que ese nombre no existe donde estás.

El historial. La flecha ↑ recupera el comando anterior; púlsala varias veces para ir más atrás, y ↓ para volver. El comando history muestra la lista completa. En bash y zsh, Ctrl + R busca en el historial mientras escribes.

Espacios y mayúsculas en los nombres

El shell separa las piezas de un comando por los espacios. Por eso, si una carpeta se llama Mis juegos, el comando cd Mis juegos falla: el shell entiende dos argumentos, Mis y juegos. Hay dos soluciones: escribir el nombre entre comillas, cd "Mis juegos", o poner una barra invertida antes del espacio, cd Mis\ juegos (lo que hace Tab automáticamente). La mejor solución es no usar espacios en los nombres de tus proyectos: mis-juegos.

Con las mayúsculas, cada sistema se comporta distinto. Linux distingue Fotos de fotos: son dos carpetas diferentes. Windows y macOS, en su configuración normal, las consideran la misma. Como tus proyectos acabarán en servidores con Linux, escribe siempre los nombres exactamente igual y, mejor aún, todo en minúsculas.

  1. Entra en la carpeta niveles, que está en proyectos/juego/niveles. Puedes hacerlo en varios pasos o en uno.
  2. Desde niveles, llega a fotos/viajes con un solo comando cd y una ruta relativa. Pista: tienes que subir varios niveles con ...
  3. Vuelve a tu carpeta personal con cd ~.

Usa Tab para completar nombres y pwd si te pierdes. Si algo se complica, pulsa «Reiniciar».

Consejo de oficio

Antes de un comando que cambia o borra cosas, mira el prompt o escribe pwd. La mayoría de los desastres en la terminal no vienen de comandos raros, sino de comandos normales ejecutados en la carpeta equivocada.

Crear, leer, mover y borrar

Ya sabes moverte. Ahora vas a cambiar cosas: crear carpetas para tus proyectos, crear archivos, copiarlos, cambiarles el nombre y borrar lo que sobra. Todo lo que harías con el explorador de archivos, pero escrito. Cuando te acostumbres, vas a ser más rápido así, y además podrás repetir lo mismo en cualquier computadora copiando los comandos.

El símbolo > se llama redirección: en vez de mostrar el resultado de un comando en la pantalla, lo manda a un archivo. echo "Hola" escribe Hola en la terminal; echo "Hola" > saludo.txt no muestra nada, porque el texto fue a parar al archivo. Compruébalo con cat saludo.txt.

Los archivos ocultos son los que empiezan por un punto, como .git o .gitignore. No son secretos: el sistema los esconde para no llenar la vista con archivos de configuración. ls no los muestra; ls -a sí.

Para copiar una carpeta entera, en tu computadora se usa cp -r carpeta copia. La terminal de práctica no admite esa opción: en ella copia solo archivos.

No hay papelera

rm borra de verdad: el archivo no va a la papelera y no hay «deshacer». Con rm -r se va la carpeta entera con todo su contenido. Antes de borrar, mira con ls qué hay y con pwd dónde estás. En tu computadora, rm -i te pide confirmación archivo por archivo. Y nunca copies de internet un comando con rm -rf si no entiendes cada una de sus partes. Lo mismo vale para >: si el archivo ya existía, su contenido anterior desaparece.

Archivos de código creados con echo en PowerShell

En Windows PowerShell (la versión 5.1 que viene con Windows), > guarda el texto con una codificación llamada UTF-16, que Node.js no lee bien: un archivo .js creado así puede dar SyntaxError: Invalid or unexpected token aunque el código esté perfecto. Crea tus archivos de código con VS Code, o usa Git Bash, que guarda en UTF-8, la codificación estándar que viste en la Estación 2.

Abrir en VS Code desde la terminal

El comando code une tus dos herramientas. code . abre la carpeta actual en VS Code (recuerda: el punto es «la carpeta actual»). code notas.txt abre un solo archivo. El flujo más común de un día de trabajo empieza así:

$ cd ~/proyectos/juego
$ code .

Vas a montar la carpeta de un juego a partir de lo que tienes en Descargas:

  1. Crea una carpeta juego en tu carpeta personal y entra en ella.
  2. Crea dentro un archivo vacío index.html.
  3. Crea notas.txt con el texto Nivel 1: el bosque (usa echo y >).
  4. Crea una carpeta recursos dentro de juego.
  5. Mueve sprite.png desde Descargas a juego/recursos.
  6. Borra basura.tmp, que está en Descargas.

Antes de ejecutar comandos, hay que pensar en qué orden van. Ordena estos para conseguir lo siguiente: crear la carpeta recetas en tu carpeta personal, entrar, crear tortilla.txt con el texto «Huevos y papas», comprobar lo que quedó escrito y volver a tu carpeta personal.

  1. cd ~
  2. mkdir recetas
  3. cd recetas
  4. echo "Huevos y papas" > tortilla.txt
  5. cat tortilla.txt
  6. cd ..

Consejo de oficio

Pon nombres en minúscula, sin espacios, sin tildes ni eñes, y separa las palabras con guiones: mi-primer-juego, notas-clase-3.txt. Es la costumbre en casi todos los equipos. Te ahorra comillas en la terminal y problemas cuando esos archivos terminen en un servidor o en una dirección web. Y no olvides la extensión (.js, .html, .txt): le dice a VS Code, y a ti, qué tipo de archivo es.
