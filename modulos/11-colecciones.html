Lo que vas a lograr

Hasta ahora cada variable guardaba un solo dato. Pero un juego tiene decenas de enemigos, una tienda tiene cientos de productos y tu lista de tareas crece cada día. En esta estación vas a aprender las dos colecciones que usan todos los programas: los arrays, que guardan listas en orden, y los objetos, que guardan fichas con datos etiquetados. Y vas a aprender a transformarlas con unas pocas líneas, sin escribir bucles a mano.

  • Crear arrays, leer y cambiar sus elementos por su índice (que empieza en 0) y usar length.
  • Añadir, quitar y buscar elementos con push, pop, shift, unshift, splice, includes e indexOf, y distinguir slice de splice.
  • Recorrer una lista con for, for...of y forEach, y elegir el adecuado en cada caso.
  • Transformar datos con map, filter y reduce, buscar con find y findIndex, y comprobar con some y every.
  • Ordenar con sort sin caer en la trampa de los números y sin estropear el array original.
  • Crear objetos con propiedades y métodos, y leerlos con punto, con corchetes y con Object.keys, values y entries.
  • Trabajar con arrays de objetos y datos anidados, el formato de casi todos los datos reales, y protegerte de datos que faltan con ?..
  • Usar el operador spread (...) y la desestructuración para copiar, combinar y extraer datos.
  • Explicar la diferencia entre una referencia y una copia, y hacer copias profundas con structuredClone.
  • Convertir datos a texto JSON y de vuelta con JSON.stringify y JSON.parse.

Arrays: muchos datos bajo un solo nombre

Imagina que programas un juego de carreras con cinco corredores y quieres guardar el tiempo de cada uno. Con lo que sabes hasta ahora, escribirías algo así:

const tiempo1 = 62.4;
const tiempo2 = 58.9;
const tiempo3 = 71.2;
const tiempo4 = 60.5;
const tiempo5 = 65.7;

Con cinco corredores funciona. ¿Y con 200? ¿Y si la cantidad cambia en cada partida? ¿Cómo calculas el mejor tiempo sin escribir 200 comparaciones a mano? Necesitas una sola variable que guarde muchos valores en orden.

Un array es exactamente eso: un valor que guarda varios valores en fila. En español también se le llama arreglo o, de forma informal, lista. Se escribe entre corchetes [ ], con los valores separados por comas. Cada valor guardado se llama elemento.

const tiempos = [62.4, 58.9, 71.2, 60.5, 65.7];
const frutas = ["manzana", "pera", "uva"];
const vacio = [];   // un array sin elementos (todavía)

Para entenderlo

Piensa en un tren: tiene un solo nombre (el tren de la Línea 2) y varios vagones en fila, cada uno con su número. Para encontrar a alguien no das su dirección completa: dices «vagón 3». El array es el tren, los elementos son los vagones y el número del vagón es su posición. La analogía falla en un detalle importante: en un array, si quitas el primer vagón, todos los demás se renumeran solos. Lo verás en la próxima sección.

La posición de cada elemento se llama índice. Y aquí está la primera sorpresa: los índices empiezan en 0, igual que las posiciones de los caracteres de un texto que viste en la Estación 7. Mira qué pasa en la memoria:

Leer elementos y saber cuántos hay

Para leer un elemento escribes el nombre del array y, entre corchetes, su índice. Para saber cuántos elementos tiene usas length, igual que con los textos. length es una propiedad: un dato que viene pegado al valor y se lee con un punto.

const frutas = ["manzana", "pera", "uva"];
console.log(frutas[0]);                  // "manzana" (el primero)
console.log(frutas.length);              // 3 (cuántos elementos hay)
console.log(frutas[frutas.length - 1]);  // "uva" (el último)
console.log(frutas.at(-1));              // "uva" (también el último)
console.log(frutas[5]);                  // undefined (no existe)

La forma clásica de pedir el último elemento es frutas[frutas.length - 1]: si hay 3 elementos, el último está en la posición 2. Desde 2022 todos los navegadores modernos y Node.js tienen también at(), que acepta números negativos para contar desde el final: at(-1) es el último, at(-2) el penúltimo.

Cuidado

Pedir un índice que no existe no produce un error: produce undefined. Eso parece cómodo, pero es peligroso: el programa sigue con un undefined dentro y falla más tarde, lejos del verdadero problema. Cuando algo «sale undefined», revisa primero los índices. En la Estación 12 aprenderás a rastrear este tipo de fallos.

Cambiar un elemento

Para cambiar un elemento, asigna un valor nuevo a su posición, como harías con una variable:

const frutas = ["manzana", "pera", "uva"];
frutas[1] = "kiwi";
console.log(frutas);   // ["manzana", "kiwi", "uva"]

¿Cómo que se puede cambiar, si frutas es const? const impide que el nombre frutas pase a apuntar a otro array, pero no impide cambiar lo que hay dentro del array. Suena raro ahora; en la sección Referencias y copias entenderás exactamente por qué.

Antes de ejecutar este programa, predice las cinco líneas que va a imprimir. Escríbelas en un papel. Después pulsa «Ejecutar» y compara.

Si acertaste, ya dominas lo esencial: "verde", 3, el array con 'negro' en la primera posición, undefined (porque colores[3] no existe) y "verde" otra vez (el penúltimo). Fíjate en cómo la consola muestra el array: entre corchetes y con los textos entre comillas simples. Es solo su forma de mostrarlo, la misma que usa Node.js; en tu código puedes seguir usando comillas dobles.

Error común

Si asignas en una posición lejana, por ejemplo frutas[10] = "mango" en un array de 3, JavaScript rellena las posiciones 3 a 9 con huecos vacíos y length pasa a ser 11. La consola lo muestra como <7 empty items>. Casi nunca es lo que querías. Para añadir al final, usa push, que verás en la próxima sección.

Qué se puede guardar en un array

Cualquier cosa: números, textos, booleanos, otros arrays, objetos… incluso mezclados: ["Ana", 30, true, null] es un array válido. Pero que se pueda no significa que convenga.

Consejo de oficio

En un array guarda elementos del mismo tipo: una lista de nombres, una lista de precios, una lista de enemigos. Si quieres agrupar datos distintos que describen una sola cosa (el nombre, la edad y la ciudad de una persona), lo que necesitas es un objeto, que verás más adelante en esta estación. Así, cualquiera que lea tu código sabe qué esperar de cada elemento.

Un detalle que confunde: si preguntas el tipo de un array, typeof responde "object", porque en JavaScript los arrays son un tipo especial de objeto. Para saber si algo es un array de verdad, usa Array.isArray(valor), que devuelve true o false.

Añadir, quitar y buscar

Las listas de los programas cambian todo el tiempo: entran productos al carrito, llegan personas a una fila de espera, aparecen y desaparecen enemigos. Para eso los arrays traen incorporadas varias funciones propias. Una función que pertenece a un valor se llama método y se usa con un punto: frutas.push("kiwi"). Ya conoces algunos métodos de los textos, como toUpperCase().

Por los extremos: push, pop, unshift y shift

Cuatro métodos añaden o quitan elementos por los extremos del array. Míralos trabajar sobre una fila de personas que esperan su turno:

MétodoQué haceQué devuelve
push(x)Añade x al finalLa nueva longitud
pop()Quita el últimoEl elemento quitado
unshift(x)Añade x al principioLa nueva longitud
shift()Quita el primeroEl elemento quitado

Un mismo push puede añadir varios elementos a la vez: fila.push("Fer", "Gael"). Y lo que devuelven pop y shift es útil: puedes guardarlo para usarlo, por ejemplo const atendida = fila.shift(); para saber a quién le toca.

Guardar lo que devuelve push

let compra = ["pan", "leche"];
compra = compra.push("huevos");
console.log(compra);   // 3 ¡ya no es un array!

push ya cambia el array

const compra = ["pan", "leche"];
compra.push("huevos");
console.log(compra);   // ["pan", "leche", "huevos"]

Error común

Es muy común pensar que push devuelve el array con el elemento nuevo. No: modifica el array que ya tienes y devuelve un número, la nueva longitud. Si guardas ese resultado en la misma variable, pierdes tu lista.

¿Da igual por qué extremo?

Para la computadora, push y pop son muy rápidos. unshift y shift tienen que renumerar todos los elementos, así que con listas enormes (cientos de miles) se notan más lentos. Con las listas de esta estación no hay diferencia práctica. En la Estación 19 verás por qué pasa y qué estructuras se usan para filas de espera grandes.

¿Está en la lista? includes e indexOf

Para buscar un valor exacto hay dos métodos. includes responde sí o no. indexOf te dice en qué posición está, o -1 si no está.

const invitados = ["Ana", "Luis", "Marta"];
console.log(invitados.includes("Luis"));   // true
console.log(invitados.includes("luis"));   // false: mayúsculas distintas
console.log(invitados.indexOf("Marta"));   // 2
console.log(invitados.indexOf("Pedro"));   // -1: no está

// Patrón típico: añadir solo si no estaba
if (!invitados.includes("Pedro")) {
  invitados.push("Pedro");
}

Los dos comparan con ===, así que "Luis" y "luis" son valores distintos, igual que en la Estación 8. Si indexOf encuentra el valor varias veces, te da la primera posición.

Error común

Una trampa clásica: if (invitados.indexOf("Ana")) { … }. Ana está en la posición 0, y 0 es un valor falsy: el if cree que no está. Y si el valor no está, -1 es truthy: el if cree que sí. Justo al revés. Para preguntar «¿está?» usa includes, o compara explícitamente: indexOf(x) !== -1.

Cortar y pegar: slice y splice

Estos dos métodos tienen nombres casi iguales y hacen cosas muy distintas. Es una de las confusiones más frecuentes de JavaScript, así que vale la pena verlas juntas:

  • slice(inicio, fin) (en inglés, «rebanada») copia un trozo, desde inicio hasta antes de fin, como el slice de los textos. No toca el original.
  • splice(inicio, cuantos) (en inglés, «empalmar») quita cuantos elementos desde inicio, directamente del original, y te devuelve lo que quitó.

Una forma de recordarlo: slice es sacar una rebanada de una foto del pan (el pan sigue entero); splice es cirugía: corta y cose sobre el original. Además, splice puede insertar: los argumentos que pongas después de cuantos se meten en esa posición.

const letras = ["a", "b", "c", "d", "e"];
console.log(letras.slice(1, 3));   // ["b", "c"]
console.log(letras.slice(-2));     // ["d", "e"]: los dos últimos
console.log(letras.slice());       // una copia completa

letras.splice(1, 2);               // quita "b" y "c"  → ["a", "d", "e"]
letras.splice(1, 0, "x", "y");     // quita 0 e inserta → ["a", "x", "y", "d", "e"]
letras.splice(0, 1, "z");          // reemplaza el primero → ["z", "x", "y", "d", "e"]

De array a texto y de texto a array: join y split

Muchas veces un array tiene que convertirse en un texto para mostrarlo, o te llega un texto que quieres partir en trozos. join(separador) une los elementos en un texto; split(separador), que es un método de los textos, hace lo contrario.

const palabras = ["Aprender", "a", "programar"];
console.log(palabras.join(" "));   // "Aprender a programar"
console.log(palabras.join("-"));   // "Aprender-a-programar"
console.log(palabras.join());      // "Aprender,a,programar" (sin argumento usa comas)

const linea = "Ana;34;Lima";
const partes = linea.split(";");   // ["Ana", "34", "Lima"]
console.log(partes[1]);            // "34"
console.log("hola".split(""));     // ["h", "o", "l", "a"]: letra por letra

Cuidado

split siempre produce textos. En el ejemplo, partes[1] es el texto "34", no el número 34: si lo sumas, concatenará. Conviértelo con Number(partes[1]), como aprendiste en la Estación 7.

Recorrer una lista

Casi siempre querrás hacer algo con cada elemento: mostrar cada producto, sumar todos los precios, encontrar la puntuación más alta. Visitar los elementos uno por uno se llama recorrer (en inglés, iterate). En la Estación 9 recorriste textos con bucles; con arrays funciona igual, y tienes tres formas de hacerlo.

for clásico: cuando necesitas el índice

const tareas = ["Lavar platos", "Estudiar", "Pasear al perro"];
for (let i = 0; i < tareas.length; i++) {
  console.log(`${i + 1}. ${tareas[i]}`);
}
// 1. Lavar platos
// 2. Estudiar
// 3. Pasear al perro

La variable i toma los valores 0, 1 y 2: justo los índices válidos. La condición i < tareas.length hace que el bucle funcione con cualquier cantidad de tareas, aunque la lista crezca. Y i + 1 convierte la posición de la computadora (que empieza en 0) en el número que espera una persona (que empieza en 1).

Error común

Escribir i <= tareas.length en vez de i < tareas.length da una vuelta de más: en la última, tareas[3] no existe y se imprime 4. undefined. Es el error de «uno más o uno menos» que viste en la Estación 9, y con arrays aparece constantemente. Regla práctica: si empiezas en 0, la condición lleva <, nunca <=.

for...of: cuando solo necesitas cada elemento

for (const tarea of tareas) {
  console.log(tarea);
}

Se lee casi como una frase: «para cada tarea de tareas». En cada vuelta, tarea es el elemento siguiente; no hay índices que calcular, así que no hay forma de pasarse. Puedes usar const porque en cada vuelta se crea una variable nueva. Y como es un bucle normal, admite break y continue.

forEach: un método que recorre por ti

En la Estación 10 viste que una función puede recibir otra función como argumento; a esa función recibida se le llama callback. El método forEach recibe un callback y lo llama una vez por cada elemento, pasándole el elemento y su índice:

tareas.forEach((tarea, indice) => {
  console.log(`${indice + 1}. ${tarea}`);
});

(tarea, indice) => { … } es una función flecha con dos parámetros. Los nombres los eliges tú; lo que importa es el orden: el primero recibe el elemento y el segundo, su índice. Si no necesitas el índice, no lo escribas: tareas.forEach((tarea) => console.log(tarea));.

Cuidado

forEach no se puede detener: break no funciona dentro de un callback, y un return solo termina esa llamada, no el recorrido. Si necesitas parar al encontrar algo, usa for...of con break, o los métodos find y some de la próxima sección. Además, forEach siempre devuelve undefined: sirve para hacer algo con cada elemento, no para fabricar un array nuevo.

for...ofQuieres cada elemento y quizá parar antes con break. Es la opción más clara por defecto.for (const x of a)

Transformar con map, filter y reduce

Mira este patrón. Lo vas a necesitar una y otra vez:

const precios = [10, 25, 8];
const conIva = [];
for (const p of precios) {
  conIva.push(p * 1.16);
}

Crear un array vacío, recorrer, calcular algo con cada elemento y meterlo con push. Es tan común que los arrays traen métodos que hacen el bucle por ti. Tú solo dices qué hacer con cada elemento, con una función, y el método se encarga del cómo. El código queda más corto, pero sobre todo más fácil de leer: el nombre del método ya anuncia la intención.

Idea clave

Estos métodos se usan con funciones flecha cortas, así que conviene recordar una regla de la Estación 10: si una función flecha tiene una sola expresión sin llaves, devuelve su resultado automáticamente: (p) => p * 2 devuelve el doble de p. Si escribes llaves, necesitas return: (p) => { return p * 2; }. Esta diferencia causa muchísimos errores con map.

Estas son las tres «máquinas» más importantes. Fíjate en lo que entra y lo que sale de cada una:

map: transformar cada elemento

map crea un array nuevo del mismo largo, donde cada elemento es lo que devolvió tu función para el elemento original:

const precios = [10, 25, 8];
const dobles = precios.map((p) => p * 2);         // [20, 50, 16]
const etiquetas = precios.map((p) => `$${p}`);    // ["$10", "$25", "$8"]
const nombres = ["ana", "leo"].map((n) => n.toUpperCase());  // ["ANA", "LEO"]
console.log(precios);                              // [10, 25, 8]: sin cambios

En `$${p}`, el primer $ es un signo de dólar normal y ${p} inserta el valor. El callback de map también puede recibir el índice como segundo parámetro, igual que forEach: precios.map((p, i) => `${i + 1}: ${p}`).

Llaves sin return

const dobles = [1, 2, 3].map((n) => {
  n * 2;
});
console.log(dobles);
// [undefined, undefined, undefined]

Sin llaves, o con return

const dobles = [1, 2, 3].map((n) => n * 2);
// o bien:
const triples = [1, 2, 3].map((n) => {
  return n * 3;
});

Error común

El error de la izquierda es el más frecuente con map: con llaves, la función no devuelve nada salvo que escribas return, y «nada» es undefined. Si un map te llena el array de undefined, busca unas llaves sin return.

filter: quedarse con los que cumplen

filter crea un array nuevo solo con los elementos para los que tu función devuelve true. La función funciona como un portero: responde sí o no para cada elemento.

const edades = [12, 25, 17, 40, 16];
const adultos = edades.filter((edad) => edad >= 18);   // [25, 40]
const menores = edades.filter((edad) => edad < 18);    // [12, 17, 16]
const mayores100 = edades.filter((edad) => edad > 100); // []: ninguno cumple

Aunque solo cumpla un elemento, o ninguno, filter siempre devuelve un array. Si esperabas un único elemento, lo que buscas es find, que verás en un momento.

reduce: combinar todo en un solo valor

reduce recorre el array y va acumulando un resultado. Recibe dos cosas: una función y un valor inicial. La función recibe el acumulado hasta el momento y el elemento actual, y devuelve el nuevo acumulado.

Para entenderlo

Piensa en una alcancía que empieza con el valor inicial. En cada vuelta, la función mira lo que hay en la alcancía y el elemento que toca, y decide qué queda dentro. Al terminar, reduce te entrega lo que haya en la alcancía. La analogía se queda corta en algo: lo acumulado no tiene por qué ser una suma de dinero; puede ser un máximo, un texto, un array o un objeto.

const carrito = [12, 5, 8];
const total = carrito.reduce(
  (acumulado, precio) => acumulado + precio,
  0
);
console.log(total);

El valor inicial decide qué tipo de resultado vas a construir: 0 para sumas y cuentas, "" para unir textos, [] para construir un array, {} para un objeto. Aquí tienes otras reducciones típicas:

const notas = [7, 9, 4, 10];
const maxima = notas.reduce((max, n) => (n > max ? n : max), notas[0]);  // 10
const aprobadas = notas.reduce((cuenta, n) => (n >= 5 ? cuenta + 1 : cuenta), 0);  // 3

En la segunda, el acumulador es un contador: en cada vuelta devuelve el contador más uno si la nota aprueba, o el mismo contador si no. El operador ? : es el ternario que viste en la Estación 8.

Error común

Dos fallos típicos con reduce. El primero: olvidar el valor inicial. Sin él, reduce usa el primer elemento como acumulado inicial, y si el array está vacío lanza TypeError: Reduce of empty array with no initial value. El segundo: usar llaves sin return, igual que con map: el acumulado pasa a ser undefined y el resultado final, NaN. Escribe siempre el valor inicial.

Consejo de oficio

reduce es potente, pero no siempre es lo más legible. La propia documentación de MDN recomienda sopesar la claridad: si la función de reduce se vuelve larga o enrevesada, un for...of con un acumulador suele entenderse mejor. El objetivo es que otra persona entienda tu código a la primera, no escribirlo en una sola línea.

find y findIndex: el primero que cumple

includes e indexOf buscan un valor exacto. Cuando lo que tienes es una condición, usa find, que devuelve el primer elemento que la cumple (o undefined si ninguno), y findIndex, que devuelve su posición (o -1).

const usuarios = ["ana_22", "leo", "marta.dev", "sol"];
console.log(usuarios.find((u) => u.length > 4));        // "ana_22": el primero de más de 4 letras
console.log(usuarios.findIndex((u) => u.includes("."))); // 2
console.log(usuarios.find((u) => u === "zoe"));          // undefined: ninguno cumple

No confundas find con filter: filter devuelve todos los que cumplen, dentro de un array; find devuelve el primero, suelto, y deja de buscar en cuanto lo encuentra.

some y every: preguntas de sí o no

const notas = [8, 6, 9, 4];
console.log(notas.some((n) => n < 5));    // true: al menos una suspende
console.log(notas.every((n) => n >= 5));  // false: no todas aprueban

some («alguno») devuelve true si al menos un elemento cumple; every («todos»), solo si cumplen todos. Los dos paran en cuanto conocen la respuesta. Una curiosidad lógica: con un array vacío, every devuelve true (no hay nadie que incumpla) y some, false.

Encadenar métodos

Como map y filter devuelven arrays, puedes llamar a otro método directamente sobre su resultado. Se llama encadenar, y se escribe una operación por línea para que se lea de arriba abajo, como una receta:

const pedidos = [120, 45, 300, 80];
const total = pedidos
  .filter((p) => p >= 100)          // [120, 300]: solo los grandes
  .map((p) => p + 10)               // [130, 310]: sumar el envío
  .reduce((suma, p) => suma + p, 0); // 440
console.log(total);

Ordena este programa, que hace lo mismo pero guardando cada paso en una constante. Piensa qué necesita cada línea que exista antes:

  1. const pedidos = [120, 45, 300, 80];
  2. const grandes = pedidos.filter((p) => p >= 100);
  3. const conEnvio = grandes.map((p) => p + 10);
  4. const total = conEnvio.reduce((suma, p) => suma + p, 0);
  5. console.log(total);

Ordenar con sort (y su trampa)

sort ordena un array. Con textos simples hace lo que esperas:

const nombres = ["Olga", "Ana", "Tomás"];
nombres.sort();
console.log(nombres);   // ["Ana", "Olga", "Tomás"]

Con números, en cambio, hace algo que sorprende a todo el mundo la primera vez. Pruébalo:

Sin argumentos, sort convierte cada elemento en texto y los compara carácter por carácter, como en un diccionario. Por eso "100" va antes que "25": su primer carácter, "1", va antes que "2". Para ordenar números tienes que darle una función de comparación (en inglés, comparator), que recibe dos elementos a y b y devuelve:

Si la función devuelve…sort entiende que…
Un número negativoa va antes que b
Un número positivob va antes que a
0Son equivalentes: se quedan en el orden en que estaban

(a, b) => a - b cumple exactamente eso: si a es menor, la resta es negativa y a va primero. Para el orden inverso, b - a. Desde 2019, el estándar de JavaScript garantiza que sort es estable: los elementos que la función considera iguales conservan su orden original.

Con textos que tienen tildes o mayúsculas, el orden por defecto también falla: ["banana", "Manzana", "árbol"].sort() da ["Manzana", "banana", "árbol"], porque las mayúsculas y las letras acentuadas tienen códigos distintos. Para ordenar como en un diccionario español usa localeCompare, un método de los textos que compara según las reglas de un idioma:

const palabras = ["banana", "Manzana", "árbol", "cereza"];
palabras.sort((a, b) => a.localeCompare(b, "es"));
console.log(palabras);   // ["árbol", "banana", "cereza", "Manzana"]

sort modifica el original

A diferencia de map y filter, sort ordena el array en su sitio y devuelve ese mismo array. Si escribes const ordenados = numeros.sort(…), ordenados y numeros son el mismo array, ya desordenado para siempre. Para conservar el original usa toSorted, que devuelve una copia ordenada (disponible en todos los navegadores modernos desde 2023 y en Node.js desde la versión 20; compruébala con node --version), o copia primero con numeros.slice().sort(…). reverse, que invierte el orden, también modifica el original; su versión que copia es toReversed.

Objetos: fichas con datos etiquetados

Supón que quieres guardar los datos de un personaje. Con un array quedaría así: ["Lyra", "maga", 7, 240]. ¿Qué es el 7? ¿Y el 240? Tendrías que recordar qué significa cada posición, y si un día cambias el orden, todo tu programa se rompe. Cuando varios datos distintos describen una sola cosa, lo que necesitas es ponerle un nombre a cada dato.

Un objeto agrupa datos con nombre. Se escribe entre llaves { } con pares clave: valor separados por comas. Cada par es una propiedad: la clave es su nombre y el valor puede ser cualquier cosa: un número, un texto, un booleano, un array, otro objeto o incluso una función.

const personaje = {
  nombre: "Lyra",
  clase: "maga",
  nivel: 7,
  vida: 240,
  vivo: true,
};

Para entenderlo

Un objeto es como la ficha de un personaje en un juego de rol, o como un formulario ya rellenado: cada campo tiene una etiqueta y un contenido. A diferencia de un formulario impreso, puedes añadir y quitar campos en cualquier momento.

La coma después de la última propiedad (vivo: true,) es opcional en JavaScript. Muchos equipos la escriben siempre, porque así añadir una propiedad nueva solo cambia una línea. Recuerda este detalle: en JSON, al final de la estación, esa coma está prohibida.

Leer propiedades: punto y corchetes

Hay dos formas de leer una propiedad. La más común es el punto; la otra, los corchetes con la clave como texto:

console.log(personaje.nombre);      // "Lyra"
console.log(personaje["clase"]);    // "maga"
console.log(personaje.mana);        // undefined: esa propiedad no existe

Igual que con los índices de un array, leer una propiedad que no existe no da error: da undefined. Los corchetes son imprescindibles en dos casos: cuando la clave está guardada en una variable y cuando la clave tiene espacios, guiones u otros caracteres que no valen en un nombre de variable.

const campo = "nivel";
console.log(personaje[campo]);   // 7: usa el VALOR de campo, que es "nivel"
console.log(personaje.campo);    // undefined: busca una propiedad llamada "campo"

const ficha = { "nombre completo": "Lyra Vento", "fecha-alta": "2026-09-01" };
console.log(ficha["nombre completo"]);   // "Lyra Vento"

Error común

personaje.campo no mira qué hay dentro de la variable campo: busca, literalmente, una propiedad que se llame «campo». Cuando la clave está en una variable (porque la eligió la persona usuaria o viene de un bucle), usa siempre corchetes: personaje[campo].

Añadir, cambiar y borrar propiedades

personaje.arma = "báculo";         // añadir: no existía, ahora sí
personaje.vida -= 35;              // cambiar: 240 - 35 = 205
delete personaje.vivo;             // borrar la propiedad entera
console.log("vivo" in personaje);  // false: ya no existe
console.log("arma" in personaje);  // true

Asignar a una propiedad que no existe la crea; asignar a una que existe la cambia. El operador delete borra una propiedad, y el operador in responde si una clave existe en el objeto. Y sí: personaje es const y aun así cambió por dentro, igual que pasaba con los arrays.

Hay un atajo muy usado: si tienes variables con el mismo nombre que las claves que quieres, basta con escribir el nombre una vez.

const nombre = "Kai";
const nivel = 3;
const heroe = { nombre, nivel };   // igual que { nombre: nombre, nivel: nivel }
console.log(heroe);                // { nombre: 'Kai', nivel: 3 }

Métodos y this

Una propiedad cuyo valor es una función se llama método. Ya usaste muchos: push es un método de los arrays y toUpperCase, de los textos. Tú también puedes crearlos:

const personaje = {
  nombre: "Lyra",
  vida: 240,
  recibirGolpe(danio) {
    this.vida -= danio;
    return `${this.nombre} recibe ${danio} de daño. Vida: ${this.vida}`;
  },
};
console.log(personaje.recibirGolpe(35));  // "Lyra recibe 35 de daño. Vida: 205"

recibirGolpe(danio) { … } es la forma corta de escribir recibirGolpe: function (danio) { … }; las dos funcionan. El parámetro se llama danio, sin ñ: JavaScript acepta la ñ en los nombres, pero la costumbre en los equipos es evitar tildes y eñes en el código.

Dentro de un método, la palabra this se refiere al objeto que está antes del punto en la llamada. En personaje.recibirGolpe(35), this es personaje, así que this.vida es su vida. ¿Por qué no escribir directamente personaje.vida? Funcionaría, pero this hace que el método sirva aunque cambies el nombre de la variable o copies el método a otro objeto. Con las clases de la Estación 21, donde fabricarás muchos personajes con los mismos métodos, this será imprescindible.

Método con función flecha

const gato = {
  nombre: "Michi",
  saludar: () => `Soy ${this.nombre}`,
};
console.log(gato.saludar());
// "Soy undefined"

Método con la forma corta

const gato = {
  nombre: "Michi",
  saludar() { return `Soy ${this.nombre}`; },
};
console.log(gato.saludar());
// "Soy Michi"

Error común

Las funciones flecha no tienen su propio this: usan el de fuera del objeto, que no es el objeto. Según dónde se ejecute el código, verás undefined o incluso un error. Regla sencilla: para escribir métodos, usa la forma corta nombre() { … }; guarda las flechas para los callbacks de map, filter y compañía.

Recorrer un objeto: Object.keys, values y entries

Un objeto no tiene índices, así que no puedes recorrerlo con un for clásico. En su lugar, tres funciones convierten sus partes en arrays, y con los arrays ya sabes hacer de todo:

const stats = { fuerza: 12, agilidad: 8, magia: 15 };
console.log(Object.keys(stats));     // ["fuerza", "agilidad", "magia"]
console.log(Object.values(stats));   // [12, 8, 15]
console.log(Object.entries(stats));  // [["fuerza", 12], ["agilidad", 8], ["magia", 15]]

const totalPuntos = Object.values(stats).reduce((s, v) => s + v, 0);   // 35
for (const par of Object.entries(stats)) {
  console.log(`${par[0]}: ${par[1]}`);   // "fuerza: 12", luego "agilidad: 8"…
}

Object.entries devuelve un array de pares, y cada par es un array pequeño [clave, valor]: por eso par[0] es la clave y par[1], el valor. En la sección de desestructuración verás una forma más cómoda de escribirlo.

¿En qué orden salen las claves?

En el orden en que las añadiste, con una excepción: las claves que parecen números enteros ("1", "20") salen primero, ordenadas de menor a mayor. Si el orden importa de verdad, guarda los datos en un array. Existe también for...in para recorrer claves, pero puede incluir propiedades heredadas (lo entenderás en la Estación 21); Object.keys y Object.entries son más predecibles.

Los productos de una tienda, los mensajes de un chat, los enemigos de un nivel, las canciones de una lista de reproducción, las filas de una hoja de cálculo. Casi todos los datos que vas a manejar en tu vida profesional tienen esta forma. Preguntas a los datos

Con map, filter, find, reduce y sort puedes contestar casi cualquier pregunta sobre el catálogo. Cada callback recibe un producto entero, que aquí se llama p:

// Los nombres de todos los productos (map)
const nombres = productos.map((p) => p.nombre);
// ["Teclado", "Ratón", "Auriculares", "Monitor", "Altavoz"]

// Solo los que hay en stock (filter)

// Cuánto vale todo el inventario (reduce)

// Del más barato al más caro, sin tocar el original (toSorted)
const porPrecio = productos.toSorted((a, b) => a.precio - b.precio);

// Por nombre, en orden alfabético español

Cuando falta un dato: el encadenamiento opcional ?.

Los datos reales vienen incompletos. Algunas personas no escribieron su dirección; algunos productos no tienen foto. Mira qué pasa:

const usuarios = [
  { nombre: "Ana", direccion: { ciudad: "Quito" } },
  { nombre: "Beto" },   // sin dirección
];
console.log(usuarios[1].direccion);          // undefined
console.log(usuarios[1].direccion.ciudad);
// TypeError: Cannot read properties of undefined (reading 'ciudad')

usuarios[1].direccion vale undefined, y pedirle una propiedad a undefined es un error que detiene el programa. Es uno de los errores más frecuentes de JavaScript; en la Estación 12 aprenderás a leerlo con calma. La solución es el encadenamiento opcional ?. (en inglés, optional chaining): si lo que está a su izquierda es null o undefined, se detiene ahí y da undefined en lugar de fallar.

console.log(usuarios[1].direccion?.ciudad);                  // undefined, sin error
console.log(usuarios[0].direccion?.ciudad);                  // "Quito"
console.log(usuarios[1].direccion?.ciudad ?? "Sin ciudad");  // "Sin ciudad"

Combinado con ??, que viste en la Estación 8, te da un valor por defecto cuando el dato falta. También funciona con corchetes y con llamadas: lista?.[0] y objeto.metodo?.(). Lo que no puedes hacer es asignar a través de él: usuario.direccion?.ciudad = "Lima" es un error de sintaxis.

Consejo de oficio

No llenes tu código de ?. «por si acaso». Úsalo donde es normal que el dato falte (una dirección opcional). Si un dato debería estar siempre y no está, es mejor que el programa falle en voz alta: así descubres el problema en lugar de esconderlo.

Spread y desestructuración

Hay dos formas de escribir que vas a encontrar en todo el código moderno de JavaScript, y sobre todo en React (Estación 32). Las dos sirven para mover datos entre arrays, objetos y variables con muy poco código. Al principio parecen jeroglíficos; con cuatro ejemplos se vuelven naturales.

Spread: desplegar los elementos con ...

El operador spread (en español, «propagación» o «esparcir») se escribe con tres puntos, ..., y despliega el contenido de un array allí donde lo pongas, como si hubieras escrito los elementos uno por uno:

const frutas = ["pera", "uva"];
const verduras = ["papa", "zanahoria"];

const copia = [...frutas];                  // ["pera", "uva"]: un array NUEVO
const todo = [...frutas, ...verduras];      // ["pera", "uva", "papa", "zanahoria"]
const conKiwi = [...frutas, "kiwi"];        // añade al final sin modificar frutas
const conMango = ["mango", ...frutas];      // añade al principio sin modificar frutas
console.log(Math.max(...[3, 9, 4]));        // 9: los elementos pasan como argumentos sueltos

Con objetos funciona igual: { ...objeto } copia todas sus propiedades en un objeto nuevo. Si después escribes otras propiedades, se añaden, y si alguna clave se repite, gana la que está más a la derecha:

const base = { nombre: "Kai", vida: 100, nivel: 1 };
const subido = { ...base, nivel: 2 };       // copia todo y cambia nivel
const armado = { ...base, arma: "arco" };   // copia todo y añade arma
console.log(base.nivel, subido.nivel);      // 1 2: base no cambió
console.log({ nivel: 9, ...base }.nivel);   // 1: base va después y pisa el 9

Idea clave

Con spread puedes «cambiar» un array u objeto sin tocar el original: creas uno nuevo con el cambio. [...lista, nuevo] en lugar de lista.push(nuevo); { ...ficha, vida: 50 } en lugar de ficha.vida = 50. Enseguida verás por qué eso importa tanto.

Desestructuración: sacar datos en variables

La desestructuración (en inglés, destructuring) hace lo contrario: saca valores de un array o de un objeto y los guarda en variables, en una sola línea. Se reconoce porque los corchetes o las llaves aparecen a la izquierda del =.

Con arrays, los valores se asignan por posición:

const podio = ["Nia", "Leo", "Mar", "Tom"];
const [oro, plata, bronce] = podio;    // oro = "Nia", plata = "Leo", bronce = "Mar"
const [ganador, ...resto] = podio;     // ganador = "Nia", resto = ["Leo", "Mar", "Tom"]

let a = 1;
let b = 2;
[a, b] = [b, a];                       // intercambio: ahora a = 2 y b = 1

Con objetos, se asignan por nombre de clave, así que el orden da igual:

const personaje = { nombre: "Lyra", clase: "maga", nivel: 7 };
const { nombre, nivel } = personaje;        // nombre = "Lyra", nivel = 7
const { clase: oficio } = personaje;        // guarda personaje.clase en una variable llamada oficio
const { mascota = "ninguna" } = personaje;  // valor por defecto: la clave no existe
const { nombre: n, ...otros } = personaje;  // n = "Lyra", otros = { clase: "maga", nivel: 7 }

Los mismos tres puntos, dos trabajos

A la derecha del = o dentro de un array u objeto que estás creando, ... despliega (spread). A la izquierda del =, en una desestructuración, o en los parámetros de una función, ... recoge lo que sobra en un array u objeto nuevo; en ese papel se llama rest («el resto»). Mira de qué lado del = está.

Donde más brilla la desestructuración es en los parámetros de las funciones y de los callbacks. Compara:

// Sin desestructurar
const etiquetas = productos.map((p) => `${p.nombre}: $${p.precio}`);

// Desestructurando el objeto que llega como parámetro
const etiquetas2 = productos.map(({ nombre, precio }) => `${nombre}: $${precio}`);

// Recorrer Object.entries con los pares ya separados
const stats = { fuerza: 12, agilidad: 8 };
for (const [clave, valor] of Object.entries(stats)) {
  console.log(`${clave}: ${valor}`);
}

Predice cada línea antes de ejecutar. La última usa desestructuración directamente en los parámetros de una función.

Referencias y copias

Esta sección explica la sorpresa más frecuente de JavaScript. Quieres probar un cambio en una copia de tu lista, y al final también cambió la original:

const original = ["espada", "escudo"];
const copia = original;
copia.push("antorcha");
console.log(original);   // ["espada", "escudo", "antorcha"] ¿¡Qué!?

No es un error de JavaScript: es cómo funciona la memoria. Con los valores primitivos (números, textos, booleanos, undefined y null, los tipos de la Estación 7), asignar una variable a otra copia el valor:

let x = 5;
let y = x;    // y recibe una copia del 5
y = 10;
console.log(x);   // 5: x no se enteró

Los arrays y los objetos, en cambio, se guardan una sola vez en la memoria, y la variable guarda una referencia: la indicación de dónde está ese array u objeto. Recuerda la analogía de la etiqueta de la Estación 7: una variable es una etiqueta pegada a un valor. Con un array, const copia = original no fabrica otro array; pega una segunda etiqueta en la misma caja.

Cambiar el contenido de un array u objeto que ya existe se llama mutar. push, pop, splice, sort, asignar lista[0] = … o ficha.vida = … y delete son mutaciones. Cualquier variable que tenga una referencia a ese array u objeto verá el cambio.

const no congela el contenido

Ahora puedes entender lo que quedó pendiente al principio de la estación. const protege la etiqueta, no la caja: no puedes despegar la etiqueta y pegarla en otra caja, pero sí puedes cambiar lo que hay dentro.

const lista = [1, 2];
lista.push(3);     // permitido: cambias el contenido de la caja
lista = [9, 9];    // TypeError: Assignment to constant variable.

Si quieres que el contenido tampoco pueda cambiar, existe Object.freeze; lo verás junto con la inmutabilidad en la Estación 21.

Comparar arrays y objetos

console.log([1, 2] === [1, 2]);   // false: son dos arrays distintos
const a = [1, 2];
const b = a;
console.log(a === b);             // true: es el mismo array

Para saber si dos arrays sencillos tienen el mismo contenido, compara elemento por elemento: a.length === c.length && a.every((x, i) => x === c[i]).

Las funciones también pueden mutar

Cuando pasas un array u objeto a una función, la función recibe la referencia. Si lo muta, cambia el original:

function subirNivel(personaje) {
  personaje.nivel++;              // muta el objeto que le pasaron
}
const heroe = { nombre: "Kai", nivel: 1 };
subirNivel(heroe);
console.log(heroe.nivel);         // 2: la función cambió el original

// Alternativa sin mutar: devolver un objeto nuevo
function conNivelSubido(personaje) {
  return { ...personaje, nivel: personaje.nivel + 1 };
}
const heroe2 = conNivelSubido(heroe);   // heroe no cambia; heroe2 tiene nivel 3

Consejo de oficio

Muchos equipos prefieren funciones que no mutan lo que reciben, sino que devuelven datos nuevos: son las funciones puras que conociste en la Estación 10, y la Estación 21 las estudia a fondo. Son más fáciles de probar y de razonar. React, por ejemplo, exige crear arrays y objetos nuevos en vez de mutar los que tienes; si no, la pantalla no se actualiza.

Copia superficial y copia profunda

[...lista], lista.slice() y { ...objeto } crean una copia superficial (en inglés, shallow copy): una caja nueva por fuera, pero si dentro hay otros arrays u objetos, esos siguen siendo compartidos.

const partida = { jugador: "Mira", inventario: ["espada", "escudo"] };
const copia = { ...partida };
copia.jugador = "Otra";            // no afecta: jugador es un texto (primitivo)
copia.inventario.push("mapa");     // ¡afecta! inventario es el mismo array
console.log(partida.inventario);   // ["espada", "escudo", "mapa"]

Para copiar todos los niveles necesitas una copia profunda (deep copy). La forma moderna es structuredClone, disponible en todos los navegadores modernos desde 2022 y en Node.js desde la versión 17:

const partida = { jugador: "Mira", inventario: ["espada", "escudo"] };
const segura = structuredClone(partida);
segura.inventario.push("brújula");
console.log(partida.inventario.length);   // 2: el original no cambió
console.log(segura.inventario.length);    // 3

Lo que structuredClone no copia

No puede copiar funciones: si el objeto tiene un método, lanza un error (DataCloneError). Y los objetos creados con clases (Estación 21) se copian como objetos normales, sin sus métodos. Para datos (números, textos, arrays, objetos, fechas, Map y Set) funciona perfectamente. En código antiguo verás el truco JSON.parse(JSON.stringify(x)), que también copia en profundidad pero pierde más cosas por el camino (lo entenderás en la próxima sección); hoy es mejor structuredClone.

JSON: guardar y enviar datos

Todo lo que has creado en esta estación vive en la memoria RAM, y en la Estación 2 viste que la RAM se borra cuando el programa termina. ¿Cómo guardas la partida de un juego para seguirla mañana? ¿Cómo le mandas tu carrito de compras a un servidor que está al otro lado del mundo? En los dos casos necesitas convertir tus arrays y objetos en texto, porque el texto sí se puede guardar en un archivo o enviar por internet.

JSON (siglas de JavaScript Object Notation, «notación de objetos de JavaScript») es un formato de texto para datos que se parece mucho a los objetos y arrays que ya conoces. Nació de JavaScript, pero hoy lo entienden prácticamente todos los lenguajes: es el idioma común de los datos en la web.

De datos a texto: JSON.stringify

Convertir datos en texto para guardarlos o enviarlos se llama serializar. En JavaScript se hace con JSON.stringify:

const partida = { jugador: "Mira", nivel: 3, inventario: ["espada", "escudo"] };
const texto = JSON.stringify(partida);
console.log(texto);          // {"jugador":"Mira","nivel":3,"inventario":["espada","escudo"]}
console.log(typeof texto);   // "string": ya no es un objeto, es texto
console.log(JSON.stringify(partida, null, 2));   // lo mismo, con saltos de línea y sangría de 2 espacios

El segundo argumento (null) sirve para filtrar qué se incluye; casi siempre lo dejarás en null. El tercero es la sangría: con 2, el resultado queda legible para personas, ideal para archivos y para inspeccionar datos anidados.

De texto a datos: JSON.parse

El camino inverso, leer un texto JSON y reconstruir los datos, se hace con JSON.parse. En inglés, parse significa analizar: la función analiza el texto y fabrica los arrays y objetos que describe.

const guardado = '{"jugador":"Mira","nivel":3,"inventario":["espada","escudo"]}';
const datos = JSON.parse(guardado);
console.log(datos.nivel + 1);        // 4: nivel volvió a ser un número
console.log(datos.inventario[0]);    // "espada"

Adelanto: Map y Set

Además de arrays y objetos, JavaScript trae otras dos colecciones que te conviene reconocer. La Estación 19 explica cómo funcionan por dentro y cuándo elegir cada una.

Resumen

  • Un array guarda una lista ordenada: [1, 2, 3]. Los índices empiezan en 0, el último es length - 1 (o at(-1)), y un índice que no existe da undefined, no un error.
  • push/pop trabajan al final y unshift/shift, al principio; push devuelve la nueva longitud, no el array. slice copia un trozo; splice corta del original.
  • Para buscar un valor exacto: includes (sí o no) e indexOf (posición o -1). Para buscar con una condición: find y findIndex.
  • Recorre con for...of por defecto, con for clásico si necesitas el índice (condición con <, nunca <=) y con forEach en estilo de métodos. for...in no es para arrays.
  • map transforma (mismo largo), filter selecciona (igual o menos), reduce combina en un valor (escribe siempre el valor inicial). some y every responden sí o no. Ninguno modifica el original.
  • sort sin argumentos ordena como texto: para números usa (a, b) => a - b, y para palabras, localeCompare. sort modifica el original; toSorted devuelve una copia.
  • Un objeto guarda una ficha de pares clave: valor. Se lee con punto o con corchetes (obligatorios si la clave está en una variable), y se recorre con Object.keys, values y entries. En los métodos, this es el objeto antes del punto; no uses flechas para métodos.
  • Los datos reales son arrays de objetos, a menudo anidados. ?. evita el error cuando falta un dato intermedio, y ?? pone un valor por defecto.
  • ... despliega (spread) o recoge (rest). La desestructuración saca valores en variables: const [a, b] = lista, const { nombre } = ficha.
  • Arrays y objetos se manejan por referencia: asignar no copia, === compara identidad y const no congela el contenido. Spread hace copias superficiales; structuredClone, profundas. JSON.stringify convierte datos en texto y JSON.parse los reconstruye.

const cargada = JSON.parse(texto);
console.log(cargada.jugador.nombre);

Prueba a cambiar structuredClone(partida) por { ...partida }: la primera línea pasará a ser 3, porque la copia superficial comparte el inventario. En un juego real, texto se guardaría en un archivo o en localStorage, y JSON.parse se haría al volver a abrir el juego.

Proyecto: el inventario de tu juego

Casi todos los juegos de aventura tienen un inventario: una mochila con objetos que recoges, usas y guardas. Vas a programar el de un juego de rol en la consola. Es un array de objetos, y cada función del proyecto usa una herramienta distinta de esta estación. Si en vez de juegos prefieres apps, al final tienes una variante: un gestor de tareas con las mismas ideas.

  1. Lee los datos. Cada objeto del array inventario es una pila de cosas iguales: tiene nombre, tipo, cantidad, peso por unidad (en kg) y valor por unidad (en monedas). La mochila aguanta como máximo PESO_MAXIMO kilos.

  2. mostrar(inv). Imprime Inventario: y después una línea por objeto con la forma - Poción x4 (consumible), en orden alfabético. Ordena una copia con toSorted y localeCompare: mostrar no debe cambiar el orden del inventario.

  3. pesoTotal(inv). Devuelve la suma de peso × cantidad de todos los objetos, con reduce y valor inicial 0.

  4. agregar(inv, nuevo). Si ya hay un objeto con ese nombre (búscalo con find), súmale la cantidad. Si no lo hay, añádelo con push, pero guarda una copia ({ ...nuevo }) para no compartir la referencia con quien te lo pasó. En los dos casos, antes comprueba el peso: si pesoTotal(inv) + nuevo.peso * nuevo.cantidad supera el máximo, imprime No puedes cargar Yunque: pesarías 44.5 kg (máximo 15) y no añadas nada.

  5. usar(inv, nombre). Busca la posición con findIndex. Si es -1, imprime No tienes Antorcha. Si existe, resta 1 a su cantidad e imprime Usaste Poción. Quedan 4; si la cantidad llega a 0, quítalo del array con splice.

  6. nombresPorTipo(inv, tipo). Devuelve un array con los nombres de los objetos de ese tipo, con filter y map.

  7. Guarda y carga. Convierte el inventario en texto con JSON.stringify e imprime cuántos caracteres ocupa. Reconstrúyelo con JSON.parse e imprime cuántos tipos de objeto tiene la versión cargada. Así es como un juego guarda la partida.

const PESO_MAXIMO = 15;
const inventario = [
  { nombre: "Poción", tipo: "consumible", cantidad: 3, peso: 0.5, valor: 20 },
  { nombre: "Espada", tipo: "arma", cantidad: 1, peso: 4, valor: 150 },
  { nombre: "Flecha", tipo: "munición", cantidad: 20, peso: 0.1, valor: 1 },
];

function mostrar(inv) {
  console.log("Inventario:");
  const ordenado = inv.toSorted((a, b) => a.nombre.localeCompare(b.nombre, "es"));
  for (const { nombre, cantidad, tipo } of ordenado) {
    console.log(`- ${nombre} x${cantidad} (${tipo})`);
  }
}

function pesoTotal(inv) {
  return inv.reduce((suma, obj) => suma + obj.peso * obj.cantidad, 0);
}

function agregar(inv, nuevo) {
  const pesoFinal = pesoTotal(inv) + nuevo.peso * nuevo.cantidad;
  if (pesoFinal > PESO_MAXIMO) {
    console.log(`No puedes cargar ${nuevo.nombre}: pesarías ${pesoFinal} kg (máximo ${PESO_MAXIMO})`);
    return;
  }
  const existente = inv.find((obj) => obj.nombre === nuevo.nombre);
  if (existente) {
    existente.cantidad += nuevo.cantidad;
    console.log(`${existente.nombre}: ahora tienes ${existente.cantidad}`);
  } else {
    inv.push({ ...nuevo });
    console.log(`Nuevo objeto: ${nuevo.nombre}`);
  }
}

function usar(inv, nombre) {
  const indice = inv.findIndex((obj) => obj.nombre === nombre);
  if (indice === -1) {
    console.log(`No tienes ${nombre}`);
    return;
  }
  const obj = inv[indice];
  obj.cantidad--;
  console.log(`Usaste ${nombre}. Quedan ${obj.cantidad}`);
  if (obj.cantidad === 0) {
    inv.splice(indice, 1);
  }
}

function nombresPorTipo(inv, tipo) {
  return inv.filter((obj) => obj.tipo === tipo).map((obj) => obj.nombre);
}

// Pruebas (no las cambies)
agregar(inventario, { nombre: "Poción", tipo: "consumible", cantidad: 2, peso: 0.5, valor: 20 });
agregar(inventario, { nombre: "Escudo", tipo: "armadura", cantidad: 1, peso: 6, valor: 90 });
agregar(inventario, { nombre: "Yunque", tipo: "herramienta", cantidad: 1, peso: 30, valor: 5 });
usar(inventario, "Poción");
usar(inventario, "Antorcha");
mostrar(inventario);
console.log(`Peso total: ${pesoTotal(inventario)} kg`);
console.log(`Consumibles: ${nombresPorTipo(inventario, "consumible").join(", ")}`);

// Paso 7: guarda y carga
const guardado = JSON.stringify(inventario);
console.log(`Guardado: ${guardado.length} caracteres`);
const cargado = JSON.parse(guardado);
console.log(`Cargado: ${cargado.length} tipos de objeto`);

Fíjate en que estas funciones mutan el inventario que reciben (push, splice, cantidad--). Para este programa es razonable, porque el inventario es un único estado que todo el juego comparte. En la Estación 21 verás la alternativa: funciones que devuelven un inventario nuevo sin tocar el anterior.

Autoevaluación

Responde sin mirar arriba. Si fallas alguna, lee la explicación: equivocarse aquí es la forma más barata de aprender.

Con const letras = ["a", "b", "c"];, ¿qué imprime console.log(letras[letras.length]);?

  1. "c"

    El último elemento está en letras.length - 1, es decir, en la posición 2. letras[3] ya está fuera del array.

  2. undefined

    Correcto. letras.length es 3, y la posición 3 no existe porque los índices van de 0 a 2.

  3. 3

    3 es la longitud, pero aquí se usa como índice para leer un elemento, no se imprime la longitud.

  4. Un error.

    Leer un índice que no existe no da error en JavaScript: da undefined. Por eso estos fallos pasan desapercibidos.

Después de const lista = [1, 2]; const resultado = lista.push(3);, ¿qué vale resultado?

  1. [1, 2, 3]

    Ese es el nuevo contenido de lista, pero push no devuelve el array.

  2. [3]

    push no devuelve lo que añadiste.

  3. undefined

    El que siempre devuelve undefined es forEach. push devuelve algo útil.

  4. 3

    Correcto. push modifica el array y devuelve su nueva longitud.

¿Qué imprime console.log([10, 1, 5].sort());?

  1. [1, 10, 5]

    Correcto. Sin función de comparación, sort compara como texto: "1" va antes que "10", y "10" antes que "5" porque su primer carácter, "1", es menor que "5".

  2. [1, 5, 10]

    Eso es lo que obtendrías con sort((a, b) => a - b). Sin función, compara como texto.

  3. [10, 5, 1]

    Eso sería de mayor a menor, con (a, b) => b - a.

  4. [10, 1, 5], porque sort devuelve una copia sin tocar el original.

    sort sí ordena (y modifica) el array. El que devuelve una copia es toSorted.

Tienes const nums = [1, 2, 3]; y quieres un array nuevo con el cuadrado de cada número. ¿Qué método usas?

  1. forEach

    forEach recorre, pero siempre devuelve undefined: no fabrica un array.

  2. filter

    filter decide qué elementos se quedan, pero no los transforma.

  3. map

    Correcto: nums.map((n) => n * n) devuelve [1, 4, 9], un array nuevo del mismo largo.

  4. reduce

    Se podría forzar, pero reduce está pensado para combinar todo en un solo valor. Para transformar cada elemento, la herramienta clara es otra.

¿Cuál es la diferencia entre slice y splice?

  1. Ninguna: son dos nombres del mismo método.

    Se parecen en el nombre, pero hacen cosas muy distintas, y confundirlos causa errores serios.

  2. slice copia un trozo sin tocar el original; splice quita o inserta elementos en el original.

    Correcto. slice es una fotocopia; splice, cirugía sobre el array.

  3. slice modifica el original y splice hace una copia.

    Es justo al revés.

  4. slice es para textos y splice para arrays.

    Los textos tienen slice, pero los arrays también. splice solo existe en arrays, y la diferencia importante es otra.

¿Qué imprime este programa? const a = ["x"]; const b = a; b.push("y"); console.log(a);

  1. ["x"]

    Eso pasaría si b fuera una copia. Pero const b = a copia la referencia, no el array.

  2. ["y"]

    push añade, no reemplaza.

  3. Un error, porque a es const.

    const impide reasignar el nombre, no cambiar el contenido del array.

  4. ["x", "y"]

    Correcto. a y b son dos nombres para el mismo array: lo que haces a través de uno se ve a través del otro.

Con const personaje = { nivel: 5 }; y const campo = "nivel";, ¿qué expresión da 5?

  1. personaje[campo]

    Correcto. Los corchetes usan el valor de la variable campo, que es "nivel".

  2. personaje.campo

    El punto busca una propiedad llamada literalmente «campo», que no existe: da undefined.

  3. personaje["campo"]

    Con comillas, "campo" es un texto fijo, no la variable. Es lo mismo que personaje.campo.

  4. personaje.[campo]

    Mezclar punto y corchetes así es un error de sintaxis.

¿Cuánto vale [2, 3, 4].reduce((acc, n) => acc + n, 10)?

  1. 9

    Esa sería la suma sin el valor inicial. El acumulador empieza en 10.

  2. 24

    24 es el producto 2 × 3 × 4, pero la función suma.

  3. 19

    Correcto: 10 + 2 = 12, 12 + 3 = 15, 15 + 4 = 19.

  4. [12, 13, 14]

    Eso lo daría map((n) => n + 10). reduce devuelve un solo valor.

¿Qué devuelve [3, 8, 1].filter((n) => n > 5)?

  1. 8

    Eso lo devolvería find, que entrega el primer elemento suelto. filter siempre devuelve un array.

  2. [8]

    Correcto: un array con todos los que cumplen, aunque sea uno solo.

  3. true

    Eso lo devolvería some: «¿alguno es mayor que 5?».

  4. [false, true, false]

    Eso lo daría map con la misma función: transforma cada número en el resultado de la comparación.

Con const u = { nombre: "Beto" };, ¿qué da u.direccion?.ciudad?

  1. TypeError: Cannot read properties of undefined

    Ese error lo daría u.direccion.ciudad, sin el signo de interrogación.

  2. undefined

    Correcto. Como u.direccion es undefined, ?. se detiene ahí y da undefined sin error.

  3. null

    ?. siempre da undefined al detenerse, nunca null.

  4. ""

    No aparece ningún texto vacío. Si quieres un valor por defecto, combínalo con ??.

¿Cuál de estos textos es JSON válido?

  1. {nombre: "Ana"}

    En JSON las claves van siempre entre comillas dobles.

  2. {'nombre': 'Ana'}

    JSON no admite comillas simples, ni en claves ni en textos.

  3. {"nombre": "Ana",}

    La coma después del último elemento está prohibida en JSON, aunque en JavaScript sea válida.

  4. {"nombre": "Ana", "edad": 30}

    Correcto: claves y textos con comillas dobles, un número sin comillas y sin coma final.

Con const partida = { inventario: ["espada"] }; const copia = { ...partida }; copia.inventario.push("mapa");, ¿qué pasa con partida.inventario?

  1. Sigue siendo ["espada"], porque spread copia todo.

    Spread copia solo el primer nivel. El array de dentro sigue compartido.

  2. Da error, porque partida es const.

    const no impide cambiar el contenido; y además aquí se cambia un array que está dentro.

  3. También pasa a ser ["espada", "mapa"].

    Correcto. { ...partida } es una copia superficial: los dos objetos apuntan al mismo array. Para evitarlo, structuredClone(partida).

  4. Queda vacío.

    Nada lo vacía: push solo añade.

Glosario

Array (arreglo)
Valor que guarda una lista ordenada de elementos, escrita entre corchetes: [1, 2, 3].
Elemento
Cada uno de los valores guardados dentro de un array.
Índice
Número de posición de un elemento en un array. El primero es 0 y el último, length - 1.
length
Propiedad que indica cuántos elementos tiene un array (o cuántos caracteres tiene un texto).
Método
Función que pertenece a un valor y se llama con un punto: lista.push(x), texto.toUpperCase().
Mutar
Cambiar el contenido de un array u objeto que ya existe, por ejemplo con push, sort, splice o asignando una propiedad.
map
Método que crea un array nuevo, del mismo largo, con el resultado de aplicar una función a cada elemento.
filter
Método que crea un array nuevo solo con los elementos para los que una función devuelve true.
reduce
Método que combina todos los elementos de un array en un solo valor, usando un acumulador que empieza en un valor inicial.
find y findIndex
Métodos que buscan el primer elemento que cumple una condición: find devuelve el elemento (o undefined) y findIndex, su posición (o -1).
some y every
Métodos que responden true o false: si al menos un elemento cumple una condición (some) o si la cumplen todos (every).
Función de comparación
Función que se le pasa a sort para decidir el orden: recibe dos elementos y devuelve un número negativo, positivo o cero. En inglés, comparator.
Objeto
Valor que agrupa datos con nombre, escritos como pares clave: valor entre llaves.
Propiedad
Cada par clave-valor de un objeto, como nombre: "Lyra".
Clave
El nombre de una propiedad de un objeto, que sirve para leer su valor con punto o con corchetes.
this
Dentro de un método, el objeto sobre el que se llamó (el que está antes del punto).
Encadenamiento opcional
Operador ?. que lee una propiedad solo si lo de su izquierda no es null ni undefined; si lo es, da undefined sin error. En inglés, optional chaining.
Spread
Operador ... que despliega los elementos de un array o las propiedades de un objeto dentro de otro. Cuando recoge «lo que sobra» se llama rest.
Desestructuración
Sintaxis que saca valores de un array o de un objeto y los guarda en variables: const [a, b] = lista;, const { nombre } = ficha;.
Referencia
Indicación de dónde está un array u objeto en la memoria. Las variables guardan referencias, no copias, de los arrays y objetos.
Copia superficial
Copia que duplica solo el primer nivel de un array u objeto; lo que hay dentro sigue compartido. La hacen [...a], slice() y { ...o }.
Copia profunda
Copia que duplica todos los niveles, de modo que nada queda compartido. En JavaScript se hace con structuredClone.
JSON
Formato de texto para datos (JavaScript Object Notation), con claves y textos entre comillas dobles. Es el idioma común de los datos en la web.
Serializar
Convertir datos en texto para guardarlos o enviarlos, por ejemplo con JSON.stringify. Lo contrario (reconstruirlos con JSON.parse) se llama deserializar o parsear.
Map y Set
Dos colecciones de JavaScript: Set guarda valores sin repetidos y Map guarda pares clave-valor con claves de cualquier tipo.
